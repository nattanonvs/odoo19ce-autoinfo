📄 ส่วนที่ 13 · เอกสาร ความรู้ และการลงนาม

ส่วนนี้ว่าด้วยการบริหาร “เอกสาร” ขององค์กรตั้งแต่ต้นน้ำถึงปลายน้ำ — ศูนย์รวมเอกสารแนบและหมวดหมู่, การดึงรายการจากเอกสารต้นทางเข้าสู่เอกสารปลายทาง, เลขที่เอกสารแบบไทย, การส่งเอกสารให้ลงนามอิเล็กทรอนิกส์, การประกาศแจ้งพนักงาน และคลังความรู้ภายในองค์กร โดยทุกโมดูลอยู่บนข้อมูลจริงของระบบ (ไม่มีการสมมติข้อมูลนอกโค้ด)

สารบัญส่วนนี้

  1. ศูนย์เอกสาร (คลังเอกสารกลาง)
  2. ดึงรายการจากเอกสารต้นทาง (Document Pull)
  3. เลขที่เอกสารไทย (Thai Document Sequence)
  4. การลงนามเอกสารอิเล็กทรอนิกส์ (Document Signing)
  5. ประกาศองค์กร (Announcement)
  6. คลังความรู้ (Knowledge Enhanced)

od19_document_hub ศูนย์เอกสาร (คลังเอกสารกลาง)

โมดูลนี้เป็น ศูนย์กลาง metadata ของเอกสารแนบ (ir.attachment) ในระบบ — เพิ่มหมวดหมู่เอกสาร, ชั้นความเป็นส่วนตัว, ที่มา, นโยบายอายุการเก็บรักษา และจัดทำดัชนีค้นหาแบบข้อความ เพื่อให้ค้นหาและจัดระเบียบไฟล์แนบที่เกิดจากทุกโมดูลได้จากที่เดียว

เมนู

  • ศูนย์เอกสาร › คลังเอกสารกลาง — รายการเอกสารแนบทั้งหมด (ทุกผู้ใช้ที่อยู่ในกลุ่ม Document User)
  • ศูนย์เอกสาร › หมวดหมู่เอกสาร — จัดการโครงสร้างหมวด (เฉพาะผู้จัดการเอกสาร)
  • ศูนย์เอกสาร › นโยบายการเก็บรักษา — กำหนดอายุ/การจัดการเมื่อครบกำหนด (เฉพาะผู้จัดการเอกสาร)

ขั้นตอนใช้งาน — จำแนกและจัดเก็บเอกสาร

  1. เปิดคลังเอกสารกลาง เข้าแอป ศูนย์เอกสาร › คลังเอกสารกลาง จะเห็นรายการไฟล์แนบทั้งระบบ
  2. เปิดเอกสารแนบ คลิกที่รายการเพื่อเปิดฟอร์ม แล้วเลื่อนลงมาที่กลุ่ม “ศูนย์เอกสาร (OD19)”
  3. ระบุหมวดและที่มา เลือก หมวดเอกสาร และ ที่มา (รับจากภายนอก / สร้างจากระบบ / ยกมาจาก Odoo 15)
  4. ใส่ข้อมูลอ้างอิง กรอก วันที่บนเอกสาร, คู่ค้า, แผนก, ระดับความลับ และ เลขอ้างอิงต้นทาง
  5. กำหนดนโยบายอายุ (ถ้ามี) เลือก นโยบายอายุ ระบบจะคำนวณ ครบกำหนดเก็บรักษา จากวันที่บนเอกสาร + อายุของนโยบายให้อัตโนมัติ
  6. ล็อกห้ามทำลาย (ถ้าจำเป็น) เปิด ห้ามทำลาย สำหรับเอกสารที่อยู่ระหว่างข้อพิพาท/ตรวจสอบ
  7. บันทึก กดบันทึก ระบบติดป้ายสถานะการสกัดข้อความให้เอง

ฟิลด์สำคัญบนเอกสารแนบ

ฟิลด์ความหมาย
หมวดเอกสารหมวดที่ผูกกับเอกสาร (โมดูลย่อยของ od19.document.category)
ที่มารับจากภายนอก สร้างจากระบบ ยกมาจาก Odoo 15
ระดับความลับสาธารณะ / ภายใน / ความลับ / ลับมาก (ค่าเริ่มต้น = ภายใน)
นโยบายอายุ + ครบกำหนดเก็บรักษานโยบายกำหนดอายุ (เดือน) แล้วระบบคำนวณวันครบกำหนดให้ (อ่านอย่างเดียว)
ห้ามทำลายLegal hold — กันไม่ให้ทำลายเอกสารแม้ครบกำหนด
ระเบียนที่ใช้ไฟล์เดียวกันนับไฟล์แนบที่ checksum ตรงกัน (ตรวจจับเอกสารซ้ำ)
สถานะสกัดข้อความยังไม่เข้าคิว / รอสกัด / สกัดแล้ว / ล้มเหลว / ข้าม

หมวดหมู่และนโยบายการเก็บรักษา

🗂️ หมวดหมู่เอกสาร

มีชื่อ, รหัส (ห้ามซ้ำ), หมวดแม่, ชื่อเต็ม (คำนวณ), นโยบายอายุเริ่มต้น, จัดหมวดอัตโนมัติ และโมเดลที่ผูกได้

⏳ นโยบายการเก็บรักษา

กำหนดอายุ (เดือน, ต้อง > 0), การจัดการเมื่อครบกำหนด (ทบทวน / เก็บถาวร / ทำลาย) และอ้างอิงกฎหมาย

หมวดหมู่ที่ติดตั้งมาให้เริ่มต้นได้แก่ จัดซื้อ (PUR), ใบสั่งซื้อ (PUR_PO), ขาย (SAL), ใบกำกับภาษี (SAL_TAX), ทรัพยากรบุคคล (HR), ISO และ รายงานที่ระบบสร้าง (RPT)

การค้นหาและตัวกรอง

  • ตัวกรองสำเร็จรูป: รับจากภายนอก, สร้างจากระบบ, รอสกัดข้อความ
  • จัดกลุ่มได้ตาม: หมวดเอกสาร · ที่มา · แผนก
  • ค้นหาชื่อไฟล์ด้วยดัชนี trigram (ติดตั้งส่วนขยาย pg_trgm อัตโนมัติก่อนติดตั้งโมดูล)

สิทธิ์การใช้งาน

กลุ่มสิทธิ์
Document Userอ่านเอกสารแนบ, หมวดหมู่ และนโยบายได้ (อ่านเท่านั้น)
Document Managerอ่าน/เพิ่ม/แก้ไข/ลบ หมวดหมู่และนโยบายการเก็บรักษา (สืบทอดสิทธิ์ User)
Document Auditorกลุ่มสำหรับตรวจสอบ (สืบทอดสิทธิ์ User)
เคล็ดลับ: ตั้ง นโยบายอายุเริ่มต้น ที่ระดับหมวดหมู่ เพื่อให้เอกสารที่อยู่ในหมวดนั้นได้นโยบายอายุอัตโนมัติ ลดการกรอกซ้ำ
ข้อควรระวัง: ครบกำหนดเก็บรักษา เป็นค่าที่คำนวณจาก วันที่บนเอกสาร + อายุของนโยบาย ถ้าไม่กรอกวันที่บนเอกสาร ระบบจะไม่คำนวณวันครบกำหนดให้

od19_document_pull ดึงรายการจากเอกสารต้นทาง (Document Pull)

โมดูลนี้ให้ กลไกกลางสำหรับ “ดึงรายการ (lines) จากเอกสารต้นทาง” เข้าสู่เอกสารปลายทาง พร้อมบันทึกความสัมพันธ์ (lineage) และมีตัวช่วยยืนยันก่อนลบรายการที่ดึงมา ช่วยลดการคีย์ซ้ำเมื่อสร้างเอกสารที่อ้างอิงกัน

เอกสารที่รองรับ

เอกสารปลายทางเอกสารต้นทางที่ดึงได้เงื่อนไข
ใบวางบิลผู้ขาย (in_invoice)ใบสั่งซื้อคู่ค้าตรงกัน และสถานะเป็น ยืนยันแล้ว/เสร็จสิ้น
ใบวางบิลผู้ขาย (in_invoice)ใบวางบิลเดิม (ที่ลงบัญชีแล้ว)คู่ค้าเดียวกัน และลงบัญชีแล้ว
ใบวางบิลผู้ขาย (in_invoice)ใบรับของ (incoming)คู่ค้าเดียวกัน และรับของเสร็จสิ้น (done)
ใบแจ้งหนี้ขาย (out_invoice)ใบสั่งขายคู่ค้าตรงกัน และสถานะเป็น ยืนยันแล้ว/เสร็จสิ้น
ใบแจ้งหนี้ขาย (out_invoice)ใบส่งของ (outgoing)คู่ค้าเดียวกัน และส่งของเสร็จสิ้น (done)
ใบสั่งซื้อใบขอซื้อสถานะ อนุมัติแล้ว/กำลังดำเนินการ

เมนูและปุ่ม

  • บนฟอร์ม ใบวางบิล/ใบแจ้งหนี้ มีปุ่ม ดึงรายการจากเอกสารต้นทาง และ จัดการ/ลบเอกสารต้นทาง (แสดงเมื่อเอกสารยังเป็นฉบับร่าง)
  • บนฟอร์ม ใบสั่งซื้อ มีปุ่ม Pull Lines และ Manage Source (แสดงเมื่อสถานะ ร่าง/ส่งแล้ว)
  • คอลัมน์ในตารางรายการ: เอกสารต้นทาง แสดงที่มา/จำนวนบรรทัด
  • รายงาน การจัดซื้อ › รายงาน › GRNI ของรับแล้วยังไม่วางบิล — รายการที่รับของแล้วแต่ยังไม่วางบิล

ขั้นตอน — ดึงรายการจากเอกสารต้นทาง

  1. เปิดเอกสารปลายทาง สร้างหรือเปิดใบวางบิล/ใบแจ้งหนี้/ใบสั่งซื้อที่ยังเป็นฉบับร่าง
  2. กดปุ่มดึงรายการ เลือก ดึงรายการจากเอกสารต้นทาง ระบบเปิดหน้าต่างดึงรายการ
  3. เลือกเอกสารต้นทาง เลือก เอกสารต้นทาง จากรายการที่ตรงเงื่อนไข (คู่ค้า/สถานะ)
  4. เลือกรูปแบบการดึง เลือกโหมด ทั้งหมดตามลำดับเอกสาร หรือ เลือกรายบรรทัด
  5. ตรวจรายการ ในโหมดเลือกรายบรรทัด ให้ติ๊กเลือกบรรทัดที่ต้องการ (มีคอลัมน์ จำนวนคงเหลือ, ราคา/หน่วย)
  6. กดดึงรายการ กดปุ่ม ดึงรายการ รายการจะถูกสร้างเข้าเอกสารปลายทางตามลำดับ

สถานะของตัวช่วยดึง/ลบ

เลือกเอกสารต้นทาง → ยืนยันการลบ → ลบรายการเสร็จสิ้น

หน้าต่าง “จัดการ/ลบเอกสารต้นทาง” มี 2 ขั้นตอน ปุ่ม Continue, ยืนยันการลบ และ ย้อนกลับ พร้อมแสดงสรุปจำนวนบรรทัดที่จะลบและตัวอย่างรายการก่อนยืนยัน

หมายเหตุ: ระบบดึงเฉพาะบรรทัดที่ “ยังไม่ถูกดึงไปแล้ว” และมีจำนวนคงเหลือ (ยังไม่วางบิล) เพื่อกันข้อมูลซ้ำ
ข้อควรระวัง: จัดการ/ลบรายการต้นทางได้เฉพาะเมื่อเอกสารปลายทางยังเป็นฉบับร่าง (ใบสั่งซื้อใช้สถานะ ร่าง/ส่งแล้ว) หากเอกสารยืนยันแล้ว ระบบจะไม่อนุญาต

od19_document_sequence เลขที่เอกสารไทย (Thai Document Sequence)

โมดูลนี้ต่อยอดจากชุดเลขรันแบบไทยของ OCA (l10n_th_base_sequence) โดยเพิ่ม ชื่อเดือนภาษาไทย เข้าไปในตัวแปรของลำดับเลขรัน (Sequence) ทำให้สร้างรูปแบบเลขที่เอกสารไทยได้ยืดหยุ่นขึ้น (เช่น มีชื่อเดือนเต็ม/ย่อ Thai ในเลขที่เอกสาร) ควบคู่กับปีพุทธศักราชที่มีให้อยู่แล้ว

ไม่มีเมนูของตัวเอง

โมดูลนี้ไม่มีเมนูเฉพาะ — ทำงานเบื้องหลังโดยขยายความสามารถของ ir.sequence ให้กับทุกลำดับเลขในระบบ ตั้งค่าลำดับได้ที่ การตั้งค่า › เทคนิค › ลำดับเลข (Sequences)

ตัวแปรที่ใช้ได้ในรูปแบบเลขรัน

ตัวแปรความหมาย
%(month_th)sชื่อเดือนภาษาไทยแบบเต็ม (เช่น มกราคม)
%(month_th_short)sชื่อเดือนภาษาไทยแบบย่อ (เช่น ม.ค.)
%(range_month_th)s / %(range_month_th_short)sชื่อเดือนไทยสำหรับช่วงวันที่ (range)
%(current_month_th)s / %(current_month_th_short)sชื่อเดือนไทยของวันที่ปัจจุบัน
%(range_end_month_th)s / %(range_end_month_th_short)sชื่อเดือนไทยของวันสิ้นสุดช่วง (ถ้ามี)

ขั้นตอน — ตั้งเลขที่เอกสารแบบไทย

  1. เปิดลำดับเลข ไปที่ การตั้งค่า › เทคนิค › ลำดับเลข
  2. เปิดลำดับที่ต้องการ ค้นหาและเปิดรายการลำดับ (เช่น ของใบกำกับภาษี/ใบเสนอราคา)
  3. แก้ Prefix/จำนวนหลัก ปรับช่อง Prefix และ Padding ตามรูปแบบที่ต้องการ
  4. แทรกตัวแปรไทย ใส่ %(month_th)s หรือ %(month_th_short)s ในรูปแบบ (ใช้ %(year)s สำหรับปีพุทธศักราชจากชุดฐานไทย)
  5. บันทึกและทดสอบ บันทึก แล้วสร้างเอกสารใหม่เพื่อตรวจรูปแบบเลขที่ออกมา
หมายเหตุ: ตัวแปรชื่อเดือนไทยจะได้ค่าว่างถ้าเดือนอยู่นอกช่วง 1–12 (เช่น วันที่ไม่ถูกต้อง)

od19_document_sign การลงนามเอกสารอิเล็กทรอนิกส์ (Document Signing)

โมดูลนี้ให้ระบบ ส่งเอกสารให้ลงนามอิเล็กทรอนิกส์ ทั้งจากหน้าจอหลังบ้าน (Backend) และจากพอร์ทัลลูกค้า (Portal) — มีเทมเพลตการลงนามพร้อมบทบาทผู้ลงนามเรียงลำดับ, กำหนดเส้นตายการลงนาม, ลงนามหลายคนแบบรวมลายมือชื่อ, ปฏิเสธพร้อมเหตุผล และงานตั้งเวลา (Cron) หมดอายุอัตโนมัติ

เมนู

  • Signing › Documents — รายการเอกสารที่ส่งลงนาม (ผู้ใช้ทั่วไป)
  • Signing › Templates — เทมเพลตการลงนาม (ผู้จัดการเท่านั้น)

ขั้นตอน — ส่งเอกสารให้ลงนาม

  1. สร้างเทมเพลต (ครั้งแรก) ที่ Signing › Templates กำหนดชื่อ, เนื้อหาเอกสาร และบทบาทผู้ลงนาม (เรียงตามลำดับ, ระบุผู้ลงนามเริ่มต้นได้)
  2. สร้างเอกสารลงนาม ที่ Signing › Documents กดสร้าง เลือก เทมเพลต ระบบจะดึงเนื้อหาและสร้างผู้ลงนามตามบทบาทให้อัตโนมัติ
  3. ตรวจเนื้อหาและผู้ลงนาม ปรับ เนื้อหาเอกสาร, ผู้ติดต่อหลัก, อ้างอิง และ กำหนดลงนามภายใน
  4. ตรวจผู้ลงนาม ตรวจว่าผู้ลงนามทุกคนมีผู้ติดต่อและอีเมลครบถ้วน (ระบบบังคับ)
  5. ส่งให้ลงนาม กดปุ่ม Send for Signature สถานะเปลี่ยนเป็น “ส่งแล้ว” และระบบส่งอีเมลพร้อมลิงก์ให้ผู้ลงนามแต่ละคน
  6. ผู้ลงนามลงนามผ่านพอร์ทัล ผู้ลงนามเปิดลิงก์ ลงนามด้วยชุดลงนาม หรือปฏิเสธพร้อมระบุเหตุผล
  7. ปิดงาน เมื่อผู้ลงนามครบทุกคน เอกสารจะเปลี่ยนเป็น “ลงนามแล้ว” และแนบไฟล์ PDF ที่มีลายมือชื่อเข้าเธรด (Chatter)

สถานะเอกสาร

ฉบับร่าง (Draft) → ส่งแล้ว (Sent) → ลงนามแล้ว (Signed)
สถานะความหมาย
Draftฉบับร่าง ยังไม่ส่งให้ลงนาม แก้ไขเนื้อหา/ผู้ลงนามได้
Sentส่งให้ลงนามแล้ว รอผู้ลงนามดำเนินการ
Signedลงนามครบทุกคนแล้ว
Refusedมีผู้ลงนามปฏิเสธ พร้อมเหตุผล
Expiredเลยกำหนดลงนามภายใน ระบบตั้งเวลาเปลี่ยนสถานะให้อัตโนมัติ

ปุ่มสำคัญบนฟอร์มเอกสาร

ปุ่มการทำงาน
Send for Signatureส่งเอกสารให้ลงนาม (แสดงเมื่อสถานะฉบับร่าง)
Resendส่งซ้ำให้ผู้ลงนามที่ยังไม่ลงนาม (แสดงเมื่อส่งแล้ว)
Mark Expiredทำเครื่องหมายหมดอายุ (แสดงเมื่อส่งแล้ว)
Reset to Draftรีเซ็ตกลับฉบับร่าง ล้างลายมือชื่อ (แสดงเมื่อลงนาม/ปฏิเสธ/หมดอายุ)
Printพิมพ์รายงาน PDF “เอกสารลงนาม” พร้อมตารางลายมือชื่อ

ฟิลด์สำคัญ

  • เลขที่ (Number) — ออกอัตโนมัติรูปแบบ DS-ปี-เลขรัน
  • เนื้อหาเอกสาร — ดึงจากเทมเพลต แก้ไขได้
  • ผู้ลงนาม — ตารางผู้ลงนาม (บทบาท, ผู้ติดต่อ, สถานะ, วันที่ลงนาม)
  • ผู้ลงนามถัดไป — ผู้ลงนามคนถัดไปที่ยังไม่ลงนาม (ตามลำดับ)
  • ลายมือชื่อรวม — ลายมือชื่อล่าสุด + ผู้ลงนาม + เวลา (แท็บ Signature)

กลุ่มสิทธิ์
Document Signing Userสร้าง/แก้ไข/ส่งเอกสารลงนามและติดตามสถานะ; ดูเทมเพลตได้ (อ่านเท่านั้น)
Document Signing Managerจัดการเทมเพลตและเอกสารลงนามทั้งหมด (สืบทอดสิทธิ์ User)

พอร์ทัล: /my/documents (รายการ), /my/documents/<id> (รายละเอียด), /my/documents/sign/<id> (หน้าลงนาม) — ป้องกันด้วยโทเคนความปลอดภัยแยกต่อผู้ลงนาม

ข้อห้าม/ความเสี่ยง: ผู้ลงนามทุกคนต้องมี “ผู้ติดต่อ” และ “อีเมล” มิฉะนั้นระบบจะไม่ยอมให้ส่ง (ขึ้นข้อผิดพลาด) และผู้ลงนามที่ลงนามแล้วจะลงนามซ้ำไม่ได้
เคล็ดลับ: ใช้เทมเพลตกับสัญญาที่ใช้ซ้ำบ่อย (เช่น NDA) เพื่อให้ระบบสร้างผู้ลงนามตามบทบาทและลำดับให้ทันทีทุกครั้ง

od19_announcement ประกาศองค์กร (Announcement)

โมดูลนี้ใช้ ประกาศข่าวสารภายในองค์กร พร้อมเก็บ “หลักฐานการอ่าน (Read Receipts)” และส่งแจ้งเตือนได้หลายช่องทาง (ผ่านระบบแจ้งเตือนรวมขององค์กร) เหมาะกับประกาศทั่วไป ประกาศเตือน และประกาศที่บังคับให้รับทราบ

เมนู

  • Announcements › Announcements — รายการประกาศ

ขั้นตอน — สร้างและเผยแพร่ประกาศ

  1. สร้างประกาศ ที่ Announcements › Announcements กดสร้าง ใส่ หัวข้อ และ เนื้อหา
  2. เลือกประเภท เลือก ประเภท — ข้อมูล, เตือน หรือ บังคับ
  3. กำหนดกลุ่มเป้าหมาย เลือก เป้าหมาย — ทั้งบริษัท / ตามแผนก / ตามบทบาท แล้วระบุแผนกหรือบทบาทที่เกี่ยวข้อง
  4. ตั้งวันหมดอายุ (ถ้ามี) ใส่ วันหมดอายุ เพื่อให้ระบบเลิกเผยแพร่อัตโนมัติเมื่อหมดอายุ
  5. เผยแพร่ กดปุ่ม Publish หรือเปิดสวิตช์ เผยแพร่ — ประกาศประเภท “เตือน/บังคับ” จะส่งแจ้งเตือนไปยังกลุ่มเป้าหมายทันที
  6. ติดตามการอ่าน ดูได้ที่แท็บ Read Receipts ว่ามีใครอ่านแล้วบ้างและอ่านเมื่อไหร่

ฟิลด์สำคัญ

ฟิลด์ความหมาย
ประเภทข้อมูล / เตือน / บังคับ (ค่าเริ่มต้น = ข้อมูล)
เป้าหมายทั้งบริษัท / แผนก / บทบาท
วันหมดอายุวันที่ระบบจะเลิกเผยแพร่ประกาศอัตโนมัติ
เผยแพร่ + วันที่เผยแพร่สถานะและวันที่เริ่มเผยแพร่ (บันทึกอัตโนมัติ)
จำนวนผู้อ่านนับจำนวนผู้ที่กดรับทราบประกาศ

ปุ่มสำคัญ

  • Publish — เผยแพร่ประกาศ (แสดงเมื่อยังไม่เผยแพร่)
  • Unpublish — ยกเลิกการเผยแพร่ (แสดงเมื่อเผยแพร่แล้ว)
  • การ “รับทราบ” จะบันทึก Read Receipt ต่อผู้ใช้หนึ่งคนต่อหนึ่งประกาศ

สิทธิ์และขอบเขต

กลุ่มสิทธิ์
ผู้ใช้ทั่วไป (User)อ่านประกาศ (อ่านเท่านั้น) และบันทึกการรับทราบของตัวเองได้
ผู้ดูแลระบบ (System)สร้าง/แก้ไข/ลบ/เผยแพร่ประกาศได้ทั้งหมด
ขอบเขตแผนกผู้ใช้ที่มีบทบาทลึกระดับแผนกจะเห็นเฉพาะประกาศของแผนกตัวเองและประกาศที่ไม่ระบุแผนก
หมายเหตุ: งานตั้งเวลาประจำวันจะเลิกเผยแพร่ประกาศที่เลยวันหมดอายุให้อัตโนมัติ
ข้อควรระวัง: ประกาศจะส่งแจ้งเตือนอัตโนมัติเฉพาะประเภท “เตือน” และ “บังคับ” ประกาศประเภท “ข้อมูล” จะไม่ส่งแจ้งเตือน

od19_knowledge_enhanced คลังความรู้ (Knowledge Enhanced)

โมดูลนี้ยกระดับ คลังความรู้ภายในองค์กร ให้ฉลาดขึ้น โดยขยายโมเดลหน้าความรู้ (document.page) เพิ่มหมวดหมู่ความรู้, คำค้น, การค้นหาแบบข้อความเต็ม และเทมเพลตบทความ พร้อมผูกกับตั๋วบริการ (Helpdesk) เพื่อสร้างบทความจากเคสที่แก้ไขแล้ว

เมนู

  • Knowledge › Articles — บทความความรู้ (อยู่ภายในแอป Knowledge ที่มีอยู่แล้ว)

ขั้นตอน — สร้างบทความความรู้

  1. เปิดคลังความรู้ ไปที่ Knowledge › Articles
  2. สร้างบทความ กดสร้าง กำหนด ชื่อบทความ และเนื้อหา
  3. จัดหมวดความรู้ เลือก หมวดความรู้ — ขั้นตอน (Procedure), แก้ปัญหา (Troubleshooting), FAQ หรือ ทั่วไป
  4. ใส่คำค้น กรอก คำค้น (คั่นด้วยจุลภาค) เพื่อให้ค้นเจอง่ายขึ้น
  5. ตั้งค่าฉุกเฉิน (ถ้ามี) เปิด ฉุกเฉิน สำหรับบทความที่ต้องเข้าถึงด่วน
  6. ผูกกับตั๋ว (ถ้ามี) เลือก ตั๋วต้นทาง เมื่อสร้างบทความจากเคส Helpdesk
  7. บันทึก ระบบจะสร้างข้อความล้วน (Content plain) ให้อัตโนมัติเพื่อช่วยค้นหา

ฟิลด์สำคัญ

ฟิลด์ความหมาย
หมวดความรู้ขั้นตอน / แก้ปัญหา / FAQ / ทั่วไป (ค่าเริ่มต้น = ทั่วไป)
คำค้นคำสำคัญคั่นด้วยจุลภาค ช่วยการค้นหา
ฉุกเฉินทำเครื่องหมายบทความที่ต้องเข้าถึงด่วน
ตั๋วต้นทางลิงก์ไปยังตั๋ว Helpdesk ต้นทาง
เนื้อหา (ล้วน)ข้อความล้วนที่สกัดจากเนื้อหา ใช้เพิ่มประสิทธิภาพการค้นหา (คำนวณอัตโนมัติ)

การค้นหาและตัวกรอง

  • ค้นหาได้จาก ชื่อ, คำค้น, เนื้อหา (ล้วน) และหมวดความรู้
  • ตัวกรองสำเร็จรูป: ฉุกเฉิน, ขั้นตอน, แก้ปัญหา
  • จัดกลุ่มตาม หมวด หรือ ผู้เขียน (Contributor)
  • มีเทมเพลตบทความ “แก้ปัญหา” (Problem / Cause / Solution / Prevention) ให้ใช้เป็นโครงเริ่มต้น

สิทธิ์การใช้งาน

กลุ่มสิทธิ์
ผู้ใช้ทั่วไปอ่าน/เขียน/สร้างบทความความรู้ (ไม่มีสิทธิ์ลบ)
ผู้ดูแลระบบ (System)อ่าน/เขียน/สร้าง/ลบบทความได้ทั้งหมด
เคล็ดลับ: ใช้ ตั๋วต้นทาง เพื่อเชื่อมโยงบทความกับเคส Helpdesk — ช่วยให้เกิดคลังความรู้ที่โตจากงานบริการจริง
