📊 ส่วนที่ 9 · โครงการและต้นทุน

ส่วนนี้อธิบายการบริหารโครงการ (Project) ที่ผูกกับงานบริการ-บำรุงรักษา-ขายของ AutoInfo — ตั้งแต่การตั้ง “รหัสงาน” (Job Number) แบบไทย, การจัดประเภทโครงการเป็นลำดับชั้น, การผูกบัญชีวิเคราะห์ (Analytic Account) เพื่อคิดต้นทุน, รายงานกำไร-ขาดทุน (P&L) และรายงานความเสี่ยงของโครงการ, ไปจนถึงการเรียกเก็บค่าบริการจากชั่วโมงทำงาน (Timesheet → Invoice) และกติกาการออกเลขรหัสงาน/รหัสงานย่อยอัตโนมัติ

สารบัญส่วนนี้

  1. od19_project_enhanced — ประเภทโครงการ, รายงาน P&L/ความเสี่ยง, แจ้งเตือนกำหนดส่ง
  2. od19_project_analytic — รหัสงาน, แผนก, เจ้าของ/ผู้รับเหมา, บัญชีวิเคราะห์
  3. od19_project_timesheet_billing — เรียกเก็บค่าบริการจาก Timesheet
  4. od19_project_document_sequence — เลขรหัสงาน/รหัสงานย่อยตามแผนก

od19_project_enhanced โครงการอัจฉริยะ — ประเภทโครงการ, รายงาน P&L และความเสี่ยง

1) วัตถุประสงค์

เสริมโมดูลโครงการมาตรฐานให้รองรับงานจริงของ AutoInfo — เพิ่ม ประเภทธุรกิจของโครงการ (Project Category) แบบลำดับชั้น, ฟิลด์ ใบมอบหมายงาน (Job Assignment) ทั้งผู้รับผิดชอบ ผู้ประสานงาน ขอบเขตงาน และเอกสารที่ต้องส่งมอบ, รายงาน กำไร-ขาดทุนโครงการ (Project P&L), รายงาน ความเสี่ยงโครงการ (Risk Report), การ แจ้งเตือนกำหนดส่งงานทางอีเมล อัตโนมัติ และการ ห้ามย้อนขั้นตอนงาน (No Backward Stage)

2) เมนู

เมนูทั้งหมดอยู่ในแอป โครงการ (Project) ใต้เมนูหลักของผู้จัดการโครงการ

เมนูใช้ทำอะไรกลุ่มสิทธิ์
โครงการ › Project Typesกำหนดประเภท/หมวดหมู่โครงการแบบลำดับชั้น (ใช้ทั้งในโครงการและงานย่อย)ผู้ใช้โครงการ
โครงการ › P&L Reportออกรายงานกำไร-ขาดทุนของโครงการตามช่วงวันที่และบริษัทผู้ใช้โครงการ
โครงการ › Risk Reportรายงานความเสี่ยงโครงการ (ตาราง/กราฟ/ตารางสรุป)ผู้ใช้โครงการ
โครงการ › Projects without Job Numberตรวจโครงการที่ยังไม่มีรหัสงาน (คุณภาพข้อมูล)ผู้จัดการโครงการ
โครงการ › Projects without Analytic Accountตรวจโครงการที่ยังไม่ผูกบัญชีวิเคราะห์ผู้จัดการโครงการ

3) ขั้นตอนการใช้งาน

  1. กำหนดประเภทโครงการ ไปที่ โครงการ › Project Types สร้างรายการประเภท (เช่น งานติดตั้ง, งานบำรุงรักษา) เลือก Parent Type ได้ถ้าต้องการจัดเป็นลำดับชั้น แล้วติ๊ก Usable on Projects / Usable on Tasks เพื่อเปิดให้เลือกใช้
  2. ระบุประเภทให้โครงการและงานย่อย เปิดโครงการ → แท็บข้อมูลหลัก เลือก Project Category (od19_project_type_id) ส่วนงานย่อยเลือก Project Type ในฟอร์มงาน
  3. กรอกใบมอบหมายงาน ในแท็บ Job Assignment ของโครงการ ระบุ Responsible Persons, Coordinators, Scope of Work และ Document Requirements
  4. ออกรายงาน P&L ไปที่ โครงการ › P&L Report เลือกช่วงวันที่/บริษัท/โครงการ (เว้นว่าง = ทุกโครงการ) แล้วกด Generate
  5. ตรวจรายงานความเสี่ยง ไปที่ โครงการ › Risk Report ดูค่า Risk Score และ Risk Level (สีบอกระดับ) พร้อมสลับเป็นมุมมองกราฟ/ตารางสรุป
  6. ตรวจคุณภาพข้อมูล ใช้เมนู Projects without Job Number และ Projects without Analytic Account เพื่อตามหาโครงการที่ตั้งค่าไม่ครบ

4) สถานะและตัวชี้วัด

รายงานโครงการมีตัวชี้วัดเฉพาะดังนี้

ตัวชี้วัดความหมาย
Risk LevelLow ต่ำกว่า 40 · Medium 40–69 · High 70 ขึ้นไป
P&L Warningไม่ผูกบัญชีวิเคราะห์ / ยังไม่มีรายได้ที่รับรู้ / มียอดที่ยังไม่จัดหมวดหมู่ ต้องตรวจสอบ

เกณฑ์คิดคะแนนความเสี่ยง (Risk Score) รวมจาก 3 เงื่อนไข: รายได้ > 0 แต่กำไรขั้นต้นต่ำกว่า 15% (+40), มียอดลูกหนี้ค้างชำระ (+30), เลยกำหนดเสร็จของโครงการแล้ว (+30)

5) ฟิลด์/ปุ่มสำคัญ

ฟิลด์/ปุ่มอยู่ที่ความหมาย
Project Categoryฟอร์มโครงการประเภทธุรกิจของโครงการ ส่วนงานย่อยใช้ Project Type
Responsible / Coordinatorsแท็บ Job Assignmentผู้รับผิดชอบและผู้ประสานงานโครงการ (หลายคน)
Scope of Work / Document Requirementsแท็บ Job Assignmentขอบเขตงาน และเอกสารที่ต้องส่งมอบ (พิมพ์ในใบมอบหมายงาน)
Generateวิซาร์ด P&L Reportสร้างผลลัพธ์รายงาน P&L ตามช่วงวันที่/บริษัท
Job Assignment (PDF)ปุ่มพิมพ์บนโครงการพิมพ์ “ใบมอบหมายงาน” พร้อมลายเซ็น 3 ฝ่าย

6) สิทธิ์การใช้งาน

  • ผู้ใช้โครงการ (Project User): ดู/แก้ไข/สร้างประเภทโครงการ ดูรายงานความเสี่ยง (อ่านเท่านั้น) และใช้วิซาร์ด P&L ได้เต็ม
  • ผู้จัดการโครงการ (Project Manager): ลบประเภทโครงการได้ และเห็นเมนูตรวจคุณภาพข้อมูล (Projects without Job Number / Analytic Account)
เคล็ดลับ: ถ้าคะแนนความเสี่ยงเป็น 0 ทุกรายการ แต่โครงการยังไม่เสร็จ ให้ตรวจว่ารายได้ถูก รับรู้แล้ว หรือไม่ — ระบบจะไม่คิดเงื่อนไขกำไรขั้นต้นกับโครงการที่ยังไม่มีรายได้ เพื่อไม่ให้โครงการที่อยู่ระหว่างทำกลายเป็น “เสี่ยง” ทั้งหมด
ข้อควรระวัง: งานย่อยห้ามย้อนขั้นตอน (ย้ายจากขั้นที่ sequence มากไปน้อยกว่า) — ผู้ใช้ทั่วไปจะย้ายไม่ได้ ระบบจะแจ้งเตือน เฉพาะผู้ดูแลระบบ (Administrator) เท่านั้นที่ย้อนขั้นตอนได้

od19_project_analytic รหัสงาน, แผนก, เจ้าของ/ผู้รับเหมา และบัญชีวิเคราะห์

1) วัตถุประสงค์

ขยายฟอร์มโครงการให้เก็บ รหัสงาน (Job Number), แผนกเจ้าของงาน, เจ้าของโครงการ และ ผู้รับเหมา พร้อม สร้างบัญชีวิเคราะห์อัตโนมัติ ให้ทุกโครงการ เพื่อให้คิดต้นทุน/กำไรได้ทันที และกำหนด ขอบเขตข้อมูลตามแผนก (ผู้ใช้เห็นเฉพาะโครงการของแผนกตัวเอง)

2) เมนูและตำแหน่งบนหน้าจอ

  • ไม่มีเมนูใหม่ — เพิ่มฟิลด์เข้าไปใน ฟอร์มโครงการ โดยตรง
  • ป้ายชื่อเรื่อง (Title Bar) ของโครงการจะแสดง Job Number เป็นบรรทัดใหญ่ และชื่อโครงการอยู่ถัดลงมา
  • ฟิลด์บัญชีวิเคราะห์เปลี่ยนป้ายเป็น บัญชีวิเคราะห์

3) ขั้นตอนการใช้งาน

  1. สร้างโครงการใหม่ ระบบสร้าง บัญชีวิเคราะห์ ให้อัตโนมัติ (ใช้รหัสงานหรือชื่อโครงการเป็นชื่อบัญชี)
  2. กรอกรหัสงาน ที่หัวฟอร์ม รหัสงานต้อง ไม่ซ้ำ กับโครงการอื่น (ระบบตรวจทั้งตอนบันทึกและตอนสร้าง)
  3. ระบุแผนกเจ้าของงาน เลือก Department เพื่อใช้ในการออกรหัสงานและรายงานระดับแผนก
  4. ระบุเจ้าของและผู้รับเหมา เลือก Project Owner (ต้องมีบทบาท Project Owner) และ Contractors (ต้องมีบทบาท Contractor)
  5. ตรวจบัญชีวิเคราะห์ ยืนยันว่าช่อง บัญชีวิเคราะห์ มีค่า (ถ้าว่าง ให้ใช้เมนู Projects without Analytic Account ตามหา)

4) สถานะ/เงื่อนไข

โมดูลนี้ไม่มี workflow สถานะของตัวเอง แต่บังคับกติกาความถูกต้อง (constraint) ดังนี้

กรอกรหัสงาน → ตรวจไม่ซ้ำ → เลือกเจ้าของ/ผู้รับเหมา → ตรวจบทบาทผู้ติดต่อ → บันทึก + ผูกบัญชีวิเคราะห์

5) ฟิลด์/ปุ่มสำคัญ

ฟิลด์ความหมาย
Job Number (job_no)รหัสงานของโครงการ — ไม่ซ้ำ, จำเป็นที่หน้าจอ
Departmentแผนกเจ้าของงาน ใช้กำหนดรหัสงานและรายงานตามแผนก
Project Ownerเจ้าของโครงการ (ผู้ติดต่อที่มีบทบาท Project Owner)
Contractorsผู้รับเหมาโครงการ (ผู้ติดต่อที่มีบทบาท Contractor)
บัญชีวิเคราะห์ (account_id)บัญชีวิเคราะห์สำหรับคิดต้นทุน/กำไรของโครงการ

6) สิทธิ์การใช้งาน (ขอบเขตตามแผนก)

กลุ่มมองเห็นโครงการ
กลุ่มขอบเขตแผนก (group_od19_department_scope)เฉพาะโครงการของแผนกตัวเอง + โครงการที่ยังไม่ระบุแผนก (Fail-safe) · อ่าน/แก้ไข/ลบได้ แต่ สร้างไม่ได้
กลุ่มเห็นทุกแผนก (group_od19_department_all)เห็นทุกแผนก (กฎนี้ OR กับกฎแผนก จึงชนะเมื่ออยู่ทั้งสองกลุ่ม)
หมายเหตุ: เจ้าของโครงการและผู้รับเหมาเลือกได้เฉพาะผู้ติดต่อที่มีบทบาทตรงกัน (Project Owner / Contractor) — ถ้าเลือกคนที่ไม่มีบทบาท ระบบจะขึ้นข้อความ “Project owner must have the Project Owner role.” หรือ “All contractors must have the Contractor role.”
ข้อควรระวัง: รหัสงานต้องไม่ซ้ำ (unique) — เปลี่ยนรหัสงานที่ออกเลขไปแล้วควรทำเฉพาะกรณียืนยันได้ เพื่อไม่ให้ข้อมูลอ้างอิงสับสน

od19_project_timesheet_billing เรียกเก็บค่าบริการจาก Timesheet (Timesheet → Invoice)

1) วัตถุประสงค์

ช่วยติดตามและเรียกเก็บค่าบริการจาก ชั่วโมงทำงาน (Timesheet) ของงานบริการ/โครงการ — ระบุชัดว่า Timesheet ใด เรียกเก็บได้แต่ยังไม่ถูกแจ้งหนี้ และสร้างใบแจ้งหนี้ตามช่วงวันที่ได้โดยอาศัยกลไกมาตรฐานของ Odoo (sale_timesheet)

2) เมนูและปุ่ม

  • เมนู: การขาย › การออกใบแจ้งหนี้ › Invoice Timesheets (เปิดวิซาร์ดเรียกเก็บ)
  • ปุ่มบนฟอร์มโครงการ: ปุ่มสถิติ Unbilled Timesheets (แสดงเฉพาะเมื่อมีรายการ)
  • ปุ่มบนฟอร์มใบสั่งขาย: Unbilled Timesheets และ Invoice Timesheets

3) ขั้นตอนการใช้งาน

  1. ยืนยันใบสั่งขาย ต้องมีใบสั่งขายที่ยืนยันแล้ว (สถานะ “ใบสั่งขาย”) และมีรายการที่เป็นสินค้าบริการแบบ “เรียกเก็บตามเวลาที่ใช้ (Timesheet)”
  2. ลงเวลา (Timesheet) พนักงานลงชั่วโมงทำงานผูกกับโครงการ/รายการขายนั้น
  3. ตรวจ Timesheet รอเรียกเก็บ ดูปุ่ม Unbilled Timesheets บนฟอร์มโครงการหรือใบสั่งขาย เพื่อเปิดดูรายการที่ยังไม่เรียกเก็บ
  4. เปิดวิซาร์ดเรียกเก็บ บนใบสั่งขาย กด Invoice Timesheets (หรือเปิดจากเมนู) เลือก Sales Orders และช่วงวันที่ (เว้นว่าง = ทั้งหมด)
  5. สร้างใบแจ้งหนี้ กด Create Invoices ระบบจะคำนวณจำนวนที่เรียกเก็บได้ใหม่ตามช่วงวันที่แล้วสร้างใบแจ้งหนี้ พร้อมเปิดรายการใบแจ้งหนี้ให้ตรวจต่อ

4) สถานะ/เงื่อนไข

  • Timesheet ถือว่า “เรียกเก็บได้แต่ยังไม่แจ้งหนี้” เมื่อผูกกับรายการขายที่สินค้าเป็นแบบ invoice_policy = 'delivery' และ service_type = 'timesheet' และยังไม่มี timesheet_invoice_id
  • ต้องยืนยันใบสั่งขายก่อนจึงจะเรียกเก็บได้ — ถ้ายังไม่ยืนยัน ระบบแจ้ง “ต้องยืนยันใบสั่งขายก่อนจึงจะเรียกเก็บเงินได้”

5) ฟิลด์/ปุ่มสำคัญ

ฟิลด์/ปุ่มอยู่ที่ความหมาย
Unbilled Timesheets / Unbilled Hoursโครงการ และใบสั่งขายจำนวนรายการและชั่วโมงที่รอเรียกเก็บ
Invoice Timesheetsฟอร์มใบสั่งขายเปิดวิซาร์ดเรียกเก็บจาก Timesheet สำหรับใบสั่งขายนั้น
Create Invoicesวิซาร์ดสร้างใบแจ้งหนี้จาก Timesheet ที่ยังไม่เรียกเก็บ (คีย์ลัด Q)

6) สิทธิ์การใช้งาน

ผู้ใช้กลุ่ม พนักงานขาย (Salesman) ใช้วิซาร์ดเรียกเก็บจาก Timesheet ได้ (อ่าน/สร้าง/แก้ไข/ลบ)

เคล็ดลับ: กดปุ่มจำนวน Timesheet ค้างเพื่อเปิดดูได้ทุกครั้งที่ยอดค้างเปลี่ยน — ปุ่มจะแสดงเฉพาะเมื่อมีรายการค้าง จึงไม่รบกวนเมื่อไม่มีงานค้างเรียกเก็บ
ข้อควรระวัง: การเรียกเก็บจะรวมเฉพาะ Timesheet ที่สินค้าเป็นแบบ “เรียกเก็บตามเวลาที่ใช้” เท่านั้น — ถ้าไม่พบรายการที่เรียกเก็บได้ ระบบจะแจ้งให้ตรวจชนิดสินค้าของรายการขายก่อน

od19_project_document_sequence เลขรหัสงาน/รหัสงานย่อยตามแผนกและพนักงานขาย

1) วัตถุประสงค์

ออก รหัสงาน (Job Number) และ รหัสงานย่อย (Task Code) อัตโนมัติ ตามรูปแบบไทยที่กำหนด — ใช้ รหัสแผนก + อักษรย่อพนักงานขาย + ปี + เลขรัน โดยแยกชุดเลข (Sequence) ตามประเภทโครงการ: งาน (Job), บำรุงรักษาเชิงป้องกัน (PM), บริการ (Service) และงานขาย (Sales)

2) รูปแบบรหัสงาน

Job: J + แผนก + ย่อ + YY-รัน → PM: PM + แผนก + ย่อ + YY-รัน → Service: S + แผนก + ย่อ + YY-รัน → Sales: S + ย่อ + YY-รัน
ประเภทโครงการชุดเลขที่ใช้ตัวอย่างรหัสงาน
Job (งาน)Sequence ของแผนกตามประเภทงานJBNV26-0001
Preventive Maintenance (PM)Sequence ของแผนก (PM)PMBNV26-0001
Service (บริการ)Sequence ของแผนก (Service)SBNV26-0001
Sales (งานขาย)Sequence ของพนักงานขาย (ไม่ใช้เลขแผนก)SNV26-0001

รหัสงานย่อย (Task Code) ใช้รูปแบบ T + รหัสแผนก + อักษรย่อ + เลขรัน เช่น TBANV0001

3) ขั้นตอนการตั้งค่าและการใช้งาน

  1. ตั้งชุดเลขให้แผนก เปิด พนักงาน › แผนก แท็บ Project Sequences กำหนด Project Job No. Sequence / Project PM No. Sequence / Project Service No. Sequence ตามประเภทงาน
  2. ตั้งอักษรย่อพนักงานขาย เปิด ตั้งค่า › ผู้ใช้ กรอก Initials (เช่น NV) — ถ้าเว้นว่าง ระบบจะดึงอักษรตัวแรกของชื่อต้นและนามสกุลให้เอง
  3. ตั้งชุดเลขงานขาย (เฉพาะ Sales) ผู้ดูแลระบบ (base.group_erp_manager) กำหนด Sale Project Job No. Sequence ให้พนักงานขาย (ใช้เลขรันเท่านั้น ส่วนคำนำหน้าถูกกำหนดเป็น S เอง)
  4. สร้างโครงการ เลือก Project Type (Job/PM/Service/Sales) และ Salesperson — ระบบออก รหัสงาน ให้อัตโนมัติเมื่อบันทึก (ถ้ายังไม่กรอกเอง)
  5. สร้างงานย่อย เมื่อสร้างงานในโครงการ ระบบออก รหัสงานย่อย ให้เองจากรหัสแผนกและอักษรย่อของโครงการ

4) สถานะ/เงื่อนไข

  • ถ้าเลือกประเภท Sales แต่พนักงานขายยังไม่มีชุดเลขงานขาย ระบบจะ ไม่เดาให้ — จะแจ้ง “Set a Sale Project Job No. Sequence on the salesperson…”
  • ถ้ามีการเปลี่ยนแผนก/ประเภท/พนักงานขาย ภายหลัง และรหัสงานยังว่าง ระบบจะสร้างรหัสงานให้ใหม่

5) ฟิลด์/ปุ่มสำคัญ

ฟิลด์อยู่ที่ความหมาย
Project Type (od19_project_type)ฟอร์มโครงการJob / Preventive Maintenance / Service / Sales — กำหนดคำนำหน้ารหัสงาน (ค่าเริ่มต้น = Job)
Salespersonฟอร์มโครงการผู้ให้อักษรย่อในรหัสงาน และเป็นเจ้าของ Sequence สำหรับประเภท Sales
Task Code (od19_task_code)ฟอร์มงานย่อยรหัสงานย่อยที่สร้างอัตโนมัติเมื่อผูกงานกับโครงการ
Initials (od19_initials)ฟอร์มผู้ใช้อักษรย่อพนักงานขายที่ใช้ในรหัสงาน
Project … Sequenceฟอร์มแผนก / ผู้ใช้ชุดเลขโครงการตามประเภท และชุดเลขสำหรับพนักงานขาย

6) สิทธิ์การใช้งาน

  • ชุดเลขของแผนกในหน้าฟอร์มแผนก — เป็นการตั้งค่าของฝ่ายบุคคล/ผู้ดูแลระบบ
  • ช่อง Sale Project Job No. Sequence บนฟอร์มผู้ใช้วางเฉพาะกลุ่ม ผู้จัดการ ERP (base.group_erp_manager)
หมายเหตุ: คำนำหน้าใน Sequence ของแผนกจะถูกตั้งไว้แล้ว (เช่น JB%(y)s- = Job แผนก BA) — ระบบจะแทรกอักษรย่อพนักงานขายไว้ ก่อนเลขปี 2 หลัก ให้อัตโนมัติ (เช่น JB26-0001 → JBNV26-0001)
ข้อควรระวัง: รหัสงานที่ออกแล้วถือเป็นข้อมูลอ้างอิงสำคัญ — ก่อนเปลี่ยนแผนก/ประเภท/พนักงานขายของโครงการควรตรวจว่าไม่กระทบรหัสงานที่ใช้งานอยู่ และอย่าลบชุดเลข (Sequence) ของแผนกทิ้งเพราะจะทำให้ออกเลขต่อไม่ได้
