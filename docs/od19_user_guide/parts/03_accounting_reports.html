od19_etax_invoice e-Tax Invoice & e-Receipt (ใบกำกับภาษีอิเล็กทรอนิกส์)

วัตถุประสงค์

ออก ใบกำกับภาษีอิเล็กทรอนิกส์ และ ใบเสร็จรับเงินอิเล็กทรอนิกส์ ตามมาตรฐาน ETDA (ขมธอ.3-2560) พร้อมไฟล์ XML ที่ผ่านการตรวจ schema (XSD), ลายเซ็นดิจิทัลแบบ XAdES และ QR Code จากนั้นส่งเข้าระบบรับรองของสรรพากร (RD) ได้ในตัว

เมนู

การบัญชี (Accounting) › e-Tax Invoice (เฉพาะกลุ่ม group_account_invoice) ประกอบด้วยเมนูย่อย

  • e-Tax Documents — เอกสาร e-Tax ทั้งหมด (ออก/ลงนาม/พิมพ์/ส่ง RD)
  • Signing Certificates — ใบรับรองอิเล็กทรอนิกส์สำหรับลงนาม
  • Import Purchase e-Tax — นำเข้าไฟล์ e-Tax จากผู้ขายเพื่อสร้างใบวางบิล
  • RD Submissions — ประวัติการส่งข้อมูลให้สรรพากร

ขั้นตอนการออกเอกสาร

  1. สร้างเอกสาร e-Tax เลือก document_type (ค่าเริ่มต้น = ใบกำกับภาษี) และเลือกใบแจ้งหนี้ต้นทางใน move_id (รับเฉพาะใบกำกับขาย/คืน/ใบเสร็จ)
  2. สร้าง XML กดปุ่ม Generate XML (action_generate_xml) ระบบสร้างไฟล์ XML และตรวจ schema — สถานะเปลี่ยนเป็น Generated
  3. ลงนามดิจิทัล เลือกใบรับรองใน certificate_id แล้วกด Sign ระบบเซ็นด้วย XAdES และบันทึก digest/ผู้ลงนาม — สถานะเป็น Signed
  4. ออก PDF / พิมพ์ กด Generate PDF แล้ว Print เพื่อพิมพ์เอกสาร (มี QR Code)
  5. ส่งสรรพากร กด Submit to RD ระบบสร้างรายการส่งใน RD Submissions (ช่องทาง channel = mock / live)
Draft→ Generated→ Signed→ Cancelled

สถานะ & ปุ่มสำคัญ

สถานะปุ่มที่ใช้ได้หมายเหตุ

ฟิลด์สำคัญ

  • name + document_type + บริษัท ต้องไม่ซ้ำกัน (unique constraint)
  • source_document_id — แสดงเฉพาะเมื่อออกใบลดหนี้/ใบเพิ่มหนี้/ใบยกเลิก (อ้างเอกสารเดิม)
  • type_code, purpose_code, global_id — รหัสตามมาตรฐาน ETDA
  • ไฟล์ผลลัพธ์: xml_file, signed_xml_file, pdf_file, digest, signer_subject, signer_serial

การนำเข้า e-Tax ฝั่งซื้อ

  1. เปิดฟอร์มนำเข้า จากเมนู Import Purchase e-Tax
  2. Parse / ตรวจสอบ อัปโหลดไฟล์ XML แล้วกด Parse (action_parse) เพื่อตรวจความถูกต้อง
  3. สร้างใบวางบิล กด Import (action_import) ระบบสร้างใบวางบิลซื้อ in_invoice พร้อมภาษีซื้อ (input VAT)

สิทธิ์การใช้งาน

  • เมนูและเอกสาร: account.group_account_invoice
  • คีย์ส่วนตัวและ passphrase ของใบรับรอง (private_key / passphrase): เห็นเฉพาะ base.group_system (ผู้ดูแลระบบ)
ข้อควรระวัง: เอกสารที่ ลงนามแล้วห้ามแก้ไข — ต้องออกใบลดหนี้/ใบยกเลิกแทน และการนำเข้าไฟล์จากผู้ขายต้องตรวจเลขอ้างอิงให้ตรงกับเอกสารจริงก่อนบันทึกเป็นภาษีซื้อ

od19_thai_tax_reports รายงานภาษีไทย (Thai Tax Reports)

วัตถุประสงค์

พิมพ์รายงานภาษีไทยครบชุดจากข้อมูลบัญชีจริง ทั้งทะเบียนภาษีขาย/ซื้อ, หนังสือรับรองหัก ณ ที่จ่าย และแบบแสดงรายการยื่นสรรพากร พร้อมโมดูลเสริมการยื่น e-Withholding Tax, ภาษีเงินได้รอการตัดบัญชี (TAS 12) และอากรแสตมป์

เมนู

การบัญชี › รายงาน › Thai Tax Reports ประกอบด้วย

ทะเบียน & หนังสือรับรอง

ทะเบียนภาษีขาย (VAT Sales Register), ทะเบียนภาษีซื้อ (VAT Purchase Register), ทะเบียนหัก ณ ที่จ่าย (WHT Register)

แบบแสดงรายการ

ภ.พ.30, ภ.พ.36, ภ.ธ.40 (SBT), ภ.ง.ด.3, ภ.ง.ด.53, ภ.ง.ด.54, ภ.ง.ด.50, ภ.ง.ด.51

การเงิน / DBD

งบการเงินส่ง NPAE, รายการ SBC3 DBD

โมดูลเสริม

e-Withholding Tax, ภาษีเงินได้รอการตัดบัญชี (Deferred Tax), อากรแสตมป์ (Stamp Duty)

ขั้นตอนการพิมพ์รายงาน

  1. เปิดวิซาร์ด เลือกรายงานที่ต้องการ (ส่วนใหญ่เปิดหน้าต่างเลือกช่วงวันที่ของ thai.tax.report.wizard)
  2. ระบุเงื่อนไข กำหนด date_from – date_to, company_id และ report_type
  3. พิมพ์ / ส่งออก กด Print (action_print) ระบบเปิดรายงาน QWeb PDF ตามประเภทที่เลือก

ขอบเขตประเภทรายงาน (report_type)

มีทั้งหมด 14 ประเภท: vat_sales, vat_purchase, wht, pp30, pp36, pnd3, pnd53, pnd54, pnd50, pnd51, npae, sbc3, sbt_pp40, stamp_duty

e-Withholding Tax (ยื่นหัก ณ ที่จ่ายอิเล็กทรอนิกส์)

  • โมเดล od19.ewht.submission — สถานะ Draft Accepted Rejected Failed; ช่องทาง channel = mock / live
  • ปุ่ม Submit to Bank (action_submit) และ Retry (action_retry)
  • ดึงรายการหัก ณ ที่จ่ายจาก move_ids (account.withholding.move); รหัสเอกสาร EWHT/%(year)s/

ภาษีเงินได้รอการตัดบัญชี (Deferred Tax / TAS 12)

  1. สร้างใบงาน เปิด od19.deferred.tax.worksheet (สถานะ Draft)
  2. กรอกรายการ เพิ่มบรรทัด od19.deferred.tax.line โดยเลือกหมวด: สินทรัพย์ถาวร / ประมาณการ / ค่าเผื่อ / สินค้าคงเหลือ / อื่น ๆ พร้อมมูลค่าตามบัญชี, ฐานภาษี และอัตราภาษี
  3. บันทึกบัญชี กด Post (action_post_deferred_tax) ระบบคำนวณ DTA/DTL และสร้างรายการบัญชี (ดูได้ผ่าน View Journal Entry) — สถานะเป็น Posted

อากรแสตมป์ (Stamp Duty)

อัตราอากร

od19.stamp.duty.rate รองรับแบบอัตราแบบขั้นบันได (scale) และแบบคงที่ (fixed) พร้อมฐานต่อหน่วยและเพดานสูงสุด

บันทึกอากร

od19.stamp.duty สถานะ Draft → Paid (action_mark_paid / action_reset_draft) คำนวณอัตโนมัติ

สิทธิ์ & ข้อควรระวัง

สิทธิ์: ใช้สิทธิ์บัญชีมาตรฐานของ Odoo (group_account_invoice / group_account_readonly) · ตัวเลขทุกรายงานดึงจากใบกำกับที่ post แล้วเท่านั้น — ก่อนยื่นสรรพากรควรตรวจสอบว่าปิดงวดบัญชีเรียบร้อย และใช้พื้นฐานจาก l10n_th_account_tax

od19_mis_balance_sheet งบแสดงฐานะทางการเงิน (MIS Balance Sheet)

วัตถุประสงค์

ให้ งบแสดงฐานะทางการเงิน (งบดุล) รูปแบบพร้อมใช้ โดยอิงกับ MIS Builder (OCA mis_builder) มีการเปรียบเทียบหลายงวด และตรวจสอบความสมดุล (Assets = Liabilities + Equity) อัตโนมัติ

เมนู

การบัญชี › รายงาน › MIS Reports (จาก mis_builder) เลือกงบ งบแสดงฐานะทางการเงิน (Balance Sheet) หรือเรียกใช้ instance ของงบ

ขั้นตอนการใช้งาน

  1. เลือกงบ เปิดรายงาน งบแสดงฐานะทางการเงิน (Balance Sheet)
  2. กำหนดงวด ระบบมีคอลัมน์เปรียบเทียบ 3 งวด: เดือนปัจจุบัน, เดือนก่อน (หัก 1 เดือน) และ เดือนเดียวกับปีก่อน (หัก 12 เดือน)
  3. เลือกสมุด/สถานะ ค่าเริ่มต้นนับเฉพาะรายการที่ posted (target_move = posted)
  4. พิมพ์ / ส่งออก รองรับ PDF แนวนอน (landscape_pdf) และเปรียบเทียบงวด (comparison_mode)

โครงสร้างตัวชี้วัด (KPIs)

ลำดับกลุ่มตัวอย่าง KPI

od19_accounting_reporting รายงานบัญชีและการเงิน (Accounting Reporting)

วัตถุประสงค์

ศูนย์รวมรายงานบริหารด้านบัญชี ได้แก่ รายงานปิดงานบัญชีปฏิบัติการ, แดชบอร์ดควบคุมการเงิน (Finance Control Board), การตั้ง ช่วงเวลาบัญชี (Date Ranges) และการปรับชื่อ/ป้ายเมนูบัญชีให้เป็นสองภาษา (ไทย-อังกฤษ)

เมนู

  • การบัญชี › รายงาน › Accounting Operational Closure
  • การบัญชี › Finance Control Board (แดชบอร์ด)
  • เมนูหลักปรับชื่อเป็น การบัญชี (Accounting) และ รายการบัญชี (Accounting Entries)

รายงานปิดงานบัญชีปฏิบัติการ

เป็นมุมมอง SQL (อ่านอย่างเดียว) แสดงตัวชี้วัดค้างดำเนินการ:

ตัวชี้วัด (metric)ความหมาย
billable_backlogงานที่ยังไม่เปิดบิล (ค้างเปิดบิล)
open_receivableลูกหนี้ค้างชำระ
overdue_receivableลูกหนี้เกินกำหนด
open_payableเจ้าหนี้ค้างชำระ
due_payableเจ้าหนี้ครบกำหนดชำระ
cash_application_statusสถานะการนำเงินเข้า/จับคู่การชำระ
unreconciled_customer_itemsรายการลูกค้าที่ยังไม่กระทบยอด
unreconciled_vendor_itemsรายการเจ้าหนี้ที่ยังไม่กระทบยอด

แต่ละบรรทัดมีฟิลด์ metric_label, company_id, item_count (จำนวนรายการ) และ total_amount (ยอดรวม)

แดชบอร์ด Finance Control Board

แดชบอร์ดที่สร้างจาก od19.dashboard โดยดึงข้อมูลจาก account.move.line, account.cheque และ petty.cash.transaction มีวิดเจ็ตเช่น

ลูกหนี้ / เจ้าหนี้

Receivables Outstanding, Payables Outstanding, Receivables by Customer, Payables by Vendor

เช็ค

Cheques in Hand, Cheques Due (Next 7 Days), Overdue Cheques, Cheques by Status/Type

อื่น ๆ

Petty Cash Spend, Petty Cash by Type, Accounting Entries by Month

วิดเจ็ต Cheques Due (Next 7 Days) มีการแจ้งเตือนตามเงื่อนไข: แดงเมื่อยอด ≥ 500,000 และเหลืองเมื่อ ≥ 100,000

ช่วงเวลาบัญชี & อื่น ๆ

  • สร้าง date.range.type: “ปีบัญชี” และ “เดือน” พร้อมสั่งสร้างช่วงเวลาอัตโนมัติ
  • ปรับวิซาร์ด Trial Balance ให้เลือกช่วงวันที่แบบปกติ (ทดแทนการเลือก date range)

สิทธิ์

รายงานปิดงานบัญชี: account.group_account_user และ account.group_account_manager

od19_accounting_money_in_report รายงานเงินเข้า (Money In Report)

วัตถุประสงค์

วิเคราะห์ กระแสเงินเข้า ของกิจการทั้งแบบอิงใบแจ้งหนี้ (invoice-based) และอิงการรับเงินจริง (cash-based) โดยแยกตามพนักงานขาย, โครงการ, หมวดสินค้า และประเภทงาน พร้อมบันทึกผลเป็นชุดข้อมูล (Run) และส่งออก Excel

เมนู

การบัญชี › รายงาน › Money In Analysis ประกอบด้วย

  • Generate Report — เปิดวิซาร์ดสร้างรายงาน
  • Report Runs — ชุดผลลัพธ์ที่สร้างไว้
  • Analysis Lines — รายการวิเคราะห์รายบรรทัด

ขั้นตอนการสร้างรายงาน

  1. เปิดวิซาร์ด เลือก Generate Report
  2. กำหนดเงื่อนไข ระบุ date_from – date_to, company_id และ phase (เฟส 1 อิงใบแจ้งหนี้ / เฟส 2 อิงเงินสด-ใบแจ้งหนี้)
  3. กรองข้อมูล เลือกได้ทั้งพนักงานขาย, โครงการ, หมวดสินค้า และ job_type_values (งาน / PM / บริการ / ขาย / ไม่ทราบ)
  4. สร้างชุดรายงาน กด Generate (action_generate_report) ระบบสร้าง Run ใหม่พร้อมบรรทัดวิเคราะห์
  5. ดูผล / ส่งออก เปิดมุมมอง รายการ / Pivot / กราฟ หรือกด Export XLSX

สถานะของชุดรายงาน (Run)

Draft→Done
  • สถานะ Draft — แก้ไข/สร้างบรรทัดได้
  • สถานะ Done — ล็อกข้อมูลเป็น snapshot ห้ามแก้ไขและห้ามย้อนสถานะ

ปุ่ม & สิทธิ์

  • ปุ่ม Open Lines (รายการ/Pivot/กราฟ) และ Export XLSX (สร้างไฟล์ Excel ด้วย openpyxl)
  • ใช้สิทธิ์บัญชีและการขายมาตรฐาน; รองรับติดตามงานผ่านพันธมิตร (mail.thread + activity)

od19_accounting_operational_closure ปิดงานบัญชีปฏิบัติการ (Operational Closure)

วัตถุประสงค์

เพิ่มสถานะ การปิดงานเชิงปฏิบัติการ ให้เอกสารขาย–ซื้อ เพื่อให้ทีมงานเห็นภาพว่าอะไรพร้อมออกบิล รับวางบิล หรือชำระแล้ว โดยไม่ต้องดูจากบัญชีอย่างเดียว

สถานะที่เพิ่มในเอกสาร

เอกสารฟิลด์สถานะค่าที่เป็นไปได้
ใบสั่งขาย (Sale Order)od19_invoice_closure_stateรอความพร้อม → พร้อมออกบิล → ออกบิลแล้ว → ชำระบางส่วน → ชำระครบ
ใบสั่งซื้อ (Purchase Order)od19_vendor_bill_closure_stateรอผูกพัน → รอตรวจรับบริการ → พร้อมวางบิล → วางบิลแล้ว → ชำระบางส่วน → ชำระครบ
รายการบัญชี (Journal Entry)od19_operational_closure_stateฉบับร่าง → บันทึกแล้ว → ชำระบางส่วน → ชำระครบ

การใช้งาน

  1. ดูสถานะใบสั่งขาย/ซื้อ เปิดฟอร์มเอกสาร จะเห็นฟิลด์สถานะปิดงาน และ (บน SO) ตัวนับจำนวนใบกำกับ od19_customer_invoice_count
  2. จำแนกโฟลว์รายการบัญชี ฟิลด์ od19_operational_flow = ลูกค้า / ผู้ขาย / อื่น ๆ และ od19_source_document แสดงเอกสารต้นทาง
  3. ตรวจรับบริการ บนบรรทัดใบสั่งซื้อ ติ๊ก od19_service_acceptance_required แล้วกดปุ่ม Accept Service (action_od19_accept_service) — ทำได้หลังยืนยันใบสั่งซื้อ (committed) แล้ว
ฟิลด์ od19_service_accepted ใช้ยืนยันว่ารับบริการเรียบร้อย ซึ่งมีผลต่อความพร้อมของ od19_vendor_bill_closure_state (ผ่านขั้น “รอตรวจรับบริการ”) — เหมาะกับงานบริการที่ต้องตรวจรับก่อนวางบิล

od19_accounting_doubtful_debt หนี้สงสัยจะสูญ (Doubtful Debt)

วัตถุประสงค์

ตั้ง ค่าเผื่อหนี้สงสัยจะสูญ ตามช่วงอายุหนี้ (aging) และบันทึก การตัดหนี้สูญ พร้อมขั้นตอนอนุมัติ และบังคับแนบหลักฐาน

เมนู

  • การบัญชี › ลูกหนี้ › หนี้สงสัยจะสูญ (Doubtful Debt)
    • ตั้งค่าเผื่อหนี้สงสัยจะสูญ
    • ตัดหนี้สูญ
  • การบัญชี › การตั้งค่า › ช่วงอายุหนี้ (Aging Buckets) (เฉพาะผู้จัดการบัญชี)

การตั้งค่าเผื่อหนี้สงสัยจะสูญ

  1. สร้างเอกสารตั้งค่าเผื่อ กำหนดสมุดรายวัน, บัญชีค่าใช้จ่าย (expense_account_id) และบัญชีค่าเผื่อ (allowance_account_id)
  2. คำนวณ กด Compute (action_compute) ระบบสร้างบรรทัดจากลูกหนี้คงค้างตามช่วงอายุหนี้ แล้วสรุปเป็น total_balance และ total_provision_amount
  3. บันทึกบัญชี กด Post (action_post) ระบบสร้างรายการ เดบิตค่าใช้จ่าย / เครดิตค่าเผื่อ (ดูผ่าน View Move)

สถานะ: Draft → Posted → Cancelled (ย้อนกลับได้ด้วย Reset to Draft)

การตัดหนี้สูญ (Write-off)

  1. สร้างเอกสารตัดหนี้ เลือกลูกหนี้ (partner_id) และระบุ reason (เหตุผล — บังคับ)
  2. แนบหลักฐาน อัปโหลดเอกสารประกอบ (ระบบนับจำนวนใน evidence_count)
  3. อนุมัติ กด Approve (action_approve) — ต้องมีสิทธิ์ account.group_account_manager
  4. บันทึกบัญชี กด Post (action_post) — ต้อง อนุมัติแล้ว และ มีหลักฐานแนบ ระบบสร้างรายการ เดบิตหนี้สูญ / เครดิตลูกหนี้ และกระทบยอดให้

สถานะ: Draft → Approved → Posted → Cancelled

ช่วงอายุหนี้ (Aging Buckets)

  • โมเดล od19.doubtful.debt.aging.line กำหนด from_days – to_days และ provision_rate (0–100% — ตรวจสอบค่า)
  • มีวิซาร์ดตัดหนี้ช่วยสร้างเอกสารจากรายการลูกหนี้คงค้างของลูกหนี้รายนั้น (Create Write-off)
ข้อควรระวัง: การณี ตัดหนี้สูญ มีผลทางภาษี — ต้องอนุมัติโดยผู้จัดการบัญชีและมีหลักฐานครบถ้วนเสมอ เมนูหลักเห็นได้โดย account.group_account_readonly แต่การตั้งค่าช่วงอายุหนี้จำกัดที่ผู้จัดการบัญชี

od19_accounting_payment_voucher_reports ใบสำคัญจ่าย-รับเงิน (Payment Voucher & Receipt)

วัตถุประสงค์

เพิ่มขั้นตอน เตรียมจ่าย → อนุมัติ ให้รายการชำระเงิน พร้อมพิมพ์ ใบสำคัญจ่าย และ ใบสำคัญรับเงิน เป็นเอกสาร PDF ภาษาไทย และมีทะเบียนใบสำคัญให้ตรวจสอบ

เมนู

  • การบัญชี › เจ้าหนี้ › ใบสำคัญจ่าย — รออนุมัติ / Payment Vouchers
  • การบัญชี › ลูกหนี้ › ใบสำคัญรับเงิน — รออนุมัติ / Receipt Vouchers

ขั้นตอน (บนรายการชำระเงิน)

  1. เตรียมจ่าย กด เตรียมจ่าย / Prepare (action_od19_prepare) — สถานะเตรียมเปลี่ยนเป็น Prepared และบันทึกผู้เตรียม/วันที่
  2. อนุมัติ กด อนุมัติ / Approve (action_od19_approve) — บันทึกผู้อนุมัติ/วันที่
  3. ข้ามการอนุมัติ (ถ้าจำเป็น) ผู้มีสิทธิ์อนุมัติกด ข้ามการอนุมัติ / Override (action_od19_override) พร้อมระบุเหตุผล (od19_override_reason)
  4. ยืนยันชำระ กดปุ่มยืนยันของ Odoo ตามปกติ (action_post)
  5. พิมพ์เอกสาร พิมพ์ใบสำคัญจ่าย (PV) หรือใบสำคัญรับเงิน (RV) เป็น PDF

ปุ่ม & ฟิลด์สำคัญ

รายการคำอธิบาย
Prepare / Approve / Overrideปุ่มขั้นตอนเตรียม-อนุมัติ (Override จำกัดกลุ่มผู้อนุมัติ)
od19_voucher_noเลขที่ใบสำคัญ

เอกสารที่พิมพ์ได้

ใบสำคัญจ่าย (PV)

ธีมสีเขียว ใช้กับรายการจ่ายผู้ขาย — แสดงผู้รับเงิน, ใบวางบิลต้นทาง, ยอดเป็นตัวอักษร และช่องลงนาม

ใบสำคัญรับเงิน (RV)

ธีมสีส้ม ใช้กับรายการรับเงิน — โครงสร้างคล้ายกันพร้อมทะเบียนใบสำคัญ

รายการที่ยังไม่เตรียมจะไม่แสดงเลขที่ใบสำคัญ (พิมพ์เป็น “ร่าง / DRAFT”) · ใช้ฟอนต์ไทยจากโมดูล od19_thai_font_support และรหัสเอกสารจาก od19_accounting_document_sequence

od19_currency_rate_bot อัตราแลกเปลี่ยน BOT (Currency Rate Bot)

วัตถุประสงค์

ดึง อัตราแลกเปลี่ยนอ้างอิงจากธนาคารแห่งประเทศไทย (BOT) โดยอัตโนมัติ พร้อมแสดง “มินิบาร์” อัตราแลกเปลี่ยน บนเอกสารบัญชี/ขาย/ซื้อ เพื่อให้ผู้ใช้เห็นอัตราที่ใช้จริงได้ทันที

เมนู / การตั้งค่า

  • การตั้งค่า › การบัญชี › สกุลเงิน › BOT Provider — กรอก BOT Token (แสดงแบบรหัสผ่าน, เฉพาะผู้ดูแลระบบ)
  • เพิ่มบริการ Bank of Thailand (BOT) ในผู้ให้บริการอัตราแลกเปลี่ยน (res.currency.rate.provider)
  • สกุลเงิน (res.currency) เพิ่มฟิลด์ bot_currency_name และ bot_currency_rate_type

ขั้นตอนการใช้งาน

  1. ตั้งค่า Token ผู้ดูแลระบบกรอก BOT Token ที่หน้าตั้งค่า (คอลัมน์บริษัท)
  2. สร้างผู้ให้บริการ สร้าง res.currency.rate.provider เลือกบริการ = Bank of Thailand และเลือกสกุลเงินที่ต้องใช้
  3. ดึงอัตรา ระบบดึงอัตรารายวัน (DAILY_AVG_EXG_RATE) ผ่าน API ของ BOT; ปุ่มรีเฟรชอยู่บนมินิบาร์ของเอกสาร
  4. ดูมินิบาร์ เปิดเอกสาร (ใบกำกับ/ชำระเงิน/ใบสั่งขาย/ใบสั่งซื้อ) จะเห็นแถบ “1 [สกุล] = X THB” พร้อมวันที่อัตราและเวลาอัปเดตล่าสุด

มินิบาร์บนเอกสาร

ฟิลด์ที่แสดง: autoinfo_currency_bar_currency_id, autoinfo_currency_bar_rate, autoinfo_currency_bar_rate_date, autoinfo_currency_bar_last_update พร้อมปุ่ม Refresh (action_refresh_currency_rates)

สิทธิ์

  • กลุ่ม Can View Currency Rate Bar (group_currency_rate_bar_viewer) — ดูและกดรีเฟรชมินิบาร์ได้
  • bot_token เห็นเฉพาะ base.group_system
  • ตัวเลือกเปิด/ปิดมินิบาร์ผ่านพารามิเตอร์ od19_currency_rate_bot.enable_mini_bar (ค่าเริ่มต้น = True)
ข้อควรระวัง: บริการ BOT ใช้ได้เฉพาะบริษัทที่ใช้ สกุลเงินฐาน = THB เท่านั้น อัตราจะถูกอ้าง “1 หน่วยสกุลต่างประเทศ = X บาท” (โดย JPY คิดต่อ 100 หน่วย) และระบบมีกติกาพิเศษ: ถ้าเป็นวันที่ปัจจุบันและยังไม่ถึง 18:00 น. (เวลาไทย) จะใช้อัตราของวันก่อนหน้า

od19_billing_request คำขอเปิดบิลกลาง (Billing Request)

วัตถุประสงค์

รวมกระบวนการ แจ้งขอเปิดบิล (AR/AP) จากใบส่งของ (IN/OUT), ใบสั่งขาย (SO) และใบสั่งซื้อ (PO) ไว้ที่เดียว โดยมีขั้นตอน: ผู้แจ้งสร้างคำขอ → บัญชีตรวจและออกบิลเป็นเอกสารปลายทาง พร้อมกันดึงซ้ำ (1 คำขอ = 1 ต้นทาง = 1 บิล)

เมนู

Billing Requests / คำขอเปิดบิล ประกอบด้วย

  • All Requests / คำขอทั้งหมด — ดูทุกคำขอ
  • Billing Queue / คิวรอออกบิล — เฉพาะคำขอที่ส่งรอออกบิล (เฉพาะกลุ่มบัญชีผู้เปิดบิล)

ขั้นตอนการใช้งาน

  1. เปิดคำขอ สร้างคำขอใหม่ เลือก direction (AR–ลูกหนี้ / AP–เจ้าหนี้) และเลือก origin_ref (ใบส่งของ / ใบสั่งขาย / ใบสั่งซื้อ) — หรือกดปุ่ม Billing Request จากฟอร์ม SO/PO/ใบโอนก็ได้
  2. ดึงรายการ กด Pull Lines / ดึงรายการ เพื่อดึงเฉพาะบรรทัดที่ยังเปิดบิลได้ (qty_to_invoice > 0) — ระบบกันการดึงซ้ำข้ามคำขอให้
  3. แนบหลักฐาน เพิ่มหลักฐานในแท็บ Evidence (ต้องมีอย่างน้อย 1 รายการที่ยืนยันแล้วสำหรับ AR)
  4. สำหรับ AP ระบุ รับต้นฉบับจริงแล้ว (original_received) ในแท็บ AP Original
  5. ส่งให้บัญชี กด Submit / ส่งให้บัญชี (action_submit) — ระบบแจ้งเตือนทีมบัญชีอัตโนมัติ
  6. ออกบิล บัญชีกด Create Invoice/Bill / ออกบิล (action_create_invoice) ระบบสร้างใบกำกับขาย/ใบวางบิลซื้อและเชื่อมบรรทัดต้นทาง–ปลายทาง

สถานะ & ปุ่ม

Draft→ Submitted→ Invoiced ↺Rejected / Cancelled
ปุ่มเงื่อนไขผลลัพธ์
Submit / ส่งให้บัญชีต้องเป็น Draft + มีบรรทัด→ Submitted และแจ้งเตือนบัญชี
Create Invoice/Bill / ออกบิลต้องเป็น Submittedสร้างเอกสารปลายทาง → Invoiced
Reject / ตีกลับต้องเป็น Submitted→ Rejected (ระบุเหตุผลได้)
Reset to DraftRejected / Cancelled→ Draft
Cancelไม่ใช่งานที่ออกบิลแล้ว→ Cancelled

ฟิลด์สำคัญ

  • name — เลขคำขอ (AR = BRI/AR/, AP = BRI/AP/; ถ้าเปิดจากใบโอนจะสะท้อนเลขใบโอน เช่น BRI/AP/WII/00008)
  • requested_by_id, requested_employee_id, department_id — ข้อมูลผู้แจ้งและแผนก
  • partner_id, move_type (out_invoice / in_invoice), target_move_id
  • ar_billing_mode — โหมดวางบิล AR: ออกบิลเลย (direct) หรือวางบิลก่อน (two_step)
  • บรรทัด: product_id, quantity, price_unit, discount, tax_ids และตัวเลขควบคุม qty_ordered / qty_already_requested / remaining_to_bill

หลักฐาน (Evidence)

ชนิดหลักฐานที่เตรียมไว้: ใบส่งของ (delivery_note), PO ลูกค้า (customer_po), รายงานบริการ (service_report), ใบกำกับภาษีผู้ขาย (vendor_tax_invoice), ใบแจ้งหนี้ผู้ขาย (vendor_invoice) — สองชนิดหลังบังคับ รับต้นฉบับจริง

สิทธิ์

  • Billing Requester / ผู้แจ้งเปิดบิล — เห็นเฉพาะคำขอของตัวเอง
  • Billing Accounting / บัญชีผู้เปิดบิล — เห็นทุกคำขอ และเข้าถึงคิวรอออกบิล
กติกากันดึงซ้ำ/ออกบิลซ้ำ: ระบบล็อกบรรทัด (row lock) ขณะออกบิล, ตรวจว่าจำนวนที่ขอไม่เกินยอดคงเหลือ และตรวจจำนวนบรรทัดปลายทางให้ตรงกับคำขอก่อนเชื่อมความสัมพันธ์ ตั้งค่าบังคับหลักฐาน/ต้นฉบับได้ที่ระดับบริษัท (AR require evidence และ AP require original)

วัตถุประสงค์
