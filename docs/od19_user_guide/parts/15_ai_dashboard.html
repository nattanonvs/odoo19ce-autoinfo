🤖 ส่วนที่ 16 · ผู้ช่วย AI และแดชบอร์ด

ส่วนนี้รวมเครื่องมือช่วยตัดสินใจและช่วยทำงานที่อยู่ปลายทางของข้อมูลทั้งระบบ ได้แก่ ผู้ช่วย AI ที่ถามข้อมูลจริงจาก Odoo ผ่านแชท, แดชบอร์ดผู้บริหาร ที่สร้างและออกแบบเองได้ในเบราว์เซอร์, ระบบรายงาน JasperReports สำหรับพิมพ์ฟอร์มและรายงานตามแบบราชการ/องค์กร และ ทัวร์แนะนำการใช้งาน ที่พาเรียนรู้แต่ละโมดูลทีละขั้นตอน

สารบัญส่วนนี้

  1. ผู้ช่วย AI (แชทและเครื่องมืออ่านข้อมูล)
  2. แดชบอร์ดผู้บริหารและตัวสร้างแดชบอร์ด
  3. ระบบรายงาน JasperReports
  4. ทัวร์แนะนำการใช้งาน (User Guide)

⬅️ ส่วนนี้รับต่อมาจาก handoff · in

ส่วนที่ 2 · เส้นทาง G · KPI→ แดชบอร์ดผู้บริหาร→ ส่วนนี้ (ส่วนที่ 16)

รับข้อมูลจากทุกเส้นทาง A–F (ยอดขาย, กำไรโครงการ, กระแสเงินสด, สถานะงาน) มารวมเป็นแดชบอร์ด/KPI

➡️ ส่วนนี้ส่งต่อไปยัง handoff · out

od19_ai_assistant ผู้ช่วย AI (แชทและเครื่องมืออ่านข้อมูล)

โมดูล od19_ai_assistant เป็นผู้ช่วย AI แบบ ติดตั้งในองค์กรเอง (self-hosted) ทำงานกับปลายทางที่รองรับ OpenAI API (ค่าเริ่มต้นคือ Ollama ในเครื่อง, ทางเลือกคือ Groq) โดยผู้ช่วยจะ อ่านข้อมูลจริงจาก Odoo ผ่านชุด “เครื่องมือ” (Tools) แล้วตอบกลับเป็นภาษาไทย การอ่านทั้งหมดใช้สิทธิ์ของผู้ใช้ที่ถามจริง (ไม่ใช้สิทธิ์ผู้ดูแล) จึงเห็นได้เฉพาะข้อมูลที่ตัวเองมีสิทธิ์

💬 ถาม-ตอบจากข้อมูลจริง

ค้นคู่ค้า สินค้า ใบสั่งขาย/ซื้อ ใบแจ้งหนี้ รายการบัญชี ยอดคงคลัง และพนักงาน พร้อมสรุปยอดขาย/ภาษี

🔒 อ่านอย่างเดียวเป็นค่าเริ่มต้น

โหมด read_only ห้ามเขียนข้อมูลใด ๆ การสร้างเอกสารร่างเป็นโหมดเสริมที่ต้องเปิดเอง

🧾 มีบันทึกการใช้งาน

ทุกครั้งที่เรียกเครื่องมือจะถูกบันทึกพร้อมผู้ใช้ ผลลัพธ์ และเวลา (ปิดบังข้อมูลลับอัตโนมัติ)

จุดเข้าใช้งาน (เมนู)

  • ผู้ช่วย AI › แชทผู้ช่วย AI — หน้าจอแชทแบบสนทนา (ไคลเอนต์)
  • ผู้ช่วย AI › ประวัติการสนทนา — รายการบทสนทนาทั้งหมด (แบบฟอร์มและลิสต์)
  • การตั้งค่าปลายทาง AI: การตั้งค่า › ทั่วไป › ผู้ช่วย AI
  • โหมดความสามารถต่อผู้ใช้: การตั้งค่า › ผู้ใช้ › แท็บค่ากำหนดส่วนตัว › ผู้ช่วย AI

ขั้นตอนการใช้งาน

  1. เปิดแชท เข้าเมนู ผู้ช่วย AI › แชทผู้ช่วย AI
  2. เริ่มบทสนทนาใหม่ กด “สร้าง” จะได้บทสนทนาสถานะ ฉบับร่าง เจ้าของคือผู้ใช้ปัจจุบัน
  3. พิมพ์คำถาม ในช่อง คำถามถัดไป (เช่น “สรุปยอดค้างชำระของลูกค้ารายใหญ่ให้หน่อย”)
  4. กดปุ่ม “ส่ง” ระบบจะส่งคำถามพร้อมประวัติทั้งหมดไปยังปลายทาง AI
  5. อ่านคำตอบ บทสนทนาจะแสดงข้อความทีละรายการ แต่ละรายการมีป้ายบทบาท ผู้ใช้ ผู้ช่วย ระบบ เครื่องมือ
  6. ตรวจสถานะ เมื่อได้คำตอบสถานะจะเป็น สำเร็จ และบันทึก “โมเดลที่ใช้” ไว้ให้

สถานะของบทสนทนา

ผิดพลาดเชื่อมต่อปลายทาง AI ไม่ได้ — จะมีข้อความแจ้งเตือนและบันทึกข้อผิดพลาดไว้ในบทสนทนา

เครื่องมือที่ผู้ช่วยเรียกใช้ได้

ผู้ช่วยจะเลือกเรียกเครื่องมือตามคำถามเอง โดยส่งกลับเป็น JSON เพื่อขอข้อมูลก่อนตอบจริง (จำกัดไม่เกิน 5 รอบต่อคำถาม)

กลุ่มเครื่องมือ
ค้นหาเฉพาะทางsearch_partners · search_products · search_sale_orders · search_purchase_orders · search_invoices · search_journal_items · search_stock_quants · search_employees
สรุปยอดsales_summary (ยอดขายรายเดือน) · tax_summary (ภาษีซื้อ/ขาย) · overdue_receivables (ลูกหนี้ค้างชำระ)
สำรวจทั่วไปlist_models · describe_model · search_records · aggregate_records (เฉพาะโมเดลที่ผู้ใช้มีสิทธิ์อ่าน)
เมตา/ช่วยเหลือtool_help (ดูพารามิเตอร์ของเครื่องมือ)
ร่างเอกสาร (โหมดเสริม)draft_record (เสนอสร้างเอกสารร่าง ต้องยืนยันก่อนสร้างจริง)

สิทธิ์การเข้าถึง

  • ทุกเครื่องมืออ่านข้อมูลด้วย สิทธิ์ของผู้ใช้ปัจจุบัน — Model ACL และ Record Rule มีผลเหมือนหน้าจอ Odoo ปกติ
  • เครื่องมือที่โมเดลต้นทางยังไม่ติดตั้งในฐานข้อมูลจะถูกซ่อนโดยอัตโนมัติ
  • โหมดความสามารถ: read_only (ค่าเริ่มต้น) และ read_draft (เปิดสร้างร่างได้) — ตั้งได้ทั้งระดับระบบ (General Settings) และระดับผู้ใช้
  • โหมด read_draft สร้างเอกสารร่างด้วยสิทธิ์ของผู้ใช้ (ไม่ sudo) เฉพาะโมเดลในรายการที่อนุญาต และบังคับสถานะเป็น draft เสมอ
  • บันทึกการเรียกเครื่องมือ: ผู้ใช้ทั่วไปเห็นเฉพาะของตัวเอง ผู้ดูแลระบบเห็นทั้งหมด (ข้อมูลลับอย่างรหัสผ่าน/คีย์ถูกปิดบังอัตโนมัติ)

od19_dashboard แดชบอร์ดผู้บริหารและตัวสร้างแดชบอร์ด

โมดูล od19_dashboard ให้ แดชบอร์ดตามบทบาท (เจ้าของกิจการ/ผู้บริหาร/หัวหน้างานปฏิบัติการ) พร้อม ตัวออกแบบแดชบอร์ดในเบราว์เซอร์ ที่ลาก-จัดเรียง-ย่อขยายวิดเจ็ตได้เอง ข้อมูลอ่านจาก รายการต้นทางที่กำหนดไว้ล่วงหน้า (Data Source) เท่านั้น เพื่อความปลอดภัยและความสม่ำเสมอ

🎯 แดชบอร์ดตามบทบาท

มาพร้อมชุดสำเร็จรูป Owner / Management / Operational ตามโซนสรุป–เตือน–แนวโน้ม–รายละเอียด

KPI Value · Bar · Line · Pie · List (KPI มีการเทียบช่วงก่อนหน้าเป็น % ได้)

🚦 กฎสถานะ + สูตร

สี แดง/เหลือง/เขียว/เทา จากกฎที่เรียงลำดับ และสูตรคำนวณ 14 แบบ

จุดเข้าใช้งาน (เมนู)

  • แดชบอร์ด (Dashboards) › Custom Dashboards › My Dashboards — หน้าจอแดชบอร์ด/ตัวออกแบบ
  • แดชบอร์ด › Custom Dashboards › Configuration › Dashboards — จัดการแดชบอร์ดทั้งหมด (ผู้จัดการ)
  • แดชบอร์ด › Custom Dashboards › Configuration › Data Sources — จัดการรายการต้นทางข้อมูล
ตัวออกแบบถูกวางไว้ ภายในแอป “แดชบอร์ด” (Dashboards) มาตรฐาน ไม่ได้สร้างแอปใหม่ซ้ำซ้อน

ขั้นตอนการใช้งาน

  1. เตรียม Data Source เปิด Configuration › Data Sources แล้วสร้างรายการใหม่ ระบุ ชื่อ, โมเดล (เช่น sale.order) และเพิ่ม Available Fields พร้อมกำหนดชนิดเป็น measure / group by / date
  2. เปิดตัวดูแดชบอร์ด เข้า Custom Dashboards › My Dashboards
  3. เลือกแดชบอร์ดและช่วงเวลา เลือกจากแถบเครื่องมือ แล้วกด “Refresh data” เพื่อโหลดค่าใหม่
  4. สร้างแดชบอร์ดใหม่ กด “สร้าง” ตั้งชื่อ แล้วกด “Create”
  5. เข้าสู่โหมดออกแบบ สลับเป็น “Customize” แล้วเพิ่มวิดเจ็ตจาก Data Source เลือกประเภท (KPI/Bar/Line/Pie/List) และหน่วยแสดงผล
  6. จัดวางและตกแต่ง ลากเพื่อจัดลำดับ และย่อ/ขยายผ่านขนาดกริด (กว้าง 2–12 คอลัมน์, สูง 1–6 แถว)
  7. กำหนดกฎสถานะและสูตร (ถ้าต้องการ) ตั้งค่าสีเตือนและสูตรคำนวณตามหัวข้อด้านล่าง แล้วบันทึก

🔗 ผูกกับเอกสาร

ปรากฏเป็นรายการ “Print” บนฟอร์มของเอกสารที่เกี่ยวข้อง (เช่น ใบแจ้งหนี้)

✉️ ส่งอีเมลได้

หลังสร้างเสร็จสามารถกด “Send by Email” พร้อมไฟล์แนบให้ผู้รับ

จุดเข้าใช้งาน (เมนู)

  • บัญชี › การตั้งค่า › Reports › Report Templates — ทะเบียนเทมเพลต (QWeb / JasperServer)
  • บัญชี › การตั้งค่า › Reports › Report Actions — ผูกเทมเพลตกับปุ่มพิมพ์ของโมเดล
  • บัญชี › การตั้งค่า › Reports › Jasper Database Connection — การเชื่อมต่อฐานข้อมูลที่ JasperStarter ใช้
  • ตัววิซาร์ดพิมพ์จะปรากฏในเมนูพิมพ์ (Print) ของเอกสารที่ผูกไว้ เช่น “(J-Report OD15) Customer Invoice Form”

ขั้นตอนการใช้งาน

  1. ตรวจการเชื่อมต่อฐานข้อมูล ที่ Configuration › Reports › Jasper Database Connection — ค่าเริ่มต้นดึงจาก odoo.conf ปกติมีเรคคอร์ดเดียวก็เพียงพอ
  2. เปิดเอกสารและเลือกพิมพ์ บนฟอร์มเอกสาร เปิดเมนู Print แล้วเลือกฟอร์มที่ต้องการ
  3. เลือกเอกสาร ISO (ถ้ามี) เลือก “ISO Document” เพื่อนำเลขทะเบียนISO มาต่อท้ายชื่อไฟล์และพิมพ์ลงรายงาน (ไม่เลือกก็ได้)
  4. กำหนดพารามิเตอร์ เลือก ภาษา, ปีคริสตศักราช/พุทธศักราช (AD/BE) และ รูปแบบวันที่
  5. กด “Generate” ระบบจะคอมไพล์เทมเพลต (ถ้าจำเป็น) แล้วสร้างไฟล์
  6. ดาวน์โหลดผลลัพธ์ หน้าจอจะเปลี่ยนเป็นโหมดผลลัพธ์ แสดงไฟล์ PDF และ XLSX
  7. Re-Print หรือส่งอีเมล กด “Re-Print” เพื่อกลับไปแก้พารามิเตอร์ (ค่าที่กรอกคงอยู่) หรือ “Send by Email” เพื่อส่งให้ผู้รับ

สถานะของตัวช่วยพิมพ์

input (ป้อนพารามิเตอร์) → Generate → output (แสดงไฟล์)

ปุ่ม “Re-Print” จะสลับกลับไปสถานะ input โดยล้างไฟล์เก่าออก แต่คงค่าพารามิเตอร์เดิมไว้เพื่อพิมพ์ซ้ำ

สิทธิ์และความปลอดภัย

  • การเชื่อมต่อฐานข้อมูลของ JasperReports ตั้งค่าได้ที่หน้าจอ และมีแท็บ Role Creation Script ที่แสดงสคริปต์ SQL สำหรับสร้าง role แบบอ่านอย่างเดียว (รันครั้งเดียวโดยผู้ดูแล PostgreSQL)
  • ไม่มีการสร้าง role อัตโนมัติบนฐานข้อมูล — ต้องตั้งค่าอย่างชัดเจนเพื่อความปลอดภัย
  • รหัสผ่านของการเชื่อมต่อถูกเก็บแบบรหัสผ่าน และค่าเริ่มต้นอ่านจากไฟล์ตั้งค่า ไม่ฝังในโค้ด
การสร้างรายงานต้องใช้ Java / JasperStarter ที่มาพร้อมโมดูล — ระบบจะคอมไพล์ .jrxml เป็น .jasper อัตโนมัติเมื่อไฟล์เทมเพลตใหม่กว่าไฟล์ที่คอมไพล์แล้ว
ระวังการส่งพารามิเตอร์ที่ไม่ตรงกับที่เทมเพลต .jrxml ประกาศไว้ — JasperStarter อาจล้มเหลวได้ (เทมเพลตบางตัวไม่รับพารามิเตอร์บางตัว) ให้ใช้ค่าที่หน้าจอวิซาร์ดเตรียมไว้เท่านั้น
โมดูลนี้เป็น “พื้นฐาน” ของระบบรายงาน — ฟอร์มพิมพ์จำนวนมาก (ใบกำกับภาษี, วางบิล, AR/AP Aging, บัญชีแยกประเภท, งบทดลอง, งบกำไรขาดทุน, ใบสำคัญรับ/จ่าย, การ์ดทรัพย์สิน ฯลฯ) ขยายจากวิซาร์ดพิมพ์ตัวเดียวกัน จึงเรียนรู้ครั้งเดียวใช้ได้กับทุกฟอร์ม

od19_user_guide_tours ทัวร์แนะนำการใช้งาน (User Guide)

โมดูล od19_user_guide_tours ให้ ทัวร์แนะนำการใช้งานแบบอินเทอร์แอกทีฟ ที่ครอบคลุมทุกโมดูลธุรกิจของ OD19 โดยแต่ละทัวร์จะ เริ่มเองโดยอัตโนมัติเมื่อผู้ใช้เปิดแอปนั้นเป็นครั้งแรก และยังเปิดย้อนดูได้จากเมนู User Guide หรือจากลิงก์โดยตรง

เปิดแอปครั้งแรก จะเห็นทัวร์ของแอปนั้นทันที ไม่ต้องไปตามหาเอง

🗂️ รวมไว้ที่ User Guide

ศูนย์รวมทัวร์ทั้งหมดสำหรับผู้ใช้ทุกคน (ไม่ใช่แค่ผู้ดูแลระบบ)

🔁 ทบทวนได้เสมอ

ทัวร์ที่นับว่า “ดูแล้ว” เฉพาะเมื่อทำจนจบขั้นตอนสุดท้ายเท่านั้น

จุดเข้าใช้งาน (เมนู)

  • User Guide › Interactive Tours — รายการทัวร์ทั้งหมด (ผู้ใช้ภายในทุกคน)
  • การตั้งค่า › เทคนิค › Tours — จัดการทัวร์ (ผู้ดูแลระบบ)
  • ลิงก์โดยตรง: /odoo?tour=<ชื่อทัวร์>

ขั้นตอนการใช้งาน

  1. เปิดแอปที่ต้องการ เมื่อเปิดแอปครั้งแรก ทัวร์ที่ผูกกับแอปนั้นจะเริ่มขึ้นเองโดยอัตโนมัติ
  2. ทำตามขั้นตอน แต่ละขั้นมีคำอธิบายพร้อมตำแหน่งชี้ไปที่เมนู/ปุ่มที่ถูกต้อง
  3. ทำจนจบ เมื่อถึงขั้นตอนสุดท้าย ระบบจะบันทึกว่าผู้ใช้ “ดูทัวร์นี้แล้ว”
  4. เปิดทบทวนเอง (ถ้าต้องการ) เข้า User Guide › Interactive Tours เลือกทัวร์แล้วกดปุ่ม Onboarding
  5. เปิดผ่านลิงก์ ใช้ที่อยู่รูปแบบ /odoo?tour=<ชื่อทัวร์> ได้เช่นกัน

กลไกการทำงาน (แนวคิดสำคัญ)

  • ทัวร์แต่ละตัวถูกประกาศสองที่: เป็นเรคคอร์ด web_tour.tour ในฐานข้อมูล (เพื่อให้แสดงในรายการและเปิดได้) และเป็นรีจิสทรีของขั้นตอนในไฟล์ JS
  • ตั้งค่าทัวร์แนะนำเป็น custom = True เพื่อไม่ให้ปนกับคิวการแนะนำตัว (onboarding) ตามลำดับของ Odoo มาตรฐาน
  • มีบริการฝั่งหน้าเว็บ (guide tour service) คอยผูก “เมนูรากของแอป → ทัวร์” แล้วเริ่มทัวร์เมื่อเปิดแอปนั้น
  • การนับว่า “ดูแล้ว” ใช้กลไกมาตรฐานของ Odoo (consume) ซึ่งเกิดเมื่อผู้ใช้ทำถึงขั้นตอนสุดท้าย — ทัวร์ที่ทำไม่จบจะถูกเสนออีกครั้งเมื่อเปิดแอปครั้งต่อไป

สิทธิ์การเข้าถึง

  • เมนู User Guide และรายการทัวร์ เปิดให้ ผู้ใช้ภายในทุกคน
  • การจัดการ/แก้ไขทัวร์อยู่ในพื้นที่ผู้ดูแลระบบ (การตั้งค่า › เทคนิค › Tours)
  • ทัวร์จะเริ่มอัตโนมัติเฉพาะผู้ใช้ที่เปิดตัวเลือกการแนะนำ (tour) ไว้
