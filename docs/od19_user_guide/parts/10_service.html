🛠️ ส่วนที่ 10 · บริการและหลังการขาย

ส่วนนี้รวบรวมงานบริการหลังการขายทั้งวงจร — ตั้งแต่ ใบรับประกันสินค้าและ Lot/Serial, การเคลม/RMA, บัตรบริการ (บำรุงรักษาเชิงป้องกัน), สัญญาบริการเรียกเก็บรายงวด (PM/AMC), ไปจนถึง การควบคุมคุณภาพ QC ขาเข้า-ขาออก, ศูนย์ Helpdesk ทั้งฝั่งลูกค้าและภายในองค์กร, รายงาน KPI หลังการขาย และ ระบบแจ้งปัญหาภายในพร้อมการอนุมัติเป็นชั้น

สารบัญส่วนนี้

  1. od19_service_warranty — ประกันสินค้า และใบเคลม/RMA
  2. od19_service_card — บัตรบริการ/บำรุงรักษาเชิงป้องกัน และ SLA
  3. od19_service_contract — สัญญาบริการเรียกเก็บรายงวด (PM/AMC)
  4. od19_quality_control — ตรวจสอบคุณภาพขาเข้า/ขาออก และ Nonconformity
  5. od19_helpdesk_extension — Helpdesk ภายใน vs บริการลูกค้า
  6. od19_after_sales_reporting — รายงาน KPI และแดชบอร์ดหลังการขาย
  7. od19_internal_issue — แจ้งปัญหาภายใน ความเป็นส่วนตัว และการอนุมัติ

od19_service_warranty ประกันสินค้า และใบเคลม/RMA

1) วัตถุประสงค์

จัดการ ประกันสินค้า และ การเคลม บนพื้นฐานของโมดูลซ่อม (repair) โดยเพิ่มระยะเวลาประกันระดับสินค้า, สถานะประกันระดับ Lot/Serial และเอกสาร ใบเคลม/RMA (od19.warranty.claim) ที่เชื่อมกับใบสั่งซ่อม (repair order) เพื่อให้ตรวจได้ว่าอุปกรณ์ที่มาเคลมยังอยู่ในระยะประกันหรือไม่

2) เมนู

เมนู / ตำแหน่งใช้ทำอะไรกลุ่มสิทธิ์
Repair (การซ่อม) › Warranty Claimsสร้างและติดตามใบเคลม/ประกัน/RMAผู้ใช้ทั่วไป
สินค้า › แท็บ Inventory › กลุ่ม Warrantyตั้งชนิด/ระยะเวลาประกันของสินค้าผู้ใช้ทั่วไป
คลังสินค้า › Lot/Serial › กลุ่ม Warrantyตั้งวันเริ่มประกัน และดูวันหมดอายุ/สถานะประกันผู้ใช้ทั่วไป
Repair › ใบสั่งซ่อม › ฟิลด์ Warranty Claimแสดงใบเคลมต้นทางของใบสั่งซ่อมผู้ใช้ทั่วไป

3) ขั้นตอนการใช้งาน

  1. ตั้งค่าประกันของสินค้า เปิดสินค้า → แท็บ Inventory → กลุ่ม Warranty เลือก Warranty Type (none/days/months/years) และกรอก Warranty Duration (days)
  2. ตั้งวันเริ่มประกันที่ Lot/Serial (ถ้ามี) เปิด Lot/Serial → กลุ่ม Warranty กรอก Warranty Start Date ระบบจะคำนวณ Warranty End Date และ Warranty Status ให้อัตโนมัติ (ตัวคูณ: วัน = ×1, เดือน = ×30, ปี = ×365)
  3. สร้างใบเคลม ไปที่ Repair › Warranty Claims กด New ระบุลูกค้า, สินค้า, Lot/Serial, ประเภทเคลม, วันที่เคลม และรายละเอียดปัญหา
  4. ตรวจสถานะประกัน ระบบคำนวณ Under Warranty ให้เอง — ถ้าผูก Lot/Serial จะใช้สถานะของ Lot, ถ้าไม่ผูกจะคำนวณจากระยะประกันสินค้า + วันเริ่มประกัน
  5. ดำเนินการเคลม กด Confirm → Start → Done และกรอก Resolution Notes
  6. ส่งซ่อม กด Create Repair Order เพื่อสร้างใบสั่งซ่อมที่ผูกกลับมาที่ใบเคลมนี้ (สถานะจะเปลี่ยนเป็น กำลังดำเนินการ)

4) สถานะ

Draft→ Confirmed→ In Progress→ Done

นอกเส้นทางหลักมี Rejected (ไม่รับเคลม) และ Cancelled (ยกเลิก) — ใบเคลมที่ Done/Rejected จะถูกยกเลิกหรือปฏิเสธซ้ำไม่ได้

5) ฟิลด์/ปุ่มสำคัญ

ฟิลด์/ปุ่มความหมาย
Claim Typeประเภทเคลม: Warranty / RMA (คืนสินค้า) / Repair (ซ่อม)
Under Warrantyสถานะ “อยู่ในประกัน” คำนวณอัตโนมัติ ใช้ตัดสินใจคิดค่าซ่อม
Warranty Start Dateวันเริ่มประกัน (ปกติคือวันส่งมอบ) ใช้กับประกันระดับสินค้าเมื่อไม่มี Lot/Serial
Repair Orderใบสั่งซ่อมที่ผูกกับใบเคลม
Create Repair Orderสร้างใบสั่งซ่อมจากใบเคลมโดยดึงข้อมูลลูกค้า/สินค้า/ประกันมาให้

เลขที่ใบเคลมออกอัตโนมัติรูปแบบ WC/ปี/เลขรัน (5 หลัก ไม่เสนอซ้ำ)

6) สิทธิ์การใช้งาน

  • ผู้ใช้ทั่วไป (Internal User): ดู/แก้ไข/สร้างใบเคลมได้ แต่ ลบไม่ได้
  • ผู้จัดการบัญชี (Account Manager): ลบใบเคลมได้
เคล็ดลับ: ถ้าต้องการให้ระบบรู้จักวันหมดอายุประกันที่แม่นยำ ให้ตั้ง Warranty Start Date ที่ Lot/Serial เสมอ เพราะระบบจะใช้สถานะประกันของ Lot เป็นหลัก และยังตั้งวันเริ่มให้ใบเคลมอัตโนมัติเมื่อเลือก Lot
ข้อควรระวัง: ถ้าไม่ผูก Lot/Serial และไม่ได้กรอกวันเริ่มประกัน ระบบจะรายงานว่า ไม่อยู่ในประกัน ทันที — ตรวจก่อนตัดสินใจคิดค่าซ่อม

od19_service_card บัตรบริการ/บำรุงรักษาเชิงป้องกัน และ SLA

1) วัตถุประสงค์

บันทึก บัตรบริการ (od19.service.card) สำหรับติดตามงานบำรุงรักษาเชิงป้องกัน (PM) การซ่อมแก้ไข การตรวจสอบ และการติดตั้งอุปกรณ์ พร้อมคำนวณ วันนัดบริการครั้งถัดไป, ติดตาม SLA (เวลาที่ต้องทำให้เสร็จ) และบันทึก เวลาที่ใช้ทำงาน เพื่อนำไปออกบิล

2) เมนู

เมนู / ตำแหน่งใช้ทำอะไรกลุ่มสิทธิ์
คลังสินค้า › Operations › Service Cardsสร้างและติดตามบัตรบริการทั้งหมดผู้ใช้ทั่วไป
สินค้า › แท็บ Inventoryตั้งค่า Default Service Interval (days) ให้สินค้าผู้ใช้ทั่วไป

3) ขั้นตอนการใช้งาน

  1. สร้างบัตรบริการ ไปที่ คลังสินค้า › Operations › Service Cards กด New ระบุลูกค้า, สินค้า, Lot/Serial, วันที่ให้บริการ และ Service Type
  2. กำหนดรอบบริการ กรอก Service Interval (days) ระบบจะคำนวณ Next Service Date ให้ (หรือดึงค่าตั้งต้นจากสินค้าได้)
  3. กำหนด SLA และทีม กรอก SLA (hours) เลือก Service Team (แผนก) และ Technician ระบบจะคำนวณ SLA Deadline จากเวลาสร้าง + ชั่วโมง SLA
  4. บันทึกเวลาทำงาน กรอก Start Time และ End Time ระบบจะคำนวณ Duration (hours) ให้
  5. ยืนยันและปิดงาน กด Confirm → Done (ถ้าปิดแล้วจะยกเลิกหรือรีเซ็ตไม่ได้)
  6. ผูกการออกบิล เลือก Sale Order ที่จะใช้เรียกเก็บค่าบริการนี้

4) สถานะและตัวชี้วัด

Draft→ Confirmed→ Done · Cancelled → Draft
ตัวชี้วัดความหมาย
Next Service Dateวันนัดบริการครั้งถัดไป = วันให้บริการ + รอบบริการ
SLA Deadlineกำหนดเวลาที่ต้องทำให้เสร็จ = เวลาสร้าง + ชั่วโมง SLA
SLA Breachedเกิน SLA เมื่อเลยกำหนดและงานยังไม่ Done/Cancelled

5) ฟิลด์/ปุ่มสำคัญ

ฟิลด์/ปุ่มความหมาย
Service TypePreventive (บำรุงรักษา) / Corrective (ซ่อม) / Inspection (ตรวจสอบ) / Installation (ติดตั้ง) / Other
Service Teamแผนกที่รับผิดชอบงานนี้ (อ้างอิงแผนก HR)
Sale Orderใบสั่งขายสำหรับออกบิลค่าบริการ
Reset to Draftนำบัตรที่ยกเลิกกลับมาเป็นฉบับร่าง

เลขที่บัตรบริการออกอัตโนมัติรูปแบบ SC/ปี/เลขรัน (5 หลัก) · ในหน้ารายการมีตัวกรอง SLA Breached และปุ่มกลุ่มข้อมูลตามลูกค้า/สินค้า/ประเภท/สถานะ

6) สิทธิ์การใช้งาน

  • ผู้ใช้ทั่วไป (Internal User): ดู/แก้ไข/สร้างบัตรบริการได้ แต่ ลบไม่ได้
  • ผู้จัดการบัญชี (Account Manager): ลบบัตรบริการได้
เคล็ดลับ: ตรวจงานที่กำลังจะถึงกำหนดด้วยตัวกรอง SLA Breached และคอลัมน์ Next Service Date เพื่อวางแผนเข้าบริการล่วงหน้า

od19_service_contract สัญญาบริการเรียกเก็บรายงวด (PM/AMC)

1) วัตถุประสงค์

ส่วนเสริมบาง ๆ บน OCA contract เพื่อทำ สัญญาบริการ แบบเรียกเก็บรายงวด (PM/AMC) โดยเพิ่มการเชื่อมกับ บัตรบริการ (แผน PM) และ อุปกรณ์ที่รับประกัน (Lot/Serial), รองรับการ ต่ออายุสัญญา (กดเองหรืออัตโนมัติ) และ แจ้งเตือนก่อนครบกำหนด

2) เมนู

เมนู / ตำแหน่งใช้ทำอะไรกลุ่มสิทธิ์
บัญชี › ลูกค้า (Customers) › Service Contractsสร้าง/ดูสัญญาบริการรายงวด (กรองเฉพาะสัญญาที่ติ๊กเป็นสัญญาบริการ)ผู้ใช้ใบแจ้งหนี้/บัญชี
สัญญา › แท็บ Serviceตั้งค่าต่ออายุ + ผูกบัตรบริการ PM + อุปกรณ์ที่รับประกันผู้ใช้ทั่วไป

3) ขั้นตอนการใช้งาน

  1. สร้างสัญญาบริการ ไปที่ บัญชี › ลูกค้า › Service Contracts กด New (ค่าเริ่มต้นจะติ๊ก Service Contract และตั้งประเภทเป็น “ขาย” ให้แล้ว) แล้วเพิ่มคู่สัญญาและบรรทัดสัญญาที่มีวันสิ้นสุด
  2. ตั้งค่าการต่ออายุ ในแท็บ Service ตั้ง Auto Renew, Renewal Interval (Months) (ค่าเริ่มต้น 12) และ Renewal Notice (Days) (ค่าเริ่มต้น 30)
  3. ผูกอุปกรณ์และแผน PM เพิ่ม Covered Warranty Lots (อุปกรณ์ที่รับประกัน) และสร้างบัตรบริการใน Service Cards (PM) ได้จากแท็บนี้เลย
  4. เรียกเก็บเงินรายงวด ระบบ OCA จะออกใบแจ้งหนี้อัตโนมัติตามรอบ (รายเดือน/รายปี) ให้เอง
  5. ต่ออายุ กด Renew Contract เพื่อขยายวันสิ้นสุดของบรรทัดสัญญาออกไปตามจำนวนเดือนที่ตั้งไว้

4) สถานะและการแจ้งเตือน

รายการความหมาย
Expiring Soonสัญญาใกล้หมดอายุ (เหลือไม่เกินจำนวนวันที่ตั้งแจ้งเตือน)
Auto Renewเปิดไว้ = ระบบต่ออายุอัตโนมัติเมื่อครบกำหนด
Renewal Notice Sentตั้งค่าแล้วแจ้งเตือนแล้ว (กันแจ้งซ้ำ)

งานประจำวัน (cron) ชื่อ Service Contracts: Renewal & Expiry Reminder (OD19) ทำงานทุกวันเวลา 06:00 น. จะต่ออายุสัญญาที่เปิด Auto Renew และสร้าง กิจกรรม (Activity) เตือนผู้รับผิดชอบเมื่อสัญญาใกล้หมดอายุ

5) ฟิลด์/ปุ่มสำคัญ

ฟิลด์/ปุ่มความหมาย
Service Contractติ๊กเพื่อจัดการสัญญานี้เป็นสัญญาบริการรายงวด
Service Cards (stat button)จำนวนบัตรบริการ/แผน PM ภายใต้สัญญา กดเพื่อเปิดรายการ
Renew Contractขยายวันสิ้นสุดทุกบรรทัดสัญญาตามจำนวนเดือนต่ออายุ

6) สิทธิ์การใช้งาน

  • ผู้ใช้ใบแจ้งหนี้/บัญชี (Invoice/Billing): เข้าถึงเมนู Service Contracts และฟิลด์ทั้งหมด
  • ผู้ใช้ทั่วไปที่เข้าถึงสัญญาได้เห็นแท็บ Service และกดต่ออายุได้
หมายเหตุ: โมดูลนี้ใช้กลไกของ OCA contract เป็นแกน จึงต้องมี submodule third_party/oca/contract (branch 19.0) อยู่ใน addons_path — ตาราง Service Cards KPI ในส่วนรายงาน (หัวข้อถัดไป) จะสะท้อนงาน PM ที่ผูกกับสัญญาเหล่านี้ด้วย

od19_quality_control ตรวจสอบคุณภาพ (QC) ขาเข้า/ขาออก และ Nonconformity

1) วัตถุประสงค์

บันทึก การตรวจสอบคุณภาพ (od19.qc.inspection) สำหรับของขาเข้า (Incoming), ของขาออก (Outgoing) และระหว่างผลิต (In-Process) โดยผูกกับใบรับ-ส่งสินค้า (stock picking) และเมื่อตรวจไม่ผ่านสามารถ ออกใบความไม่สอดคล้อง (Nonconformity/CAPA) ตามระบบ ISO ได้ทันที

2) เมนู

เมนู / ตำแหน่งใช้ทำอะไรกลุ่มสิทธิ์
คลังสินค้า › Operations › QC Inspectionsสร้างและติดตามการตรวจสอบคุณภาพผู้ใช้ทั่วไป
คลังสินค้า › ใบรับ-ส่งสินค้า › ปุ่ม QCเปิดรายการ QC ที่ผูกกับใบรับ-ส่งนั้นผู้ใช้ทั่วไป

3) ขั้นตอนการใช้งาน

  1. สร้างใบตรวจ ไปที่ คลังสินค้า › Operations › QC Inspections กด New เลือก Inspection Type (Incoming/Outgoing/In-Process), คู่ค้า, สินค้า และผูกใบรับ-ส่ง (ถ้ามี)
  2. กรอกจำนวน ระบุ Quantity Tested และ Quantity Accepted — ระบบจะคำนวณ Quantity Rejected ให้ (จำนวนรับต้องไม่เกินจำนวนทดสอบ)
  3. (ตัวเลือก) ตรวจตามเกณฑ์ เพิ่มบรรทัด Inspection Lines ระบุ พารามิเตอร์, ค่าคาดหวัง, ค่าที่วัดได้ — ผลรายบรรทัด ผ่าน/ไม่ผ่าน คำนวณให้อัตโนมัติ (เทียบแบบไม่สนตัวพิมพ์)
  4. ตัดสินผล กด Start → Pass หรือ Fail (ระบบกันไม่ให้ปิดเป็น Pass ถ้าผลเป็น Fail)
  5. ออก Nonconformity เมื่องานไม่ผ่าน กด Create Nonconformity เพื่อสร้างใบความไม่สอดคล้องตาม ISO พร้อมดึงข้อมูลสินค้า/จำนวนมาให้

4) สถานะและตัวชี้วัด

Draft→ In Progress→ Passed / Failed

od19_internal_issue แจ้งปัญหาภายใน ความเป็นส่วนตัว และการอนุมัติ

1) วัตถุประสงค์

ต่อยอดจาก OCA helpdesk_mgmt ให้เป็นระบบ แจ้งปัญหาภายในองค์กร พร้อม การควบคุมความเป็นส่วนตัว (สาธารณะ/แผนก/ส่วนตัว), ธงเหตุฉุกเฉิน, การอนุมัติเป็นชั้น (Tier Validation) ก่อนเริ่มดำเนินการ, การแจ้งเตือนหลายช่องทาง เมื่อมอบหมาย/อัปเดต และบันทึก แนวทางแก้ไข ที่นำไปทำคลังความรู้ต่อได้

2) เมนู

ไม่มีเมนูใหม่ — ระบบต่อยอดจากหน้าตั๋ว Helpdesk เดิม โดยเพิ่มฟิลด์และแท็บ Internal ในฟอร์มตั๋ว (รวมถึงหน้าหมวดหมู่ที่มีช่องผู้รับผิดชอบ/ทีมตั้งต้น)

3) ขั้นตอนการใช้งาน

  1. ตั้งค่าความเป็นส่วนตัว สร้างตั๋ว เลือก Visibility เป็น Public (ทุกคนเห็น), Department (เฉพาะแผนกเดียวกัน — ต้องระบุแผนก), หรือ Private (เฉพาะผู้แจ้ง/ผู้รับผิดชอบ)
  2. ระบุผู้แจ้งและความเร่งด่วน ตั้ง Reported By และติ๊ก Emergency ถ้าเป็นเรื่องฉุกเฉิน
  3. ส่งตรวจสอบ กด ส่งตรวจสอบ เอกสารจะเข้าสู่กระบวนการอนุมัติ (สถานะเป็น ส่งตรวจสอบแล้ว)
  4. อนุมัติ/ปฏิเสธ ผู้อนุมัติกด ตรวจสอบผ่าน (เมื่อครบทุกชั้นจะเปลี่ยนเป็น ตรวจสอบผ่าน) หรือ ปฏิเสธ (กลับเป็นฉบับร่าง)
  5. ดำเนินการและปิด เมื่อตรวจสอบผ่านแล้วกด เริ่มดำเนินการ → กรอก Resolution → เสร็จสิ้น

4) สถานะ/การอนุมัติ

ร่าง→ ส่งตรวจสอบแล้ว→ ตรวจสอบผ่าน→ กำลังดำเนินการ→ เสร็จสิ้น
ชั้นการอนุมัติเงื่อนไขผู้อนุมัติ
Urgent (เหตุฉุกเฉิน)ติ๊ก Emergencyกลุ่มผู้ดูแลระบบ (ปรับได้)
Standard (เรื่องทั่วไป)ไม่ใช่เหตุฉุกเฉินอย่างน้อย 1 ชั้น

ระบบกันการเปลี่ยนสถานะ “ร่าง → ตรวจสอบผ่าน” ตรง ๆ หากรอบการอนุมัติยังไม่ผ่าน

6) สิทธิ์การใช้งาน

  • ผู้ใช้ทั่วไป: เห็นตั๋วแบบ Public ทั้งหมด, แบบ Department เฉพาะแผนกของตัวเอง, และแบบ Private เฉพาะที่ตัวเองเป็นผู้แจ้งหรือผู้รับผิดชอบ
  • ขอบเขตตามแผนก (Department Scope): ผู้ใช้บางบทบาทเห็นเฉพาะตั๋วของแผนกตัวเองและตั๋วที่ยังไม่ระบุแผนก (กันข้อมูลหลุดแบบ fail-safe)
  • บทบาทระดับบริหาร/บัญชี/คลัง: เห็นได้ทุกแผนก
เคล็ดลับ: กรอก Resolution ทุกครั้งที่ปิดงาน — ข้อความนี้ใช้เป็นต้นทางของบทความในคลังความรู้ และช่วยให้ปัญหาซ้ำแก้ได้เร็วขึ้น
ข้อควรระวัง: การเลือก Department โดยไม่ระบุแผนก อาจทำให้ผู้แจ้งเห็นข้อมูลผิดขอบเขต — ระบบจึงบังคับให้ระบุ Department เมื่อเลือกโหมดนี้
