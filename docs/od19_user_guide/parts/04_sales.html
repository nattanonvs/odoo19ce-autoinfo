🛒 ส่วนที่ 4 · การขายและลูกค้า

อธิบายกระบวนการขายครบวงจรของ AutoInfo — ใบเสนอราคา (Quotation), ใบสั่งขาย (Sales Order), การควบคุมความเสี่ยงลูกค้าและวงเงินเชื่อ, สัญญาการขายและงวดวางบิล, หลักฐานประกอบการวางบิล, เงินประกันผลงาน (Retention), เงื่อนไขการขาย, รายงาน และแบบพิมพ์ทั้งแบบ QWeb และ Jasper โดยอ้างอิงจากโมดูล od19_sale* · od19_sales_* ที่ติดตั้งในระบบจริง

สารบัญส่วนนี้

  1. การควบคุมความเสี่ยงลูกค้าและวงเงินเชื่อ (Credit Gate)
  2. หลักฐานประกอบการวางบิล (Billing Evidence)
  3. ตราประทับ CONFIRMED บนใบเสนอราคา
  4. แกนสัญญาการขาย (Sales Contract)
  5. ยอดเงินสองสกุลในรายการขาย
  6. สะพานงานขาย OCA และการอนุมัติตามวงเงิน
  7. บริบทโครงการและกำไรงานขาย
  8. รายงานยอดขายตามโครงการและลูกค้าประจำ
  9. เงินประกันผลงาน (Retention)
  10. แบบพิมพ์ Jasper งานบริการ
  11. ใบสั่งขาย QWeb (รูปแบบดั้งเดิม / ปรับปรุง)
  12. เทมเพลตเงื่อนไขการขาย (Sale Terms)
  13. วิซาร์ดเปลี่ยนวันส่งและข้อมูลเงินมัดจำ
  14. แบบพิมพ์ Jasper งานขาย
  15. เลขที่ใบเสนอราคาตามแผนก และการแก้ไข (Revision)

od19_sales_customer_risk_gate การควบคุมความเสี่ยงลูกค้าและวงเงินเชื่อ (Credit Gate)

โมดูลนี้ทำหน้าที่เป็น ด่านป้องกันความเสี่ยง ของฝ่ายขาย — บล็อกไม่ให้ “ยืนยัน” ใบสั่งขาย (และใบสั่งซื้อ) ที่ผูกกับคู่ค้าที่ติด บัญชีดำ (Blacklist) และบังคับให้ลูกค้าที่จะซื้อแบบเครดิต ต้องผ่านการอนุมัติวงเงินจากฝ่ายบัญชี (Credit Reviewer) พร้อมตรวจสอบยอดค้างชำระ (Aging) เพื่อกัก (Hold) ลูกค้าที่ค้างชำระเกินเกณฑ์ที่บริษัทกำหนด

เมนูที่เกี่ยวข้อง

  • การขาย › Reporting › Credit Gate › Blocked Documents — รายการเอกสารที่ถูกด่านบล็อก
  • การขาย › Reporting › Credit Gate › Credit Pending — ลูกค้าที่รออนุมัติวงเงินเชื่อ
  • ฟอร์มคู่ค้า (Contacts) แท็บ Credit & Risk — กลุ่ม Credit / Aging Hold / Blacklist
  • ฟอร์มใบสั่งขาย กลุ่ม Credit & Risk Gate และแถบเตือนสีแดงเมื่อถูกบล็อก
  • การตั้งค่า › บริษัท — เปิดใช้ Aging Hold และกำหนดเกณฑ์วัน/ยอดค้างชำระ

ขั้นตอนขอและอนุมัติวงเงินเชื่อ

  1. เปิดฟอร์มลูกค้า แท็บ Credit & Risk — ตรวจสถานะคำขอและวงเงินปัจจุบันก่อนเริ่ม
  2. กดปุ่ม “Request Credit” — คำขอเข้าสู่สถานะ Pending และบันทึกผู้ขอ/วันที่ขอ
  3. Credit Reviewer พิจารณา — กด “Approve Credit” (กำหนดวงเงิน วันหมดอายุ) หรือ “Reject Credit”
  4. ระบบคำนวณวงเงินที่เหลือและ Aging อัตโนมัติ — กด “Re-check Aging” หรือให้ Cron รายวันอัปเดตให้

สถานะและตัวตรวจของด่าน

คำขอวงเงิน: Not Requested → Pending → Approved / Rejected

ด่านจะถูกตรวจที่ 3 จุด คือ ตอน สร้างใบเสนอราคา, ตอน แก้ไข และตอน ยืนยันใบสั่งขาย (Order Confirm) หากไม่ผ่าน ระบบจะขึ้น แถบเตือนสีแดงเหนือฟอร์ม พร้อมเหตุผลที่ถูกบล็อก

สิทธิ์

  • Credit Reviewer — กลุ่ม group_od19_credit_reviewer อนุมัติวงเงิน, ตั้ง/ปลดบัญชีดำ, แก้ฟิลด์ที่ถูกป้องกัน (Protected Fields)
  • ผู้ใช้ทั่วไป — ขอวงเงินเชื่อและใช้ปุ่ม Re-check Aging (คู่กับ Partner Manager) ได้
  • ฟิลด์ด้านเครดิต/บัญชีดำจะแก้ไขได้เฉพาะ Credit Reviewer เท่านั้น
ด่านบล็อกทั้งงานขายและงานซื้อ: ฝั่ง ลูกค้า ตรวจทั้งบัญชีดำ + วงเงินเชื่อ + Aging Hold แต่ฝั่ง ผู้ขาย (Purchase) ตรวจเฉพาะบัญชีดำ — ใบสั่งซื้อที่คู่ค้าติดแบล็กลิสต์จะยืนยันไม่ได้
ใช้ตัวกรอง Blacklisted ในหน้ารายการคู่ค้า และตัวกรอง Credit sale ในใบสั่งขาย เพื่อค้นหาเฉพาะเอกสารที่เกี่ยวข้องกับความเสี่ยงได้เร็วขึ้น

od19_sales_billing_evidence หลักฐานประกอบการวางบิล (Billing Evidence)

โมดูลนี้บังคับให้มี หลักฐานประกอบการวางบิล (เช่น ใบส่งของ, ใบตรวจรับ, เอกสารยืนยันการให้บริการ) ก่อนที่ใบสั่งขายจะ ออกใบแจ้งหนี้ได้ โดยระบบคำนวณ “ความพร้อมในการวางบิล” (Billing Readiness) ให้เห็นบนใบสั่งขาย และบล็อกการออกใบแจ้งหนี้หากยังไม่พร้อม

จุดเข้าถึง

  • ฟอร์มใบสั่งขาย — ฟิลด์ Billing Readiness State แสดงต่อจากสัญญาการขาย
  • ทะเบียนหลักฐาน Billing Evidence — เก็บรายการหลักฐานและไฟล์แนบต่อใบสั่งขาย
  • ทะเบียน Evidence Type — ตั้งชนิดหลักฐาน (delivery / service / other) และตัวบังคับ

ขั้นตอนการวางบิลที่มีหลักฐานครบ

  1. สร้างรายการหลักฐานบนใบสั่งขาย — เลือกชนิดหลักฐาน (Evidence Type) และแนบไฟล์
  2. ติ๊ก “Verified” — ระบบบังคับว่าต้อง มีไฟล์แนบก่อนจึงจะยืนยันหลักฐานได้
  3. ระบบปรับสถานะความพร้อม — เมื่อหลักฐานที่จำเป็นครบ สถานะเปลี่ยนเป็น Ready
  4. ออกใบแจ้งหนี้ — ทำได้เฉพาะเมื่อสถานะพร้อมเป็น Ready หรือ Billed แล้วเท่านั้น

สถานะความพร้อมในการวางบิล

Draft (ร่าง) → Waiting (ขาดหลักฐาน) → Ready (พร้อมวางบิล) → Billed (วางบิลแล้ว)

ฟิลด์ / ฟิลด์บังคับ

ฟิลด์ความหมาย
Billing Readiness Stateความพร้อมในการวางบิล (Draft / Waiting / Ready / Billed) — คำนวณอัตโนมัติ
Evidence Typeชนิดหลักฐาน พร้อมตัวชี้วัด Trigger Kind (Delivery / Service / Other)
Required for Billingระบุว่าหลักฐานชนิดนี้ “บังคับ” สำหรับการวางบิลหรือไม่

สิทธิ์

  • ผู้ใช้ฝ่ายขายทั่วไปสร้าง/แก้ไขหลักฐานของใบสั่งขายได้
  • การยืนยันหลักฐานต้องมีไฟล์แนบจริง มิฉะนั้นระบบจะไม่ยอมให้บันทึก
ออกใบแจ้งหนี้ไม่ได้ถ้าหลักฐานไม่ครบ: หากสถานะความพร้อมไม่ใช่ Ready หรือ Billed ปุ่ม/กระบวนการออกใบแจ้งหนี้จะถูกบล็อก เพื่อป้องกันการวางบิลก่อนส่งมอบหรือก่อนมีการยืนยันการบริการ

od19_sales_confirm_stamp ตราประทับ CONFIRMED บนใบเสนอราคา

โมดูลนี้เพิ่ม ตราประทับ CONFIRMED สีแดง บนเอกสารใบเสนอราคา/ใบสั่งขายที่พิมพ์ออกมา ตราประทับจะแสดงเฉพาะเมื่อใบสั่งขาย ยืนยันแล้ว และกรอก Stamp Date แล้ว โดยเนื้อหาในตราประกอบด้วย ลายเซ็นผู้ยืนยัน, วันที่ Stamp, กำหนดส่งมอบ, เลขงาน (JOB) และรหัส Stamp

เมนู / จุดเข้าถึง

  • ฟอร์มใบสั่งขาย แท็บ Stamp — กรอก Stamp Date / Stamp Code และดูแหล่งข้อมูล Stamp
  • เมนู พิมพ์ (Print) บนใบสั่งขาย — เลือกรายงาน Quotation / Order (with Stamp)
  • ฟอร์มพนักงาน (HR Employee) — ฟิลด์ลายเซ็น Signature ใช้เป็นรูปใน Stamp

ขั้นตอนการ Stamp เอกสาร

  1. ยืนยันใบเสนอราคา — กดปุ่ม Confirm ระบบจะบันทึกผู้ยืนยันและ Stamp ให้อัตโนมัติ
  2. กรอก Stamp Date และ Stamp Code — ในแท็บ Stamp (Stamp Code ตัวอย่างเช่น PMB26014 (MA))
  3. อัปโหลดลายเซ็นพนักงาน — ที่ฟอร์มพนักงาน เพื่อให้ Stamp แสดงลายเซ็นจริง
  4. พิมพ์ “(with Stamp)” — เลือกรายงาน Stamp จากเมนูพิมพ์ Stamp จะปรากฏบนเอกสาร

สถานะการแสดง Stamp

Quotation (ร่าง) → Confirmed (ยืนยัน) → กรอก Stamp Date → Stamp แสดงเมื่อพิมพ์

สิทธิ์

  • ผู้ใช้ฝ่ายขายกรอก Stamp Date / Stamp Code และ Stamp ได้ตามปกติ
  • ผู้ดูแลระบบ/HR เป็นผู้อัปโหลดรูปลายเซ็นของพนักงาน
ตราประทับ Stamp จะแสดง เฉพาะเมื่อทั้งสองเงื่อนไขพร้อมกัน: ใบสั่งขายยืนยันแล้ว (Confirmed) และกรอก Stamp Date เรียบร้อย — ถ้ายังไม่ Stamp ต้องตรวจสองเงื่อนไขนี้ก่อน

od19_sales_contract_core แกนสัญญาการขาย (Sales Contract)

โมดูลนี้เป็น แกนกลางของสัญญาการขาย รองรับวงเงินสัญญา, การใช้งบประมาณตามสัญญา งวดวางบิล (Billing Schedule) และการรับรู้รายได้ตามมาตรฐาน TFRS 15 (Revenue Schedule) พร้อมกลไกตรวจวงเงินเมื่อเกินสัญญา (over_limit_policy)

เมนูที่เกี่ยวข้อง

  • การขาย › Sales Contracts — ทะเบียนสัญญาการขายทั้งหมด
  • ฟอร์มใบสั่งขาย — ฟิลด์สัญญาที่ผูก, งวดวางบิล และกิจกรรมสัญญา

ขั้นตอนใช้งานสัญญา

  1. สร้างสัญญาและกำหนดวงเงิน — กรอกคู่ค้า โครงการ ช่วงวันที่ และวงเงิน (Limit Amount)
  2. กด “Approve” แล้ว “Activate” — สถานะไหลจากร่าง → อนุมัติ → ใช้งาน
  3. จัดตารางงวดวางบิล (Billing Schedule) — เพิ่มงวดแบบ milestone / periodic / percent พร้อมวันครบกำหนด
  4. ออกใบแจ้งหนี้งวด — กด “Create Next Installment Invoice” หรือปุ่ม “Create Invoice” รายงวด
  5. รับรู้รายได้ — กด “Recognize Revenue” ตามวิธีรับรู้ที่กำหนด (milestone / percent / progress)
  6. ปิดสัญญา — กด “Close” เมื่องานเสร็จสิ้น และ “Reset to Draft” เมื่อต้องการแก้ไข

สถานะสัญญา

Draft (ร่าง) → Approved (อนุมัติ) → Active (ใช้งาน) → Closed (ปิด)

งวดวางบิลมีสถานะ Draft → Invoiced และงวดรับรู้รายได้มีสถานะ Pending → Partial → Recognized

Over Limit Policyนโยบายเมื่อเกินวงเงิน: แค่เตือน / ต้องอนุมัติ / บล็อก

สิทธิ์

  • ผู้ใช้ฝ่ายขายสร้างและแก้ไขสัญญา/งวดวางบิลได้
  • การรับรู้รายได้และการใช้บัญชีรายได้เป็นของฝ่ายบัญชี (ผู้ใช้ที่ผูกสิทธิ์บัญชี)
ออกใบแจ้งหนี้ต้องเรียงงวด: ระบบกำหนดให้ต้องออกใบแจ้งหนี้ของ งวดก่อนหน้า ให้ครบก่อน จึงจะออกงวดถัดไปได้ เพื่อรักษาลำดับการวางบิลตามสัญญา

  3. อ่านค่าสรุป — ยอดก่อนภาษี จำนวนเอกสาร จำนวนโครงการ ฯลฯ

od19_sales_retention เงินประกันผลงาน (Retention)

โมดูลนี้รองรับ เงินประกันผลงาน (Retention) สำหรับงานโครงการ/ก่อสร้าง — ออกใบกำกับภาษี เต็มจำนวนเมื่อส่งมอบงวดงาน แล้วแยกยอด retention ไปพักที่ บัญชีลูกหนี้เงินประกัน เพื่อให้ภาษีขาย (ภ.พ.30) ถูกต้อง พร้อมติดตามกำหนดคืนด้วยระบบแจ้งเตือน

เมนูที่เกี่ยวข้อง

  • การขาย › Retentions (เงินประกันผลงาน) — ทะเบียนรายการ retention
  • การขาย › Retentions › Retention Outstanding (ค้างคืน) — เฉพาะรายการที่ยังไม่คืน
  • ฟอร์มสัญญาการขาย — กลุ่ม Retention และแท็บ Retentions

ขั้นตอนการจัดการ retention

  1. กำหนดอัตรา/ยอด retention ที่สัญญา — ตั้งอัตราเริ่มต้น จำนวนวัน และบัญชี/สมุดรายวันของ retention
  2. ระบบสร้างรายการอัตโนมัติ — เมื่อลงบัญชีใบกำกับภาษีของงวดที่มีการหัก retention
  3. กด “Hold” — พักยอดไว้ที่บัญชีลูกหนี้เงินประกัน สถานะเป็น Held
  4. ครบกำหนดกด “Release” — คืนเงินประกัน สถานะเป็น Released
  5. กด “Close” — ปิดรายการหลังคืนครบ
  6. พิมพ์ใบสำคัญรับ — กดปุ่ม “Retention Receipt” บนฟอร์ม

สถานะ retention

Draft → Held (พักไว้) → Released (คืนแล้ว) → Closed (ปิด)

รายการที่เลยกำหนดคืนจะแสดงเป็น Overdue และยกเลิกได้จากสถานะร่างเป็น Cancelled

ฟิลด์ / ปุ่มความหมาย
Base Amountยอดฐานที่ใช้คำนวณ retention (ยอดใบกำกับ)
Retention Rate / Amountอัตรา (%) และยอดเงินประกันผลงานที่หัก
Release Date / Released Dateกำหนดคืน และวันที่คืนจริง
Retention Account / Journalบัญชีลูกหนี้เงินประกัน และสมุดรายวันที่ใช้

สิทธิ์

  • ผู้ใช้ฝ่ายขาย/บัญชีที่ผูกสิทธิ์เข้าถึงทะเบียน retention ได้
  • การออกใบสำคัญรับและกระทบยอดคืนเป็นของฝ่ายบัญชี
ออกใบกำกับเต็มจำนวน: ต้องออกใบกำกับภาษีเต็มจำนวนตามหลักเกณฑ์ (หนังสือตอบข้อหารือ กค 0706/พ.789) แล้วแยกยอด retention ไปพักที่บัญชีลูกหนี้เงินประกัน เพื่อให้ VAT ขาย (ภ.พ.30) ถูกต้อง
ระบบมี Cron แจ้งเตือน วันครบกำหนดคืน และ แจ้งเตือนรายการเลยกำหนดโดยอัตโนมัติ

โมดูลนี้ให้แบบพิมพ์ ใบสั่งขายแบบ QWeb PDF ตามแบบ Odoo 19 จำนวน 2 รูปแบบ คือ รูปแบบดั้งเดิม (Classic) ที่คงโครงสร้างเดิม และ รูปแบบปรับปรุง (Modern) ที่จัดวางใหม่ให้อ่านง่ายขึ้น (ข้อมูลชุดเดียวกัน)

เมนู / จุดเข้าถึง

  • เมนู พิมพ์ (Print) บนใบสั่งขาย — เลือก “ใบสั่งขาย (รูปแบบดั้งเดิม)” หรือ “(รูปแบบปรับปรุง)”

ขั้นตอนการพิมพ์

  1. เปิดใบสั่งขาย — เลือกเอกสารที่ต้องการพิมพ์
  2. กดเมนูพิมพ์ — เลือกรูปแบบดั้งเดิมหรือรูปแบบปรับปรุง
  3. ระบบสร้างไฟล์ PDF — ใช้ฟอนต์ไทย (Sarabun) จากโมดูลสนับสนุนฟอนต์ไทย

สิทธิ์

  • การพิมพ์สองรูปแบบนี้จำกัดให้ System (ผู้ดูแลระบบ) เป็นค่าเริ่มต้น — ปรับได้ตามนโยบาย

od19_sale_terms เทมเพลตเงื่อนไขการขาย (Sale Terms)

โมดูลนี้รวม “เงื่อนไขมาตรฐาน” ของใบเสนอราคา (ราคา, การส่งมอบ, การชำระเงินสินค้า/งานวิศวกรรม, อายุราคา, การรับประกัน, เครดิต) ให้เป็น เทมเพลตที่ใช้ซ้ำได้ แล้วเลือกใช้บนใบสั่งขายได้หลายเงื่อนไขพร้อมกัน

เมนูที่เกี่ยวข้อง

  • การขาย › การตั้งค่า › Sale Term Templates — จัดการเทมเพลตเงื่อนไข
  • ฟอร์มใบสั่งขาย แท็บ Terms — เลือกเงื่อนไขและดูข้อความรวม

ขั้นตอนใช้งาน

  1. สร้างเทมเพลตเงื่อนไข — กำหนดชื่อ ชนิดเงื่อนไข (Term Type) และเนื้อหา
  2. เปิดใบสั่งขาย แท็บ Terms — เลือกเทมเพลตในแต่ละช่องตามชนิด
  3. ดูข้อความรวมอัตโนมัติ — ระบบรวมข้อความทุกเงื่อนไขตามลำดับคงที่ให้ทันที

สิทธิ์

  • ผู้ที่มีสิทธิ์ตั้งค่าการขายจัดการเทมเพลตได้
  • ผู้ใช้ฝ่ายขายเลือกใช้เทมเพลตบนใบสั่งขายได้
เทมเพลตต้องมีชื่อและชนิดเงื่อนไขไม่ซ้ำกัน (ระบบบังคับ unique) — รวมโมเดลเงื่อนไข 7 ตัวจาก Odoo 15 ให้เป็นโมเดลเดียวเพื่อการดูแลที่ง่ายขึ้น

od19_sale_wizards วิซาร์ดเปลี่ยนวันส่งและข้อมูลเงินมัดจำ

โมดูลนี้เพิ่ม วิซาร์ดเปลี่ยนวันที่จัดส่งให้ใบเสนอราคา และบันทึก ข้อมูลเงินมัดจำ (ที่มา/ต้นทาง) ไว้บนใบแจ้งหนี้ พร้อมเชื่อมการดึงรายการจากใบสั่งขายผ่านกลไกดึงเอกสารกลาง

เมนู / จุดเข้าถึง

  • ฟอร์มใบสั่งขาย (สถานะร่าง/ส่งแล้ว) — ปุ่ม Change Delivery Date ในแถบหัว
  • ฟอร์มใบแจ้งหนี้ — กลุ่ม Downpayment Info ในแท็บข้อมูลอื่น

ขั้นตอนเปลี่ยนวันจัดส่ง

  1. เปิดใบเสนอราคา — ต้องอยู่สถานะร่างหรือส่งแล้ว
  2. กด “Change Delivery Date” — เปิดวิซาร์ดเปลี่ยนวันส่ง
  3. เลือกวันส่งใหม่ แล้วกด “Apply” — ระบบปรับวันส่งมอบและคำนวณวันตามกำหนดของทุกรายการใหม่

สิทธิ์

  • ผู้ใช้ฝ่ายขายเปลี่ยนวันส่งได้ตามปกติเมื่อเอกสารยังไม่ยืนยัน
การเปลี่ยนวันส่งมีผลกับ วันตามกำหนดของทุกรายการในใบสั่งขาย — ควรแจ้งทีมที่เกี่ยวข้องก่อนปรับ โดยเฉพาะเมื่อมีการวางแผน stocking หรือผลิต

od19_sale_jasper แบบพิมพ์ Jasper งานขาย

โมดูลนี้ให้ แบบพิมพ์ Jasper (J-Report OD15) สำหรับงานขาย ได้แก่ ใบสั่งขาย, ใบเสนอราคา, ใบแจ้งหนี้ชั่วคราว, ใบรับประกัน พร้อมรายงานสรุปยอดขาย โดยพอร์ตจาก Odoo 15

เมนู / จุดเข้าถึง

  • เมนู พิมพ์ (Print) บนใบสั่งขาย — เลือก “(J-Report OD15) …”
  • แบบฟอร์มใบสั่งขายต้องอยู่สถานะยืนยันหรือเสร็จสิ้นจึงจะพิมพ์แบบF-S-002ได้

ขั้นตอนการพิมพ์แบบ Jasper

  1. เปิดใบสั่งขาย — ตรวจสอบว่าเอกสารยืนยันหรือเสร็จสิ้นแล้ว (สำหรับ F-S-002)
  2. ไปที่เมนูพิมพ์ — เลือกแบบฟอร์ม/รายงานที่ต้องการ
  3. กรอกพารามิเตอร์ — ภาษา ชนิด/รูปแบบวันที่ ชื่อ-ลายเซ็นผู้จัดทำ และช่วงวันที่/ปี-เดือน (ตามรายงาน)
  4. กดพิมพ์ — ระบบสร้างไฟล์ตามแบบฟอร์มที่พอร์ตมา

สิทธิ์

แบบฟอร์ม F-S-002 (ใบสั่งขาย) จะยอมให้พิมพ์เฉพาะเอกสารที่สถานะยืนยันหรือเสร็จสิ้น — เพื่อไม่ให้ส่งเอกสารที่ยังไม่ยืนยันให้ลูกค้า

od19_quotation_document_sequence เลขที่ใบเสนอราคาตามแผนก และการแก้ไข (Revision)

โมดูลนี้กำหนด เลขที่ใบเสนอราคาตามแผนก (เช่น QB/QT/QI/QD) และรองรับ การแก้ไขใบเสนอราคา (Revision) ด้วยการต่อท้ายชื่อเอกสารด้วย /R01, /R02 โดยเชื่อมกับโมดูล revision มาตรฐาน OCA

เมนู / จุดเข้าถึง

  • ฟอร์มใบเสนอราคา — ฟิลด์ Department และปุ่ม Create Revision / Revisions
  • พนักงาน › แผนก (Departments) — ฟิลด์ Quotation Sequence ต่อแผนก

ขั้นตอนใช้งาน

  1. กำหนดเลขที่ให้แผนก — ที่ฟอร์มแผนก เลือกลำดับเลขที่ (Quotation Sequence) ของแผนกนั้น
  2. สร้างใบเสนอราคา — ระบบเติมแผนกให้อัตโนมัติจากพนักงาน และออกเลขที่ตามแผนก (เช่น QB, QT, QI, QD)
  3. กด “Create Revision” — สร้างฉบับแก้ไข ระบบต่อท้ายชื่อด้วย /R01, /R02 …
  4. เลือกยกเลิกฉบับเดิมได้ — ในวิซาร์ดสามารถเลือกยกเลิกใบเสนอราคาเดิมพร้อมสร้างฉบับใหม่ได้
  5. ดูประวัติการแก้ไข — กดปุ่ม “Revisions” เพื่อดูฉบับก่อนหน้า

รูปแบบเลขที่ / สถานะแก้ไข

QB (BA) / QT (TA) / QI (IA) / QD (F/DES)

เลขที่ใช้รูปแบบ PREFIX + ปี(2) + เดือน + เลขรัน 4 หลัก (เช่น QT25110001) และฉบับแก้ไขต่อท้ายด้วย /R01

  • การกำหนดเลขที่ให้แผนกเป็นหน้าที่ของผู้ดูแล/ผู้ตั้งค่า HR
