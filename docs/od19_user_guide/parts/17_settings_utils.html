od19_thai_localization_base ฐานข้อมูลไทยและปีพุทธศักราช

โมดูลนี้เป็น “ฐาน” ของการแปลไทยในระบบ กำหนดค่าบริษัทให้ใช้ ฟอนต์ Sarabun และ เปิด การใช้ปีพุทธศักราช (พ.ศ.) ในรายงานไทยเป็นค่าเริ่มต้น โดยพึ่งพาโมดูล มาตรฐานของ OCA (l10n_th, l10n_th_base_utils, l10n_th_base_sequence, l10n_th_amount_to_text) ติดตั้งมาพร้อมกัน

จุดตั้งค่า

เปิดฟอร์มตั้งค่า: แอป “การตั้งค่า” › ทั่วไป › Thai Localization จะเห็นหัวข้อ “Use Buddhist Year (พ.ศ.)”

  1. เปิดฟอร์มตั้งค่าบริษัท ไปที่ การตั้งค่า › ทั่วไป แล้วเลื่อนลงหาแถบ “Thai Localization”
  2. ติ๊ก/ถอด “Use Buddhist Year (พ.ศ.)” ตามต้องการ (ค่าเริ่มต้นเปิดอยู่) แล้วกดบันทึก
  3. ตรวจผลในรายงาน เปิดรายงานไทยฉบับใดก็ได้ — ปีในวันที่จะแสดงเป็น พ.ศ. (เช่น 2568 แทน 2025)

od19_oca_th_translations คำแปลไทยสำหรับโมดูล OCA

โมดูลนี้เป็น “ส่วนเติมคำแปลไทย” ให้โมดูลที่มาจาก OCA (third-party) จำนวนมาก เพื่อให้ป้ายกำกับ ช่องกรอก ข้อความแจ้งเตือน และเมนูต่าง ๆ ของโมดูลเหล่านั้นแสดงเป็นภาษาไทย โดยโมดูลนี้ติดตั้งอัตโนมัติ (auto_install) เมื่อโมดูล OCA ที่รองรับถูกติดตั้ง

กลไกการทำงาน

ไฟล์ต้นทาง sources/<module>/th.po → คัดลอกเข้า <module>/i18n_extra/th.po → Odoo โหลดคำแปล

ไฟล์คำแปลที่ “ถือเป็นต้นฉบับ” ถูกเก็บไว้ในโมดูลนี้ (ติดตามด้วย git) แล้วคัดลอกไปยังโฟลเดอร์ i18n_extra ของโมดูล OCA เป้าหมาย ทุกครั้งที่เซิร์ฟเวอร์เริ่มทำงาน เพื่อไม่ให้คำแปลหายไปเมื่อ clone ใหม่ (เพราะไฟล์ในโฟลเดอร์ OCA ไม่ได้ถูกเก็บใน submodule)

ขั้นตอน (สำหรับผู้ดูแลระบบ)

  1. ติดตั้งโมดูล OCA ที่ต้องการ โมดูลคำแปลจะตามมาอัตโนมัติ
  2. ตั้งภาษาผู้ใช้เป็นไทย ที่ข้อมูลส่วนตัวของผู้ใช้ (Preferences → Language = ไทย)
  3. รีเฟรชหน้าเว็บ ป้ายกำกับ/ข้อความของโมดูล OCA จะแสดงเป็นไทย
คำแปลชุดนี้ทำงานเมื่อ “เซิร์ฟเวอร์เริ่มทำงาน” (post-load) — หากแก้ไฟล์ .po ต้นทาง ต้องรีสตาร์ทเซิร์ฟเวอร์หรืออัปเดตโมดูลเพื่อให้ระบบคัดลอกเวอร์ชันใหม่ไปใช้

od19_partner_document_sequence เลขที่รหัสคู่ค้า (C/V)

ออกรหัสอ้างอิงให้คู่ค้าโดยอัตโนมัติ แยกตามประเภท — ลูกค้า ขึ้นต้นด้วย C และ ผู้จำหน่าย ขึ้นต้นด้วย V ตามด้วยเลขรัน 4 หลัก (เช่น C0001, V0001) เพื่อใช้อ้างอิงในเอกสารและงานภายใน

ฟิลด์บนหน้าคู่ค้า

🧑 Is a Customer

ติ๊กเมื่อคู่ค้าเป็นลูกค้า — รหัสจะเริ่มด้วย C

🏭 Is a Vendor

ติ๊กเมื่อคู่ค้าเป็นผู้จำหน่าย — รหัสจะเริ่มด้วย V

🔁 Auto Running

เปิดเพื่อให้ระบบออกรหัสอัตโนมัติ

🧩 Customer + Vendor

ถ้าเป็นทั้งสองอย่าง ระบบจะปิดการออกรหัสอัตโนมัติ

ขั้นตอน

  1. สร้าง/เปิดคู่ค้า ไปที่หน้าคู่ค้า แล้วดูส่วน “Reference” (รหัสอ้างอิง)
  2. ระบุประเภท ติ๊ก “Is a Customer” และ/หรือ “Is a Vendor”
  3. เว้นรหัสว่างไว้ ให้ช่อง Reference ว่างไว้ (อย่าใส่ “New”, “/”) ระบบจะสร้างรหัสให้เมื่อบันทึก
ถ้าคู่ค้าเป็นทั้งลูกค้าและผู้จำหน่าย ระบบจะไม่สร้างรหัสให้อัตโนมัติ (เพื่อไม่ให้รหัสซ้ำสองแบบ) ผู้ใช้สามารถกรอกรหัสเองได้
รหัสที่ออกแล้วระบบจะไม่สร้างใหม่ทับ — ถ้าต้องการรหัสชุดใหม่ ให้ตรวจว่าช่อง Reference ว่างจริงก่อนบันทึก

เพิ่มการจำแนก “บทบาท” ของคู่ค้าเป็น 3 แบบ เพื่อช่วยกรองและจัดกลุ่มคู่ค้าให้ตรงกับงานขาย-โครงการ พร้อมช่องโทรศัพท์มือถือและกฎตรวจสอบความถูกต้องของข้อมูล

od19_offline_draft ร่างอัตโนมัติ (Offline Draft)

บันทึกข้อมูลที่กรอกค้างไว้เป็น “ร่าง” ให้อัตโนมัติ ป้องกันข้อมูลหายเมื่อเน็ตหลุด ปิดหน้าต่าง หรือรีเฟรชหน้า ใช้ได้ทั้งหน้าจอการทำงาน (Backend) และหน้าพอร์ทัล (Portal)

หลักการทำงาน

ผู้ใช้พิมพ์ข้อมูล → บันทึกลงเบราว์เซอร์ทันที → ซิงก์ขึ้นเซิร์ฟเวอร์เมื่อออนไลน์ → บันทึกจริงสำเร็จ = ล้างร่าง

การกู้คืนร่าง

  1. เปิดฟอร์มที่เคยกรอกค้างไว้ ระบบจะตรวจพบว่ามีร่างเดิมบันทึกไว้
  2. เลือกจากแบนเนอร์ด้านบน จะเห็นข้อความ “พบร่างที่บันทึกไว้ — กู้คืนหรือทิ้ง?”
  3. กด “กู้คืน” เพื่อนำค่ากลับเข้าฟอร์ม หรือ ทิ้ง เพื่อลบร่างนั้น
  4. บันทึกฟอร์มตามปกติ เมื่อบันทึกสำเร็จ ระบบจะล้างร่างให้อัตโนมัติ

ผู้ดูแลระบบดูรายการร่างทั้งหมดได้ที่ การตั้งค่า › Offline Drafts (เฉพาะกลุ่มผู้ดูแลระบบ)

ร่างถูกเก็บแยกตาม “ผู้ใช้ + เอกสาร” — ผู้ใช้จะเห็นและกู้คืนได้เฉพาะร่างของตัวเองเท่านั้น ห้ามใช้เป็นช่องทางแชร์ข้อมูลระหว่างผู้ใช้
ร่างเก็บเฉพาะค่าฟิลด์เชิงเดี่ยว (ข้อความ/ตัวเลข/วันที่) ไม่รวมฟิลด์ความสัมพันธ์ (Many2one/Many2many) และไฟล์แนบขนาดใหญ่จะถูกจำกัดไม่เกิน 5 MB

od19_field_hints คำใบ้ในช่องกรอก (Field Hints)

แสดงข้อความตัวอย่าง/คำแนะนำ/คำเตือน สีเทา ในช่องกรอกที่ยังว่างอยู่ (placeholder) เพื่อช่วยให้ผู้ใช้รู้ว่าควรกรอกอะไร โดยข้อความนี้ ไม่ถูกบันทึก เป็นข้อมูลจริง

ลักษณะข้อความ

ชนิดคำนำหน้าใช้เมื่อ
ตัวอย่าง (example)“ตัวอย่าง:”ช่องวันที่/ตัวเลข/อีเมล ฯลฯ
แนะนำ (hint)“แนะนำ:”ช่องข้อความ/ตัวเลือกทั่วไป
สำคัญ (warning)“สำคัญ:”ช่องที่จำเป็นต้องกรอก (Required)

จุดตั้งค่า

  1. เปิดการตั้งค่า ไปที่ การตั้งค่า › ทั่วไป › ข้อความแนะนำในช่องกรอก
  2. เปิด/ปิดสวิตช์ ติ๊ก “ข้อความแนะนำในช่องกรอก” เพื่อเปิดใช้งาน (ค่าเริ่มต้นเปิด)
  3. เลือกขอบเขต ติ๊ก “ใช้กับโมดูลมาตรฐาน (Core/OCA) ด้วย” หากต้องการให้แสดงกับทุกโมดูล (ค่าเริ่มต้นปิด = แสดงเฉพาะโมดูล od19_*)
  4. รีเฟรชหน้าเว็บ เพื่อให้ค่าที่เปลี่ยนมีผล
โดยค่าเริ่มต้น คำใบ้จะแสดงเฉพาะฟิลด์ที่โมดูลของเราเพิ่ม — ต้องติ๊ก “ใช้กับ Core/OCA” จึงจะเห็นในโมดูลมาตรฐาน
คำใบ้จะแสดงเฉพาะช่องที่แก้ไขได้และยังว่าง — ถ้าช่องมีข้อมูลอยู่แล้วจะไม่ทับข้อความเดิม

od19_ui_defaults ค่าเริ่มต้น UI และความอ่านง่าย

ปรับค่าเริ่มต้นของส่วนติดต่อผู้ใช้ให้สอดคล้องกันทั้งระบบ เพื่อลดความสับสนและทำให้กรอกข้อมูลง่ายขึ้น โมดูลนี้ทำงานอัตโนมัติทั้งชุด (ไม่มีเมนูตั้งค่าแยก) และจะจัดเรียงใหม่ให้ทุกครั้งที่อัปเดตโมดูล

สิ่งที่ปรับให้อัตโนมัติ

📌 เมนูตั้งค่าอยู่ท้ายเสมอ

เมนู “Configuration/ตั้งค่า” ของแต่ละแอปจะอยู่ท้ายสุดของแถบเมนูเสมอ

🗂️ จัดกลุ่มเมนู NavBar

รวมเมนูที่เกี่ยวข้องไว้ด้วยกันเป็นเมนูย่อย เพื่อไม่ให้แถบเมนูยาวเกินไป

✂️ ย้าย/เปลี่ยนชื่อเมนู

ย้ายเมนูที่ซ้ำหรือกำกวม และตั้งชื่อใหม่ให้ชัดเจนทั้งไทย–อังกฤษ

📐 ลำดับแอปตามขั้นตอนธุรกิจ

จัดเรียงไอคอนแอปเป็นกลุ่มตามสายงาน (หน้าบ้าน การเงิน จัดซื้อ โครงการ บุคคล ฯลฯ)

👓 ฟอร์มอ่านง่ายขึ้น

เพิ่มความชัดเจนของป้ายชื่อและขอบช่องกรอก โดยไม่เปลี่ยนโครงสร้างฟอร์ม

🏷️ เน้นช่องที่ยังว่าง

ช่องที่ยังไม่ได้กรอกในโหมดแก้ไขจะแสดงพื้นอ่อนกว่าเล็กน้อย

ผลที่ผู้ใช้เห็น

  • ไอคอนแอปถูกจัดเป็นกลุ่มตามสายงาน ทำให้หาแอปที่ใช้ด้วยกันได้เร็วขึ้น
  • แถบเมนูด้านบนสั้นลง เพราะรวมเมนูที่เกี่ยวข้องเป็นเมนูย่อย (Dropdown)
  • ช่อง “ส่วนลด (Discount)” เปิดใช้งานไว้เป็นค่าเริ่มต้นในใบเสนอราคา/ใบสั่งขาย
โมดูลนี้จะจัดเรียงเมนูใหม่ให้อัตโนมัติทุกครั้งที่อัปเดตโมดูล ดังนั้นการเรียงที่ปรับไว้จะไม่ถูกทับกลับเป็นค่าเดิม
การเปลี่ยนชื่อ/ย้ายเมนูเป็นการตั้งค่าระดับระบบ (Global) — มีผลกับผู้ใช้ทุกคน ไม่ใช่รายบุคคล

od19_apps_filter ตัวกรองแอป (OD19 Modules)

เพิ่มตัวกรองและเมนูลัดในหน้ารวมแอป (Apps) เพื่อแสดงเฉพาะโมดูลที่เราพัฒนาเอง (ขึ้นต้นด้วย od19_) ทำให้ผู้ดูแลระบบค้นหาและติดตั้งโมดูลของเราได้สะดวกและรวดเร็ว

จุดตั้งค่า / เมนู

ใช้ได้ 2 ทาง: ตัวกรองในหน้า Apps ตามปกติ หรือเมนูลัด การตั้งค่า › OD19 Modules

ตัวกรองที่เพิ่ม

ตัวกรองแสดงอะไร
OD19 Modulesเฉพาะโมดูลที่ชื่อขึ้นต้นด้วย od19_
New Appsโมดูลที่ยังไม่ได้ติดตั้ง/รอติดตั้ง
New OD19 Appsโมดูล od19_ ที่ยังไม่ได้ติดตั้ง

ขั้นตอน

  1. เปิดหน้ารวมแอป แล้วกด “Apps” หรือไปที่เมนูลัด การตั้งค่า › OD19 Modules
  2. เลือกตัวกรอง เลือก “OD19 Modules” หรือ “New OD19 Apps”
  3. ติดตั้ง/อัปเดตตามต้องการ กดปุ่ม “Install/Upgrade” ของโมดูลที่เลือก
ใช้คู่กับตัวกรอง “New OD19 Apps” เพื่อดูว่าโมดูลของเราตัวไหนยังไม่ได้ติดตั้งบ้างในที่เดียว
เมนูลัด “OD19 Modules” อยู่ภายใต้แอปการตั้งค่า จึงต้องมีสิทธิ์เข้าถึงการตั้งค่าจึงจะมองเห็น

od19_misc_features ฟีเจอร์เบ็ดเตล็ด (Misc Features)

รวมฟีเจอร์ย่อยที่จำเป็นแต่ไม่มีโมดูลใดโมดูลหนึ่งโดยเฉพาะไว้ในที่เดียว เช่น โลโก้ ISO ของบริษัท, การปิดการตรวจวันที่/เลขที่เอกสารเพื่อรองรับงานย้อนหลัง, เครื่องมือตรวจสอบสภาพแวดล้อมของระบบ (Runtime Guard) และรายงานลูกค้าซื้อซ้ำ

คำสั่งตรวจสอบระบบ (Runtime Guard)

  1. เปิดเมนู ไปที่ การตั้งค่า › Misc Features › Runtime Guard
  2. รันการตรวจสอบ เลือก “Run Runtime Check” แล้วกด “Run Check” ในหน้าต่างที่เปิดขึ้น
  3. ดูผล Snapshot ระบบจะบันทึกและเปิดผลลัพธ์ให้ดูทันที (เวอร์ชัน Python, เวอร์ชัน Odoo, จำนวนโมดูลที่ติดตั้ง, ขนาดฐานข้อมูล)

โลโก้ ISO ของบริษัท

อัปโหลดโลโก้รับรอง ISO ได้ที่ การตั้งค่า › บริษัท (ช่อง “ISO Logo”) หรือที่ การตั้งค่า › ทั่วไป เพื่อใช้แสดงบนรายงานและเอกสาร

รายงานลูกค้าซื้อซ้ำ (Repeat Customer Enhanced)

คอลัมน์ความหมาย
Customerคู่ค้าผู้สั่งซื้อ
Actual Partnerคู่ค้าที่ใช้จริง (ผู้รับสินค้า ถ้ามี; ไม่งั้นใช้ผู้สั่งซื้อ)
Last Order Dateวันที่สั่งซื้อล่าสุด
Order Countจำนวนใบสั่งขายที่ยืนยันแล้ว
Total Amountยอดรวมสุทธิ

เรียกดูได้ที่ การขาย › รายงาน › Repeat Customer Enhanced พร้อมตัวกรอง “Last 30 Days” / “Last 90 Days”

การรองรับงานย้อนหลัง

โมดูลนี้ปิดการตรวจสอบ “วันที่ต้องสอดคล้องกับเลขที่เอกสาร” ของ Odoo จึงสามารถลงบันทึกเอกสารย้อนหลังได้ (รองรับกรณีใช้ปี พ.ศ. และการลงวันที่ย้อนหลัง) — ผู้ใช้ต้องระมัดระวังเป็นพิเศษเรื่องความถูกต้องของเลขที่
ฟีเจอร์ “Runtime Guard” เป็นการทำงานแบบสั่งเองด้วยมือ ไม่ใช่ cron และจำกัดสิทธิ์เฉพาะผู้ดูแลระบบ

od19_dev_field_marker เครื่องหมายฟิลด์ [od19] (โหมด Dev)

ช่วยนักพัฒนา/ผู้ดูแลระบบแยกแยะ “ฟิลด์ที่เราสร้างเอง” ออกจากฟิลด์มาตรฐานของ Odoo ได้อย่างรวดเร็ว โดยจะเติมคำนำหน้า [od19] ให้ป้ายชื่อของฟิลด์ที่ขึ้นต้นด้วย od19_ เฉพาะเมื่อเปิดโหมดนักพัฒนา (Developer Mode) เท่านั้น

ขั้นตอน

  1. เปิดโหมดนักพัฒนา ไปที่ การตั้งค่า › เปิดใช้โหมดนักพัฒนา
  2. เปิดหน้าจอที่มีฟิลด์ของเรา เช่น หน้าคู่ค้า — ป้ายชื่อฟิลด์ที่เราสร้างจะขึ้นต้นด้วย [od19]
  3. ปิดโหมดนักพัฒนาเมื่อเสร็จ ป้ายชื่อจะกลับสู่ปกติ
นอกโหมดนักพัฒนา ป้ายชื่อจะแสดงตามปกติโดยไม่มีเครื่องหมาย — จึงไม่มีผลกับผู้ใช้งานทั่วไป
ใช้เครื่องหมายนี้ช่วยตรวจสอบว่าฟิลด์ที่เห็นเป็นของเรา (ปรับแต่งได้) หรือของมาตรฐาน Odoo ก่อนแก้ไขหรือออกแบบฟอร์มเพิ่มเติม
