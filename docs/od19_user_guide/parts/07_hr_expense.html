👥 ส่วนที่ 7 · บุคคลและค่าใช้จ่ายพนักงาน

รวมงานที่พนักงานและฝ่ายบุคคล (HR) ใช้ทุกวัน — เบิกค่าใช้จ่ายที่ตัวเองออกเงินไปก่อน, ขอเงินทดรองจ่ายก่อนเดินทาง, ลงเวลาผ่านเครื่องสแกน ZKTeco, จองห้องประชุม และมอบคำชื่นชมให้เพื่อนร่วมงาน เอกสารการเงินทั้งหมดผ่านการอนุมัติเป็นชั้น (Tier Validation) และเชื่อมเข้าบัญชีจริง

สารบัญส่วนนี้

  1. ค่าใช้จ่ายพนักงาน (ไทย) — อนุมัติ 3 ชั้น + จ่ายคืนพนักงาน
  2. ค่าใช้จ่ายส่วนขยาย — เบี้ยเลี้ยง/ค่าเดินทาง/ภาษีหัก/มอบหมายอนุมัติ
  3. พอร์ทัลพนักงาน — ยื่นใบเบิกและติดตามสถานะ
  4. เงินทดรองจ่ายพนักงาน (Employee Advance)
  5. ลงเวลาด้วยเครื่อง ZKTeco
  6. จองห้องประชุม (Meeting Room Booking)
  7. ยกย่องเพื่อนร่วมงาน (Recognition / Kudos)

od19_hr_expense_thai ค่าใช้จ่ายพนักงาน (ไทย) — อนุมัติ 3 ชั้น + จ่ายคืนพนักงาน

ส่วนขยายของใบเบิกค่าใช้จ่าย (hr.expense) สำหรับการใช้งานในประเทศไทย เพิ่มวิธีรับเงินคืน (เงินสด/โอน/เช็ค), ประเภทค่าใช้จ่ายแบบไทย และ สายอนุมัติ 3 ชั้น ที่บังคับตามลำดับ ก่อนที่เอกสารจะผ่านและจ่ายคืนพนักงานได้จริง

วัตถุประสงค์

  • กำหนดวิธีรับเงินคืนและวันที่จ่ายคืนให้พนักงาน
  • จำแนกประเภทค่าใช้จ่ายตามหมวดขององค์กร (เดินทาง/อาหาร/ที่พัก/การสื่อสาร ฯลฯ)
  • บังคับอนุมัติตามลำดับชั้นหัวหน้าแผนก → บัญชี → CEO
  • สร้าง รายการจ่ายจริง (account.payment) และกระทบยอดกับเจ้าหนี้พนักงานให้ยอดเคลียร์

เมนู

โมดูลนี้ไม่เพิ่มเมนูใหม่ — ทำงานผ่านฟอร์มของ ค่าใช้จ่าย › ใบเบิกของฉัน / ค่าใช้จ่ายทั้งหมด โดยเพิ่มฟิลด์และปุ่มเข้าไปในฟอร์มเดิม

สายอนุมัติ 3 ชั้น (เรียงตามลำดับ)

ยื่นขออนุมัติ → ชั้น 1 · หัวหน้าแผนก → ชั้น 2 · ฝ่ายบัญชี → ชั้น 3 · CEO → อนุมัติครบ
ชั้นกลุ่มผู้อนุมัติค่า sequence
ชั้น 1 · หัวหน้าแผนกHR Expense Manager30
ชั้น 2 · ฝ่ายบัญชีAccount Manager20
ชั้น 3 · CEOExpense CEO Approver10
ระบบเรียงชั้นตาม sequence จากมากไปน้อย (เลขมากอนุมัติก่อน) และตั้งค่า อนุมัติตามลำดับ (approve_sequence) ทุกชั้น จึงอนุมัติข้ามชั้นไม่ได้จนกว่าชั้นก่อนหน้าจะครบ เปิดให้ใช้ปุ่ม ส่งต่อ (Forward) มอบหมายให้ผู้ใช้อื่นได้

ขั้นตอนเบิกและรับเงินคืน

  1. สร้างใบเบิก เลือกหมวดค่าใช้จ่าย ระบุจำนวนเงิน และตั้ง วิธีรับเงินคืน (เงินสด/โอน/เช็ค) พร้อม ประเภทค่าใช้จ่าย
  2. ยื่นขออนุมัติ กด ส่งขออนุมัติ — เอกสารจะไล่ตามสายอนุมัติทั้ง 3 ชั้น
  3. ลงบัญชี เมื่ออนุมัติครบ ให้แสดงรายการบัญชีของใบเบิก (Post) เพื่อบันทึกเจ้าหนี้พนักงาน
  4. จ่ายคืนพนักงาน กด Reimburse Employee ระบบจะสร้างรายการจ่ายออก (outbound) และกระทบยอดกับเจ้าหนี้พนักงานให้อัตโนมัติ

ฟิลด์/ปุ่มสำคัญ

ประเภทค่าใช้จ่ายเดินทาง / อาหาร / ยานพาหนะ / ที่พัก / การสื่อสาร / เครื่องเขียน / การแพทย์ / อบรม / อื่น ๆ
วันที่จ่ายคืนวันที่พนักงานได้รับเงินคืนจริง
ต้องอนุมัติชั้นที่สองคำนวณอัตโนมัติเมื่อยอดเกินวงเงินที่ตั้งไว้ในพารามิเตอร์ od19_hr_expense_thai.second_approval_threshold (ค่าเริ่มต้น 5,000 บาท)

รายการจ่ายคืนพนักงานรายการจ่ายที่ถูกสร้างขึ้นและกระทบยอดแล้ว

สิทธิ์

  • พนักงานทั่วไป: สร้างและยื่นใบเบิกของตัวเอง
  • หัวหน้าแผนก / บัญชี / CEO: อนุมัติตามชั้นที่ตัวเองมีสิทธิ์
  • กลุ่ม Expense CEO Approver ใช้สำหรับชั้นอนุมัติที่ 3
ปุ่ม Reimburse Employee ใช้ได้เฉพาะใบเบิกที่มีรูปแบบ พนักงานออกเงินเอง และลงบัญชีแล้ว หากยังไม่ลงบัญชี ระบบจะแจ้งให้ลงบัญชีก่อน — และจะจ่ายคืนซ้ำไม่ได้ถ้ามีรายการจ่ายคืนอยู่แล้ว
ต้องมีสมุดบัญชีเงินสด/ธนาคารที่ตั้งบัญชีค้างจ่าย (outstanding) ไว้ มิฉะนั้นระบบสร้างรายการจ่ายคืนไม่ได้

od19_hr_expense_enhanced ค่าใช้จ่ายส่วนขยาย — เบี้ยเลี้ยง/ค่าเดินทาง/ภาษีหัก/มอบหมายอนุมัติ

โมดูลนี้เพิ่มความสามารถให้ใบเบิกค่าใช้จ่ายในชีวิตจริงขององค์กร: ผู้อนุมัติชั้นแรกอัตโนมัติจากหัวหน้าแผนก, วงจรเงินสดทดรอง, เบี้ยเลี้ยง ม.42(3), ค่าเดินทางตามระยะทาง (ไมล์), ใบรับรองแทนใบเสร็จรับเงิน, ภาษีหัก ณ ที่จ่าย, การมอบหมายอนุมัติ และรายงานส่งออก XLSX

📄 ใบรับรองแทนใบเสร็จ

ใช้เมื่อผู้รับเงินออกใบเสร็จไม่ได้ — ไม่มีภาษีซื้อหักได้

🤝 มอบหมายอนุมัติ

ส่งต่อการอนุมัติให้ผู้ใช้อื่นแทนได้

เมนู

ค่าใช้จ่าย › รถของฉัน (สมุดรถของพนักงาน สำหรับใช้ผูกกับค่าเดินทาง) และฟิลด์/ปุ่มต่าง ๆ ถูกเพิ่มในฟอร์มใบเบิกเดิม

ค่าเดินทางตามระยะทาง (ไมล์)

  1. ติ๊ก ค่าเดินทางตามระยะทาง ในฟอร์มใบเบิก
  2. ระบุ ระยะทาง (กม.) และเลือกรถจาก รถของฉัน (หรือสร้างรถใหม่ที่เมนู ค่าใช้จ่าย › รถของฉัน)
  3. ระบบคูณด้วย อัตราต่อ กม. ที่ตั้งในบริษัท แล้วคำนวณยอดเงินให้อัตโนมัติ (ค่าเดินทางไม่มีภาษีมูลค่าเพิ่ม)
  4. ระบุต้นทาง–ปลายทาง และวันที่เดินทางเพื่อประกอบการพิจารณา
มีสินค้าหมวด ค่าเดินทางตามระยะทาง / Mileage (รหัส MIL-KM) หน่วยนับเป็นกิโลเมตร และราคาทุนเป็น 0 เพื่อให้ระบบคำนวณราคาต่อหน่วยจากยอดรวมได้

เบี้ยเลี้ยง ม.42(3)

  • ติ๊ก เบี้ยเลี้ยง แล้วเลือก พื้นที่ (ในประเทศ/ต่างประเทศ) และจำนวนวัน
  • ระบบเทียบกับ วงเงินมาตรฐานต่อวัน ของบริษัท แล้วคำนวณ วงเงินเบี้ยเลี้ยง และตัวชี้ เกินวงเงิน
  • ถ้าเกินวงเงิน ต้องกรอก เหตุผลที่เกินวงเงิน มิฉะนั้นระบบจะไม่ให้บันทึก

ใบรับรองแทนใบเสร็จรับเงิน

  • เลือก ประเภทเอกสาร เป็น ใบรับรองแทนใบเสร็จรับเงิน — ระบบจะไม่คิดภาษีซื้อ (หักไม่ได้)
  • กดปุ่ม พิมพ์ใบรับรองแทนใบเสร็จ เพื่อพิมพ์เอกสาร (รวมผู้จ่าย/ผู้รับ/พยาน และจำนวนเงินเป็นตัวอักษร)

วงจรเงินสด + ปุ่มในฟอร์ม

ยังไม่ได้รับเงิน → ได้รับเงินแล้ว → ใช้เงินแล้ว → คืนเงินแล้ว
ปุ่มทำอะไร
รับเงิน (Receive Cash)เปลี่ยนสถานะเงินสดเป็น “ได้รับเงินแล้ว”
ใช้เงิน (Use Cash)เปลี่ยนสถานะเป็น “ใช้เงินแล้ว”
คืนเงิน (Return Cash)เปิดหน้าต่างคืนเงินที่เหลือ (เลือกสมุดบัญชีและสร้างผังรายการได้)
รีเซ็ตสถานะเงินสดเฉพาะผู้ดูแลระบบ
มอบหมายอนุมัติเลือกผู้รับมอบหมายให้อนุมัติ/ไม่อนุมัติแทน
อนุมัติ (ผู้รับมอบหมาย) / ไม่อนุมัติ (ผู้รับมอบหมาย)ใช้ได้เฉพาะผู้ที่ถูกมอบหมาย

ภาษีหัก ณ ที่จ่าย (บนรายการจ่าย)

  • เมื่อเป็นรายการจ่ายค่าใช้จ่าย เลือก ประเภทภาษีหัก (1% / 2% / 3% / 5%) และ มูลค่าคิดภาษี
  • ระบบคำนวณ จำนวนภาษีหัก และสร้างผังรายการภาษี (เดบิตค่าใช้จ่าย / เครดิตภาษีต้องชำระ) ให้เมื่อลงรายการจ่าย

สิทธิ์

  • พนักงาน: เห็นและแก้ไข “รถของฉัน” เฉพาะของตัวเอง
  • ผู้จัดการค่าใช้จ่าย (HR) และผู้จัดการบัญชี: เห็นสมุดรถของทุกคน
  • เฉพาะผู้ดูแลระบบเท่านั้นที่รีเซ็ตสถานะเงินสดได้
ค่าเดินทางตามระยะทางและใบรับรองแทนใบเสร็จรับเงิน ห้ามมีภาษี — ถ้าเผลอใส่ภาษี ระบบจะไม่ให้บันทึก
ใช้ปุ่ม Export XLSX ในมุมมองรายการเพื่อส่งออกรายการค่าใช้จ่ายเป็นไฟล์ Excel ได้ทันที

od19_hr_expense_portal พอร์ทัลพนักงาน — ยื่นใบเบิกและติดตามสถานะ

ยกระดับประสบการณ์พนักงานในการเบิกค่าใช้จ่าย: มีหน้าต่างยื่นใบเบิกแบบสั้น, มุมมอง “ใบเบิกของฉัน” และหน้าพอร์ทัล (/my/expenses) ให้พนักงานยื่นและติดตามใบเบิกของตัวเองได้จากหน้าเว็บ

เมนู

  • ค่าใช้จ่าย › ยื่นใบเบิกค่าใช้จ่าย — หน้าต่างยื่นใบเบิกแบบเร็ว
  • ค่าใช้จ่าย › ใบเบิกของฉัน — มุมมองแบบบัตร (kanban) แสดงใบเบิกของตัวเองพร้อมช่อง “รออนุมัติจาก”
  • พอร์ทัล: /my/expenses (ดูรายการ), /my/expenses/new (ยื่นใหม่), /my/expenses/help (คู่มือ)

ขั้นตอนยื่นใบเบิก (จากหน้าต่างยื่นเร็ว)

  1. ข้อมูลเบื้องต้น เลือกหมวดค่าใช้จ่าย พนักงาน วันที่ และรายละเอียด
  2. จำนวนเงิน กรอกจำนวนเงิน หรือถ้าเป็นค่าเดินทางตามระยะทางให้กรอกระยะทาง/เลือกรถ ระบบคำนวณยอดให้
  3. รายละเอียดการเดินทาง (เฉพาะค่าเดินทาง) ระบุต้นทาง–ปลายทาง
  4. การส่ง ติ๊ก “ส่งอนุมัติทันที” ถ้าต้องการยื่นเข้าสายอนุมัติเลย แล้วกด ยื่นใบเบิก

od19_hr_advance เงินทดรองจ่ายพนักงาน (Employee Advance)

ใบเบิก เงินทดรองจ่าย คือเงินที่บริษัทจ่ายให้พนักงาน ก่อน ไปใช้จ่าย (ต่างจากใบเบิกค่าใช้จ่ายที่เป็นการคืนเงินที่พนักงานออกไปก่อน) ยอดจะค้างอยู่ที่บัญชีลูกหนี้พนักงาน จนกว่าพนักงานจะนำค่าใช้จ่ายมาเคลียร์และคืนเงินส่วนที่เหลือ

เมนู

ค่าใช้จ่าย › Employee Advances (เงินทดรองพนักงาน)

ขั้นตอนใช้งาน

  1. สร้างใบเบิกเงินทดรอง เลือกพนักงาน ระบุจำนวนเงิน วัตถุประสงค์ และ บัญชีลูกหนี้พนักงาน (บัญชีที่ใช้ติดตามยอดค้าง)
  2. ยื่นขออนุมัติ กด Submit for Approval — เอกสารเข้าสายอนุมัติ 2 ชั้น
  3. จ่ายเงิน เมื่ออนุมัติแล้ว กด Pay Advance ระบบสร้างรายการจ่ายจริง (เดบิตลูกหนี้พนักงาน / เครดิตเงินสด-ธนาคาร)
  4. เคลียร์เงินทดรอง กด Clear เลือกค่าใช้จ่ายที่นำมาเคลียร์ + ระบุจำนวนเงินที่คืน (ถ้ามี) แล้วระบบสร้างผังรายการหักกลบและกระทบยอดให้

สถานะ (statusbar)

ร่าง → รออนุมัติ → อนุมัติแล้ว → จ่ายแล้ว → เคลียร์แล้ว

สถานะ ยกเลิก ใช้ได้เฉพาะใบที่ยังไม่จ่าย/ยังไม่เคลียร์ และกด Reset to Draft กลับเป็นร่างได้

od19_hr_attendance_zkteco ลงเวลาด้วยเครื่อง ZKTeco

รับข้อมูลลงเวลาจากเครื่องสแกนลายนิ้วมือ/ใบหน้า ZKTeco ที่ใช้โปรโตคอล push (ADMS / iClock) มาจับคู่เป็นรายการเช็คอิน–เช็คเอาท์ในระบบลงเวลาอัตโนมัติ พร้อมเก็บ Log ดิบไว้ตรวจสอบย้อนหลัง

เมนู

  • ลงเวลา › การตั้งค่า › ZKTeco Devices › Devices — ทะเบียนเครื่อง
  • ลงเวลา › การตั้งค่า › ZKTeco Devices › Punch Logs — บันทึกการสแกนดิบ
  • ลงเวลา › HR Attendance Board — แดชบอร์ดภาพรวมการลงเวลา

เมนู Devices / Punch Logs เห็นได้เฉพาะผู้จัดการฝ่ายลงเวลา (Attendance Manager)

ขั้นตอนติดตั้งและใช้งาน

  1. ตั้งค่าที่ระบบ ไปที่ ลงเวลา › การตั้งค่า แล้วเปิด “Enable ZKTeco Devices” ตั้งค่า Communication Key และเลือกฟิลด์จับคู่พนักงาน (Badge ID หรือ PIN)
  2. ลงทะเบียนเครื่อง เพิ่มเครื่องที่เมนู Devices โดยระบุ Serial Number (และ Communication Key ของเครื่อง ถ้ามี)
  3. ตั้งค่าเครื่องสแกน ที่เครื่อง ให้ตั้ง Server เป็นที่อยู่/พอร์ตของ Odoo และเปิดโหมด ADMS/ชื่อโดเมน โดยเครื่องจะเรียก /iclock/cdata, /iclock/getrequest, /iclock/ping เอง
  4. รับข้อมูลอัตโนมัติ เมื่อพนักงานสแกน ระบบจะเก็บ Log และจับคู่เข้าเกณฑ์เวลาทันที (หรือรอตัวประมวลผลตามกำหนด)

สถานะความหมาย

การตั้งค่าที่สำคัญ (บริษัท)

  • Communication Key — รหัสที่เครื่องต้องส่งมาตรงกัน มิฉะนั้นคำขอถูกปฏิเสธ (ถ้าไม่ตั้งจะไม่รับเครื่องใดเลย)
  • จับคู่พนักงานด้วย — Badge ID (บาร์โค้ด) หรือ PIN
  • ประมวลผลอัตโนมัติ — จับคู่ทันทีเมื่อข้อมูลมาถึง (ถ้าปิด จะประมวลผลด้วยตัวทำงานตามกำหนด)
  • ลงทะเบียนเครื่องอัตโนมัติ — เปิดเพื่อให้เครื่องใหม่ที่ส่งรหัสถูกต้องถูกสร้างให้เอง (แนะเปิดเฉพาะเมื่อเชื่อถือเครือข่าย)
  • ช่วงผ่อนผันเช็คเอาท์ (นาที) — หากสแกนซ้ำเร็วเกินไปในเวลานี้ จะถือเป็นข้อมูลซ้ำ
มีตัวทำงานตามกำหนด (scheduled action) ทำงานทุก 15 นาที เป็นตาข่ายกันพลาด คอยประมวลผลบันทึกที่ยังค้างอยู่ให้เอง
เครื่องจะถูกปฏิเสธถ้าไม่ส่ง Communication Key ที่ตรงกัน หรือถ้าเป็นเครื่องที่ไม่ลงทะเบียนและไม่ได้เปิดโหมดลงทะเบียนอัตโนมัติ — ตรวจสอบให้ตั้งรหัสเหมือนกันทั้งสองฝ่าย

od19_meeting_room_booking จองห้องประชุม (Meeting Room Booking)

ระบบจองห้องประชุมที่ใช้งานง่าย: เลือกห้องกับช่วงเวลาแล้วบันทึก การจองยืนยันทันที มีการตรวจการทับซ้อนของเวลา ความจุ และขอบเขตการจองล่วงหน้าให้โดยอัตโนมัติ

เมนู

  • ปฏิทิน › Meeting Rooms › Bookings — หน้าจองห้อง (มุมมองปฏิทินเป็นค่าเริ่มต้น)
  • ปฏิทิน › Meeting Rooms › Room Catalog — ทะเบียนห้องประชุม (เฉพาะผู้จัดการ)

ขั้นตอนจองห้อง

  1. เปิดมุมมองปฏิทิน ที่เมนู Bookings จะเห็นตารางห้อง–ช่วงเวลาในมุมมองสัปดาห์
  2. เลือกช่วงเวลา คลิกช่วงเวลาที่ต้องการ แล้วระบุหัวข้อประชุม ห้อง ผู้จัด จำนวนผู้เข้าร่วม และเวลาเริ่ม–สิ้นสุด
  3. กรอกบรีฟการประชุม ระบุวาระ ผู้เข้าร่วม และอุปกรณ์ที่ต้องการ (ในแท็บ Meeting Brief)
  4. บันทึก การจองยืนยันทันที — ระบบตรวจการทับซ้อน/ความจุ/ขอบเขตให้ก่อนบันทึก

สถานะการจอง

จองแล้ว → กำลังใช้งาน → เสร็จสิ้น
ปุ่มทำอะไร

Finishเปลี่ยนเป็น “เสร็จสิ้น”

ทะเบียนห้องประชุม (Room Catalog)

  • ข้อมูลห้อง: ชื่อ รหัส อาคาร ชั้น ความจุ และอุปกรณ์ (โปรเจกเตอร์ / วิดีโอคอนเฟอเรนซ์ / ไวท์บอร์ด / จอใหญ่)
  • สถานะห้อง: ว่าง · ถูกจอง · กำลังใช้งาน
  • ปุ่ม “Bookings” ในฟอร์มห้อง เพื่อดูการจองทั้งหมดของห้องนั้น
  • มีข้อมูลห้องตัวอย่างตั้งต้นให้ 4 ห้อง (ห้องใหญ่/เล็ก/พิเศษ ชั้น 2 และห้องประชุมชั้น 4)
ระบบไม่อนุญาตให้จอง ทับซ้อน ในห้องเดียวกัน, ให้เวลา สิ้นสุดก่อนเริ่ม, จองล่วงหน้าเกิน 6 เดือน หรือระบุจำนวนผู้เข้าร่วม เกินความจุห้อง — จะขึ้นข้อความแจ้งเตือนทันที
ค่าเริ่มต้นของหน้าจอกรองเฉพาะ “การจองที่กำลังจะมาถึง (Upcoming)” เพื่อให้เห็นเฉพาะรายการที่ยังไม่ผ่านไป

od19_recognition ยกย่องเพื่อนร่วมงาน (Recognition / Kudos)

ระบบมอบคำชื่นชม (Kudos) ระหว่างพนักงาน พร้อมกำแพงคำชื่นชมบนพอร์ทัลพนักงาน และการฉลองวันเกิด/วันครบรอบการทำงานของเดือนนั้น เพื่อสร้างบรรยากาศที่ดีในองค์กร

เมนู

  • พนักงาน › Recognition › Kudos — ดู/กลั่นกรองคำชื่นชมทั้งหมด (เฉพาะผู้จัดการ)
  • พนักงาน › Recognition › Badges — จัดการป้าย (เฉพาะผู้จัดการ)
  • พอร์ทัลพนักงาน: /my/recognition — กำแพงคำชื่นชม + มอบ Kudos

ขั้นตอนมอบ Kudos (บนพอร์ทัล)

  1. เปิดกำแพงคำชื่นชม จากพอร์ทัลพนักงาน จะเห็น Team Wall และปุ่ม “ให้ Kudos / ดูทั้งหมด”
  2. เลือกผู้รับ เลือกเพื่อนร่วมงานจากรายการ และเลือก ป้าย (จะไม่ระบุก็ได้)
  3. เขียนข้อความขอบคุณ พิมพ์ข้อความ (ไม่เกิน 500 ตัวอักษร) แล้วกด ส่ง Kudos
  4. ปรากฏบนกำแพง คำชื่นชมจะแสดงบนฟีดล่าสุดทันที

ป้ายชื่นชมที่เตรียมไว้

ป้ายไอคอน
ขอบคุณ (Thank You)หัวใจ
ทำงานเป็นทีม (Great Teamwork)จับมือ
เกินความคาดหวัง (Above & Beyond)ดาว
สุขสันต์วันเกิด (Happy Birthday)เค้กวันเกิด
ครบรอบการทำงาน (Happy Anniversary)ถ้วยรางวัล

การฉลองในเดือนนั้น

หน้าพอร์ทัลจะแสดง วันเกิด และ วันครบรอบการทำงาน ของพนักงานในเดือนปัจจุบัน พร้อมปุ่ม “อวยพร” ที่เปิดฟอร์มมอบ Kudos ล่วงหน้าให้ผู้รับและป้ายที่เหมาะสม

สิทธิ์

  • ผู้ใช้ทั่วไป: มอบ Kudos ในนามตัวเอง เห็นคำชื่นชมสาธารณะ หรือของตัวเอง
  • ผู้เขียนเท่านั้น: แก้ไข/ลบคำชื่นชมของตัวเองได้
  • ผู้จัดการ (Recognition Manager): กลั่นกรองคำชื่นชมทั้งหมด และดูแลคลังป้าย
มอบ Kudos ให้ตัวเองไม่ได้ และข้อความต้องไม่เกิน 500 ตัวอักษร — พนักงานทั่วไปมอบได้ในนามตัวเองเท่านั้น
วันเกิดจะแสดงบนกำแพงเฉพาะกรณีที่พนักงานตั้งค่าเปิดเผยวันเกิด (ไม่ตั้งเป็น “ซ่อน”) เพื่อรักษาความเป็นส่วนตัว
