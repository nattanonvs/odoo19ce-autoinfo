od19_website ระบบรับสมัครงาน (Careers & Recruitment)

โมดูลเพิ่มแบบจำลองงานรับสมัคร od19.job.opening (ตำแหน่งงานว่าง) และ od19.job.application (ใบสมัครผู้สมัคร) พร้อมหน้าเว็บสาธารณะสำหรับประกาศตำแหน่งและยื่นใบสมัคร

เมนูหลังบ้าน

อยู่ในแอป Website (ไม่แยกแอปใหม่):

  • Website › Configuration › Recruitment › Job Openings — จัดการตำแหน่งงาน
  • Website › Configuration › Recruitment › Applications — ดูใบสมัครทั้งหมด
  • Website › Configuration › Recruitment › Configuration › Published Jobs — เฉพาะตำแหน่งที่ยังเปิดรับ (กลุ่มผู้ดูแลระบบ)

หน้าสาธารณะ

เส้นทางหน้าที่
/careers , /careers/page/<n>รายการตำแหน่งงานที่เปิดรับ + การ์ดแยกตามกลุ่มงาน
/careers/<job_id>รายละเอียดตำแหน่ง + ตำแหน่งงานที่เกี่ยวข้อง
/careers/<job_id>/applyแบบฟอร์มสมัครสำหรับตำแหน่งที่ระบุ
/careers/applyใบสมัครแบบทั่วไป/สมัครเอง (ยังไม่ระบุตำแหน่ง)
/careers/thank-youหน้ายืนยันหลังส่งใบสมัครสำเร็จ

ค่าที่ผู้สมัครกรอกจะถูกตรวจสอบก่อนบันทึกเสมอ:

  • ต้องมีชื่อ-นามสกุล, อีเมลที่ถูกต้อง, เบอร์โทร และยอมรับประกาศความเป็นส่วนตัว (PDPA)
  • แนบ เรซูเม/ซีวี 1 ไฟล์ (ไม่เกิน 10 MB) และไฟล์สนับสนุนได้สูงสุด 5 ไฟล์ (ไฟล์ละไม่เกิน 10 MB)
  • นามสกุลไฟล์ที่อนุญาต: pdf, doc(x), xls(x), ppt(x), jpg/jpeg/png/gif, zip, rar, txt

ใบสมัครจะได้ เลขที่อ้างอิง อัตโนมัติจากลำดับ od19.job.application รูปแบบ APP/ปี/เลขรัน 4 หลัก และระบบจะส่งอีเมลแจ้งทีมสรรหาที่ hr@auto-info.co.th พร้อมอีเมลตอบรับผู้สมัครอัตโนมัติ (แจ้งว่าจะติดต่อกลับภายใน 5 วันทำการ)

ขั้นตอนการลงประกาศและติดตามใบสมัคร

  1. สร้างตำแหน่งงาน — ที่ Website › Configuration › Recruitment › Job Openings กด New กรอกชื่อตำแหน่ง กลุ่มงาน ประเภทการจ้าง ระดับประสบการณ์ สถานที่ และช่วงเงินเดือน
  2. กรอกเนื้อหา — ในแท็บย่อย กรอกรายละเอียดงาน, หน้าที่ความรับผิดชอบ, คุณสมบัติ และสวัสดิการ
  3. เผยแพร่ — เปิด Published on Website และเว้นวันปิดรับ (ช่อง Closing Date) ให้ว่างหากไม่จำกัดเวลา ตำแหน่งจะปรากฏบน /careers ทันที
  4. รับใบสมัคร — ที่ Recruitment › Applications ใบสมัครใหม่จะอยู่ในสถานะ New
  5. เดินสถานะ — กดปุ่ม Shortlist → Schedule Interview → Send Offer → Mark as Hired (หรือ Not Selected) จนครบกระบวนการสรรหา
จำนวนใบสมัครและตำแหน่งที่ยังเปิดรับเป็นฟิลด์คำนวณ — ปุ่ม “Applications” บนฟอร์มตำแหน่งงานจะเปิดดูใบสมัครเฉพาะตำแหน่งนั้นให้ทันที

โมดูลมาพร้อมข้อมูลตัวอย่างตำแหน่งงาน (ไฟล์ data/job_opening_data.xml) เช่น Senior Industrial Automation Engineer, SCADA / HMI Software Engineer, Building Automation Engineer (GMP/CSV), Terminal Automation Service Engineer และตำแหน่งอื่น ๆ เพื่อให้หน้า Careers มีเนื้อหาเริ่มต้น

od19_website พอร์ทัลพนักงาน (/employee-portal)

พอร์ทัลพนักงานคือหน้าแรกแบบส่วนตัวสำหรับพนักงานที่ล็อกอิน (ต้องมีสิทธิ์ผู้ใช้ภายใน) เปิดที่ /employee-portal โดยรวบรวมงานประจำวันไว้ในหน้าเดียว

ส่วนประกอบในหน้า

👋 Hero ทักทาย

คำทักทายตามช่วงเวลา (เช้า/บ่าย/เย็น) · รูปหรือชื่อย่อ · ตำแหน่งและแผนก · วันที่ปัจจุบัน · ปุ่มกลับหน้าหลังบ้าน

📊 My Day Strip

4 การ์ด: ลงเวลาวันนี้ · รออนุมัติ · นัดถัดไป · วันลาคงเหลือ (โหลดแบบ lazy)

🗓️ ตารางของฉัน

รวมนัดจองห้องประชุมและวันลาที่อนุมัติแล้วในสัปดาห์ข้างหน้า พร้อมทางลัด “ใช้บ่อย”

📣 ประกาศล่าสุด

ดึงประกาศที่เผยแพร่และยังไม่หมดอายุสูงสุด 5 รายการ พร้อมป้ายระดับความสำคัญ

🏢 จองห้องประชุม

การ์ดห้องพร้อมสถานะสด (ว่าง / ถูกจองแล้ว / กำลังใช้งาน) และป๊อปอัปดูตารางการใช้ห้อง

🚀 เมนูด่วน

ปุ่มทางลัดจัดกลุ่มตามงาน/HR/ความรู้ พร้อม Quick Actions แจ้งปัญหา ขอยืมอุปกรณ์ จองห้อง

การจองห้องประชุมจากพอร์ทัล

  1. เลือกห้อง — คลิกการ์ดห้องเพื่อดูสถานะ หรือเลือกจากแบบฟอร์มด้านล่าง
  2. ดูตารางการใช้ห้อง — หน้าต่างแสดงตารางย้อนหลังและล่วงหน้า 6 เดือน (ดึงจาก /employee-portal/room-schedule)
  3. กรอกหัวข้อ วันที่ เวลา และจำนวนผู้เข้าร่วม — แล้วกด จองทันที
  4. ยืนยัน — การจองถูกสร้างทันที (ไม่มีขั้นอนุมัติ) และแสดงเลขที่การจอง พร้อมรายการ “การจองของฉัน”
การจองที่ผิดกฎ (เช่น เวลาทับซ้อน หรือห้องถูกใช้อยู่) ระบบจะแจ้งข้อผิดพลาดกลับมาที่หน้าเดิมทันทีโดยไม่สร้างรายการ

การนำทางเข้า–ออกพอร์ทัล

  • เมื่อพนักงาน (ที่มีข้อมูลพนักงานและไม่ใช่ผู้ดูแลระบบ) ล็อกอิน จะถูกพาไปที่ /employee-portal โดยอัตโนมัติ เว้นแต่ตั้งใจเปิดหน้าอื่น
  • หลังบ้านมีเมนูลัด เมนูลัดพนักงาน (ไอคอนสายฟ้า) รวมทางลัดพอร์ทัล/จองห้อง/ประกาศ/คู่มือ
  • กด Alt + P เพื่อเปิดพอร์ทัลพนักงานได้จากทุกหน้าในหลังบ้าน

หน้าพอร์ทัลยิงข้อมูลแบบ lazy ผ่านปลายทาง JSON เพื่อให้หน้าโหลดเร็ว: /employee-portal/me-summary (สรุป “วันของฉัน”) และ /employee-portal/room-schedule (ตารางห้อง) โดยมีแคชสั้น 60 วินาทีต่อผู้ใช้

od19_website ศูนย์อนุมัติพนักงาน (/my/approvals)

หน้าศูนย์อนุมัติเป็นแบบ ดูเท่านั้น (view-only) สำหรับให้พนักงานเห็นภาพรวมการอนุมัติของตัวเอง โดยรวบรวมรายการจากทุก “แหล่งอนุมัติ” ที่เปิดใช้งาน (โมดูล od19_approval_center) เข้าหน้าเดียว ส่วนการกดอนุมัติจริงทำในหน้าจอหลังบ้านของเอกสารนั้น ๆ

Rejectedคำขอของฉันที่ถูกปฏิเสธ

ด้านบนหน้ามีการ์ดสรุป 3 ตัวเลข (แสดงเมื่อมีรายการคงค้าง):

  • รอฉันอนุมัติ (คงค้าง) — จำนวนรายการที่รอ
  • อายุมากที่สุด (วัน) — อายุของรายการที่นานที่สุด
  • เกินกำหนด (Over SLA) — จำนวนรายการที่เกินเวลาที่กำหนด (แสดงเป็นสีแดง)
การ์ด “รออนุมัติ” บนพอร์ทัลพนักงานดึงตัวเลขผ่านปลายทาง /my/approvals/summary (JSON + แคช 60 วินาที) จึงไม่ต้องสแกนทุกแหล่งอนุมัติใหม่ทุกครั้งที่เปิดหน้า

โมดูลเพิ่มงาน SEO ที่เกินกว่าที่ Odoo ทำให้แล้ว พร้อมเปิดใช้คุกกี้และการปฏิบัติตาม PDPA:

🧩 Structured Data

ฝัง application/ld+json แบบ schema.org ชนิด Organization + WebSite ทุกหน้า (พร้อมโลโก้ ที่อยู่ เบอร์โทร โซเชียล และช่องค้นหา)

🏷️ เมตาเสริม

เพิ่ม og:locale และคำอธิบายสำรอง (fallback description) สำหรับหน้าที่ไม่มีคำอธิบายของตัวเอง

🤖 robots.txt

ตั้งค่าเริ่มต้นให้กันพื้นที่ส่วนตัวออกจากดัชนี: /web/, /my/, /employee-portal

📈 Google Analytics

ค่าจากช่อง Google Analytics ID ของบริษัทถูกส่งต่อไปยังเว็บไซต์ โดยโหลดสคริปต์แบบเคารพการยินยอมคุกกี้

ด้าน PDPA:

  • เปิดใช้ แถบความยินยอมคุกกี้ (cookies bar) ทำให้การยินยอมเป็นแบบ opt-in และแกน Odoo สร้างหน้า /cookie-policy ให้อัตโนมัติ
  • หน้า /privacy และ /terms-of-use ถูกเผยแพร่และเปิดให้จัดทำดัชนี
  • หน้า Terms ใช้ URL /terms-of-use (ไม่ใช้ /terms เพราะ Odoo ใช้เส้นทางนั้นสำหรับเงื่อนไขใบวางบิล) ระบบจะปรับ URL เก่าให้อัตโนมัติเมื่ออัปเดต
  • แบบฟอร์มสมัครงานและแบบฟอร์มติดต่อมี checkbox ยอมรับประกาศความเป็นส่วนตัวก่อนส่ง
ทุกงานตั้งค่าข้างต้นเป็นแบบ idempotent (ทำซ้ำได้ไม่พัง) จึงรันใหม่อัตโนมัติทุกครั้งที่อัปเดตโมดูล และจะไม่ทับค่าที่ผู้ดูแลแก้ไขไว้เอง

od19_website การตั้งค่าเว็บไซต์และข้อมูลแบรนด์

ข้อมูลแบรนด์ของเว็บไซต์เก็บอยู่ที่ ข้อมูลบริษัท จึงแก้จากหลังบ้านได้โดยไม่ต้องแตะโค้ด ไปที่ การตั้งค่า › บริษัท › เลือกบริษัท › แท็บ “Website”

ฟังก์ชันทำงานอะไร
website.od19_setup_websiteเปลี่ยนชื่อเว็บไซต์เริ่มต้นเป็น “Auto-Info” (แทน “My Website”)
website.menu.od19_configure_menusจัดวางเมนูบนสุดและลบเมนูซ้ำซ้อนของ Odoo
blog.blog.od19_setup_blogตั้งบล็อก “News & Events” แปลหมวดหมู่/แท็ก และสร้างโพสต์ตัวอย่างเมื่อบล็อกยังว่าง
website.od19_setup_seoส่งค่า Google Analytics ID ไปยังเว็บไซต์ และใส่ robots.txt เริ่มต้นเมื่อยังว่าง
website.od19_setup_pdpaเปิดแถบคุกกี้ และเผยแพร่/จัดทำดัชนีหน้าด้านกฎหมาย

แคตตาล็อกสินค้า หมวดคุณภาพ ผลงานโครงการ และประเภทคำขอ (RFQ) ถูกเก็บเป็นชุดข้อมูลกลางในโค้ด (od19_website/models/website.py) เพื่อให้หน้าเว็บต่าง ๆ และแบบฟอร์มอ้างอิงข้อมูลชุดเดียวกันได้ตลอด

บล็อกของเว็บไซต์เป็น “ฮับ” เดียวที่ /blog โดยแยกเนื้อหาด้วยแท็ก ข่าวสาร, กิจกรรม และ บทความ ภายใต้หมวดหมู่ “หมวดหมู่” แทนการแยกเป็นหลายบล็อก
