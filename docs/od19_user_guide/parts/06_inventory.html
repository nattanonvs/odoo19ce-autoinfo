🏭 ส่วนที่ 7 · สินค้าคงคลังและคลังสินค้า

อธิบายงานคลังสินค้าครบวงจรของ AutoInfo — ตั้งแต่การรับเข้า-จ่ายออก-โอนย้าย การบันทึกข้อมูลประกอบใบรับ-จ่าย การประเมิน มูลค่าสินค้าแบบ FIFO การ ปรับมูลค่าสินค้าคงคลัง การ นับสต๊อกเพื่อตรวจสอบ (Audit Count) การควบคุมการดำเนินงานคลัง (ลงวันย้อนหลัง, ติดตามตามล็อต), การ เบิกสินค้า (Goods Issue), การ คืนสินค้า/RMA, ใบปะหน้าส่งของ และชุดแบบพิมพ์รายงาน Jasper (J-Report OD15) — โดยอ้างอิงจากโมดูล od19_stock_*, od19_inventory_*, od19_goods_issue, od19_product_return และ od19_delivery_label ที่ติดตั้งในระบบจริง

  6. รายงานคลังสินค้าและแดชบอร์ดโลจิสติกส์

  8. คืนสินค้า / RMA
  9. ใบปะหน้าสินค้ารอส่ง (Delivery Label)
  10. แบบพิมพ์และรายงาน Jasper (J-Report OD15)

od19_stock_picking_features ส่วนขยายใบรับ-จ่ายสินค้า

โมดูลนี้เพิ่มข้อมูลประกอบในใบรับเข้า/จ่ายออกสินค้า (Stock Picking) ได้แก่ พนักงานขาย (Saleperson) หัวหน้าแผนก และตาราง บรรทัดเพิ่มเติม (Additional Lines) สำหรับบันทึกรายการที่ไม่ใช่สินค้าในระบบ (เช่น ค่าบริการ ค่าแรง ค่าขนส่ง) เพื่อให้เอกสารส่งของ/รับของแสดงผู้รับผิดชอบและรายการครบถ้วน

เมนูที่เกี่ยวข้อง

  • คลังสินค้า › ปฏิบัติการ › การรับสินค้า (Receipts)
  • คลังสินค้า › ปฏิบัติการ › การส่งสินค้า (Deliveries)
  • คลังสินค้า › ปฏิบัติการ › การโอนภายใน (Internal Transfers)
  • โมดูลนี้ ไม่มีเมนูใหม่ — เพิ่มฟิลด์/แท็บลงในหน้าเอกสาร picking เดิม

ขั้นตอนการใช้งาน

  1. เปิดใบรับ/จ่ายสินค้า — ดูแถวฟิลด์ พนักงานขาย และ หัวหน้าแผนก ที่อยู่ถัดจากใบสั่งขาย (Sales Order)
  2. ให้ระบบเติมข้อมูลอัตโนมัติ — เมื่อผูกกับใบสั่งขาย ระบบจะดึงพนักงานขายจากใบสั่งขาย และหาหัวหน้าแผนกจากแผนกของพนักงานคนนั้นให้อัตโนมัติ
  3. กรณีไม่มีใบสั่งขายตรง — ระบบจะเทียบเอกสารต้นทาง (Origin) กับเลขที่ใบสั่งขายเพื่อค้นหาข้อมูลให้
  4. เพิ่มบรรทัดเพิ่มเติม — เปิดแท็บ “บรรทัดเพิ่มเติม / Additional Lines” กด “เพิ่มบรรทัด” แล้วกรอกรายละเอียด จำนวน และหน่วย
  5. บันทึกเอกสาร — ตรวจสอบความถูกต้องแล้วบันทึก

od19_stock_fifo ประเมินมูลค่าสินค้าแบบ FIFO

ประเมินมูลค่าสินค้าคงเหลือตามวิธี FIFO (เข้าก่อน-ออกก่อน) โดยคำนวณจากการเคลื่อนไหวรับ-จ่ายจริง พร้อมวิซาร์ดประเมินย้อนหลัง ณ วันที่ (As-Of), การปรับมูลค่ายกมา (BF Revaluation) ไปยังบัญชี และการส่งรายงาน มูลค่าสต๊อกทางอีเมลอัตโนมัติทุกเดือนเป็นไฟล์ Excel (XLSX)

เมนูที่เกี่ยวข้อง

  • คลังสินค้า › FIFO Valuation / มูลค่า FIFO › บันทึกมูลค่า FIFO (FIFO Valuation Records)
  • คลังสินค้า › FIFO Valuation / มูลค่า FIFO › ประเมิน FIFO ณ วันที่ (FIFO As-Of)
  • คลังสินค้า › FIFO Valuation / มูลค่า FIFO › ปรับมูลค่ายกมา (BF Revaluation)
  • การตั้งค่า › บริษัท — ตั้งค่าบัญชีปรับมูลค่าสต๊อก (Stock Revaluation Account)

ขั้นตอนการใช้งาน

  1. ประเมิน ณ วันที่ — เปิดวิซาร์ด FIFO As-Of เลือกสินค้าและวันที่ แล้วกดประเมิน ระบบจะไล่การเคลื่อนไหว FIFO จนถึงวันนั้น
  2. ดูผลลัพธ์ — ผลลัพธ์แสดง จำนวนคงเหลือ (Quantity), ต้นทุนต่อหน่วย (Unit Cost) และมูลค่ารวม (Total Value) พร้อมยอดรวมท้ายตาราง
  3. ดูบันทึกมูลค่า — เมนู บันทึกมูลค่า FIFO กรอง “เดือนนี้” หรือจัดกลุ่มตามสินค้า / วันที่
  4. ปรับมูลค่ายกมา — เปิดวิซาร์ด BF Revaluation เพื่อสร้างรายการบัญชี (Journal Entry) และปรับราคามาตรฐานของสินค้า
  5. รับรายงานรายเดือน — ระบบตั้งเวลาอัตโนมัติ (cron) ทุกวันที่ 1 ของเดือน เวลา 08:00 ส่งอีเมลพร้อมไฟล์แนบ XLSX

สถานะ / วัฏจักรการคำนวณ

รับสินค้าเข้า (In) → เข้าคิวตามลำดับเวลา → ตัดจ่ายตามลำดับ FIFO (Out) → คงเหลือ + มูลค่าต่อหน่วย → บันทึก / รายงาน

วันที่ (Date)วันที่ของบันทึกมูลค่า

สิทธิ์การเข้าถึง

  • stock.group_stock_user — อ่าน/สร้าง/แก้ บันทึกมูลค่า (ลบไม่ได้); ใช้วิซาร์ด As-Of และ BF Revaluation ได้

Odoo 19 ไม่มีโมเดล stock.valuation.layer แล้ว — การประเมินมูลค่าใช้ข้อมูลการเคลื่อนไหวสต๊อก (stock.move) เป็นฐาน ตัวเลข FIFO จึงคำนวณจากประวัติการรับ-จ่ายจริง

od19_stock_valuation_adjustment ปรับมูลค่าสินค้าคงคลัง

บันทึกและอนุมัติการ ปรับมูลค่าสินค้าคงคลัง (เปลี่ยนราคา / ตั้งราคาสูงขึ้น / ตั้งราคาลดลง) พร้อมการอนุมัติโดยผู้จัดการพัสดุ การบันทึก audit trail ทุกครั้ง และการสร้างรายการบัญชีปรับมูลค่าอัตโนมัติ สำหรับสินค้าที่ใช้วิธีประเมินมูลค่าแบบทันกาล (real-time)

เมนูที่เกี่ยวข้อง

  • คลังสินค้า › การดำเนินงาน (Operations) › Valuation Adjustments
  • การตั้งค่า › บริษัท — ตั้งค่าบัญชี “Stock Valuation Adjustment Account”

ขั้นตอนการใช้งาน

  1. สร้างรายการปรับมูลค่า — เลือกประเภทการปรับ (เปลี่ยนราคา / ตั้งราคาสูงขึ้น / ตั้งราคาลดลง) สินค้า จำนวน และวันที่
  2. กรอกมูลค่า — ระบบแสดงมูลค่าปัจจุบัน (Current Value ดึงจากราคามาตรฐานต่อหน่วย) ให้กรอกมูลค่าใหม่ (New Value) แล้วระบบคำนวณส่วนต่างรวมให้อัตโนมัติ
  3. ระบุเหตุผล — ฟิลด์เหตุผล (Reason) เป็นข้อมูลบังคับ
  4. กด “ยืนยัน” (Confirm) — ต้องกรอกมูลค่าใหม่ มิฉะนั้นระบบไม่ให้ผ่าน
  5. กด “อนุมัติ” (Approve) — ต้องเป็นผู้จัดการพัสดุ ระบบจะปรับราคามาตรฐาน (กรณีเปลี่ยนราคา) บันทึก audit trail และสร้างรายการบัญชี
  6. กด “ยกเลิก” (Cancel) — กรณีอนุมัติแล้ว ระบบจะกลับรายการบัญชีและคืนราคาเดิม

การอนุมัติสร้าง รายการบัญชีอัตโนมัติ (กรณีหมวดสินค้าตั้งเป็น real-time) — ต้องแน่ใจว่าบัญชีปรับมูลค่าตั้งค่าถูกต้องก่อนอนุมัติ
ทุกครั้งที่อนุมัติ ระบบบันทึก audit trail (ค่าก่อน–หลัง พร้อมผู้กระทำ) เพื่อตรวจสอบย้อนหลังได้

od19_inventory_audit_count นับสต๊อกเพื่อตรวจสอบ (Audit Count)

จัดการ รอบนับสินค้าคงคลัง (Cycle/Physical Count) แบบมีขั้นตอนอนุมัติ ตั้งแต่กำหนดรอบนับ บันทึกจำนวนนับจริง เทียบกับยอดในระบบ หาความต่าง (Variance) และให้ผู้จัดการอนุมัติปรับยอดเข้าสู่ระบบ

เมนูที่เกี่ยวข้อง

  • คลังสินค้า › การดำเนินงาน (Operations) › Audit Counts

ขั้นตอนการใช้งาน

  1. สร้างรอบนับ (Scheduled) — ระบุชื่อและที่ตั้ง (Location) แล้วเพิ่มบรรทัดนับ (เลือก quant ที่อยู่ในที่ตั้งเดียวกัน)
  2. บันทึกจำนวนนับจริง — กรอกจำนวนนับจริง (Counted) ระบบคำนวณความต่าง (Variance = นับ − ระบบ) และนับจำนวนรายการที่มีความต่าง
  3. ทำเครื่องหมายว่านับแล้ว (Mark as Counted) — ต้องมีอย่างน้อย 1 บรรทัด
  4. ส่งขออนุมัติ (Submit for Approval) — สถานะเป็นรออนุมัติ
  5. อนุมัติ/ปรับยอด (Create Adjustment) — ผู้จัดการเท่านั้น ระบบปรับยอด quant ตามจำนวนนับจริง (ผ่านกลไกปรับสต๊อกมาตรฐานของ Odoo)
  6. ตรวจทาน (Mark as Reviewed) — ปิดรอบนับ

สถานะเอกสาร

กำหนดรอบ (Scheduled) → นับแล้ว (Counted) → รออนุมัติ (Pending Approval) → ปรับยอดแล้ว (Adjusted) → ตรวจทานแล้ว (Reviewed)

นอกจากนี้ยังมีสถานะ ยกเลิก (Cancelled) ซึ่งรีเซ็ตกลับเป็น Scheduled ได้

ฟิลด์และปุ่มสำคัญ

ฟิลด์ / ปุ่มความหมาย
ที่ตั้ง (Location)ที่ตั้งที่ทำการนับ
จำนวนรายการต่าง (Variances)นับเฉพาะบรรทัดที่มีผลต่าง
ผู้อนุมัติ (Approved By)ผู้กดอนุมัติปรับยอด
บรรทัดนับQuant, สินค้า (อ่านจาก quant), จำนวนตามระบบ (System Qty), จำนวนนับจริง (Counted Qty), ผลต่าง (Variance Qty)
Mark as Counted / Submit for Approvalบันทึกว่านับแล้ว / ส่งขออนุมัติ
Create Adjustment / Mark as Reviewedอนุมัติปรับยอด / ปิดรอบตรวจทาน
Cancel / Reset to Scheduledยกเลิกรอบนับ / รีเซ็ตกลับเป็นกำหนดรอบ

สิทธิ์การเข้าถึง

  • stock.group_stock_user — อ่าน/สร้าง/แก้ รอบนับและบรรทัดนับ (ลบไม่ได้)
  • stock.group_stock_manager — สิทธิ์เต็ม (ลบได้) และเป็นผู้กดอนุมัติปรับยอด
  • ขั้นตอน Create Adjustment จำกัดเฉพาะ stock.group_stock_manager
บรรทัดนับต้องอ้าง quant ใน ที่ตั้งเดียวกับรอบนับ และ นับ quant เดียวกันซ้ำในรอบเดียวไม่ได้ (ระบบตรวจสอบ)
ดูตัวนับ Variances ก่อนส่งอนุมัติ เพื่อยืนยันว่ามีเฉพาะรายการต่างที่ต้องการปรับจริง

od19_inventory_execution_control ควบคุมการดำเนินงานคลัง

เพิ่มการจัดชั้นประเภทงานคลังอัตโนมัติ (รับเข้า/จ่ายออก/โอน/คืน), สถานะการดำเนินงาน, การ ลงวันที่ย้อนหลัง (Backdate) สำหรับผู้จัดการ, การบังคับ ติดตามล็อต/ซีเรียล สำหรับสินค้าที่ใช้ FIFO และรายงาน มูลค่าสินค้าตามล็อต

เมนูที่เกี่ยวข้อง

  • คลังสินค้า › การดำเนินงาน (Operations) › Valuation by Lot (มูลค่าตามล็อต)
  • ฟิลด์เพิ่มในหน้าใบรับ/จ่ายสินค้า และหน้าสินค้า (Product)
  • เอกสารอ้างอิง (Reference Document) และวันที่ย้อนหลัง ในรายการเคลื่อนไหว (Stock Move)

ขั้นตอนการใช้งาน

  1. ดูประเภทงานคลัง (Flow Class) — ระบบจัดหมวดใบ picking ให้อัตโนมัติ: รับเข้า (Receipt) / จ่ายออก (Delivery) / โอน (Transfer) / คืน (Return)
  2. ดูสถานะดำเนินงาน — แสดงอัตโนมัติ: รอ (Waiting) / พร้อม (Ready) / เสร็จ (Done) / ข้อยกเว้น (Exception)
  3. ลงวันย้อนหลัง (เฉพาะผู้จัดการ) — กรอกวันที่ย้อนหลังในใบ picking ระบบจะลงวันให้รายการเคลื่อนไหว/มูลค่า/บัญชีตามวันนั้น
  4. ระบุเอกสารอ้างอิง — กรอกเอกสารอ้างอิงในรายการเคลื่อนไหว (Stock Move)
  5. ตั้งค่าสินค้า — สินค้าที่ใช้ FIFO ต้องเปิดติดตามล็อต/ซีเรียล (ระบบบังคับและแสดงสาเหตุ)
  6. ดูรายงานมูลค่าตามล็อต — เปิดเมนู Valuation by Lot

สถานะเอกสาร

สถานะดำเนินงาน (Execution State)ความหมาย
รอ (Waiting)ยังไม่พร้อมหยิบ
พร้อม (Ready)จองสินค้าได้แล้ว
เสร็จ (Done)ดำเนินการเสร็จสิ้น
ข้อยกเว้น (Exception)ใบถูกยกเลิก

ประเภทงานคลัง (Flow Class) แสดงเป็นป้าย: Receipt Delivery Transfer Return

ฟิลด์และปุ่มสำคัญ

ฟิลด์ / รายงานความหมาย
ประเภทงานคลัง (Flow Class)คำนวณอัตโนมัติจากชนิดใบ picking
สถานะดำเนินงาน (Execution State)คำนวณอัตโนมัติจากสถานะเอกสาร
วันที่ย้อนหลัง (Backdate)กำหนดได้เฉพาะผู้จัดการ
เอกสารอ้างอิง (Reference Document)อ้างอิงเอกสารในรายการเคลื่อนไหว
ต้องติดตาม (Tracking Required) + สาเหตุแสดงเมื่อสินค้าใช้ FIFO ต้องติดตามล็อต/ซีเรียล
Valuation by Lotรายงานมูลค่าสินค้าตามล็อต (อ่านอย่างเดียว)

สิทธิ์การเข้าถึง

  • stock.group_stock_user — อ่านรายงาน Valuation by Lot (read-only)
  • stock.group_stock_manager — อ่านรายงาน และกำหนดวันที่ย้อนหลังได้
  • การลงวันที่ย้อนหลังจำกัดเฉพาะ stock.group_stock_manager
การ ลงวันย้อนหลัง กระทบวันที่ลงรายการบัญชี/มูลค่าสต๊อก — ต้องระวังช่วงปิดบัญชี ระบบไม่อนุญาตให้ลงวันอนาคต
สินค้าที่ใช้ต้นทุนแบบ FIFO ต้องตั้ง “ติดตามล็อต/ซีเรียล” มิฉะนั้นระบบจะไม่ยอมบันทึกสินค้า
รายงาน Valuation by Lot เป็นข้อมูลอ่านอย่างเดียว (read-only) ไม่มีปุ่มแก้ไข

od19_inventory_reporting รายงานคลังสินค้าและแดชบอร์ดโลจิสติกส์

ให้ รายงานวิเคราะห์คลังสินค้า ได้แก่ ความแม่นยำของสต๊อก (Inventory Accuracy) และงานค้างเคลื่อนไหว (Movement Backlog) พร้อมแดชบอร์ด Logistics Board รวมภาพรวมงานคลัง

เมนูที่เกี่ยวข้อง

  • คลังสินค้า › Reporting › Inventory Accuracy
  • คลังสินค้า › Reporting › Movement Backlog
  • คลังสินค้า › Logistics Board (แดชบอร์ด — อยู่บนสุดของเมนู)

ขั้นตอนการใช้งาน

  1. เปิดรายงาน Inventory Accuracy — ดูความแม่นยำของยอดสต๊อก (ผลต่างระหว่างยอดในระบบกับที่นับได้จริง)
  2. เปิดรายงาน Movement Backlog — ดูงานเคลื่อนไหวที่ค้างสะสม
  3. เปิดแดชบอร์ด Logistics Board — รวมตัวชี้วัดงานคลังไว้ในหน้าเดียว

สถานะ / การแสดงผล

รายการลักษณะข้อมูล
Inventory Accuracyอ่านอย่างเดียว — มุมมอง SQL สะท้อนข้อมูลจริง
Movement Backlogอ่านอย่างเดียว — มุมมอง SQL สะท้อนข้อมูลจริง
Logistics Boardแดชบอร์ดภาพรวมงานคลัง

ฟิลด์ / ตัวชี้วัดสำคัญ

ตัวชี้วัดความหมาย
Inventory Accuracyค่าความแม่นยำของยอดสต๊อก
Movement Backlogรายการเคลื่อนไหวที่ค้าง
Logistics Boardแดชบอร์ดภาพรวมงานคลัง

สิทธิ์การเข้าถึง

  • เมนูรายงาน (Inventory Accuracy / Movement Backlog) จำกัดเฉพาะ stock.group_stock_manager
  • ตัวโมเดลรายงานอ่านได้โดย stock.group_stock_user และ stock.group_stock_manager
เมนูรายงานทั้งสองซ่อนจากผู้ใช้ทั่วไป — จะแสดงเฉพาะผู้จัดการคลังเท่านั้น
ทั้งสองรายงานเป็น มุมมอง SQL (อ่านอย่างเดียว) ข้อมูลสะท้อนผลทันทีตามข้อมูลจริง ณ ขณะเปิดดู — ส่งออกได้

od19_goods_issue ใบเบิกสินค้า (Goods Issue)

จัดการคำขอเบิกสินค้าจากคลัง ต่อยอดจากโมดูล OCA Stock Request เพิ่ม ประเภทการเบิก แผนก/พนักงานผู้ขอ งาน/โครงการ และ เหตุผลการเบิก พร้อมออกเลขที่เอกสารแยกตามแผนก (GI/<รหัสแผนก>/) และใบพิมพ์ “ใบเบิกสินค้า” และ “ใบหยิบสินค้า”

เมนูที่เกี่ยวข้อง

  • ใบขอเบิก (Stock Request) › Operations › ใบเบิกสินค้า / Goods Issue
  • ใบขอเบิก (Stock Request) › Master Data › ประเภทการเบิก / Issue Types

ขั้นตอนการใช้งาน

  1. สร้างใบเบิกสินค้า — เลือกแผนกผู้ขอ (ระบบเติมให้อัตโนมัติจากแผนกของพนักงานที่ล็อกอิน) และผู้ขอเบิก (พนักงาน)
  2. กำหนดงาน/โครงการ และประเภทการเบิก — พร้อมระบุเหตุผลการเบิก
  3. เพิ่มรายการสินค้า — ระบุสินค้าและจำนวนที่ต้องการเบิก
  4. ยืนยัน/อนุมัติ/ดำเนินการ — ตามขั้นตอนสถานะของใบขอเบิก (ร่าง → เปิด → เสร็จ → ยกเลิก)
  5. พิมพ์เอกสาร — พิมพ์ “ใบเบิกสินค้า / Goods Issue” จากใบขอเบิก หรือ “ใบหยิบสินค้า / Pick List” จากใบ picking

สถานะเอกสาร

ร่าง (Draft) → เปิด (Open) → เสร็จ (Done)

และสถานะ ยกเลิก (Cancel) — สถานะทั้งหมดอิงจากกลไกของโมดูล Stock Request

ฟิลด์และปุ่มสำคัญ

ฟิลด์ / ปุ่มความหมาย
ประเภทการเบิก (Issue Type)หมวดหมู่ของการเบิกสินค้า
แผนกที่ขอเบิก (Requesting Department)หน่วยงานผู้ขอ เติมอัตโนมัติจากพนักงาน
ผู้ขอเบิก (Employee)พนักงานผู้ยื่นคำขอ
งาน/โครงการ (Job)โครงการที่ผูกกับการเบิก
เหตุผลการเบิก (Issue Reason)เหตุผลประกอบการเบิก
เลขที่เอกสารรูปแบบ GI/<รหัสแผนก>/00001 แยกต่อแผนก — ไม่มีแผนกใช้ GI/GEN/
บนใบ pickingเหตุผลการเบิก (Goods Issue Reason), แผนกผู้เบิก (Goods Issue Department)
ใบเบิกสินค้า / ใบหยิบสินค้าปุ่มพิมพ์เอกสารทั้งสองแบบ

สิทธิ์การเข้าถึง

  • stock_request.group_stock_request_user — ใช้เมนูใบเบิกสินค้า
  • stock_request.group_stock_request_manager — จัดการประเภทการเบิก
  • ประเภทการเบิก: base.group_user อ่านได้ / stock.group_stock_manager จัดการได้
  • ใบพิมพ์จำกัดกลุ่มผู้ใช้ใบขอเบิก
เลขที่เอกสารแยกตามแผนก — ระบบออกรหัสจากรหัสย่อแผนก (3 ตัวอักษรแรก) อัตโนมัติ; แผนกที่ไม่มีรหัสใช้คำว่า GEN
ระบุ งาน/โครงการ เพื่อเชื่อมต้นทุนการเบิกเข้ากับโครงการ และดูต้นทุนตามโครงการได้ง่ายขึ้น

➡️ ส่งต่อ: เบิกวัสดุให้โครงการ

ใบเบิกสินค้า (ที่นี่)→ ส่วนที่ 10 · โครงการ (ต้นทุนวัสดุ)

วัสดุที่เบิกออกจากคลังบันทึกเป็นต้นทุนวัสดุของโครงการ — เลือกงาน/โครงการให้ครบเพื่อให้ต้นทุนลงถูกโครงการ

od19_product_return คืนสินค้า / RMA (Product Return)

จัดการคำร้อง คืนสินค้าจากลูกค้า (Return Merchandise Authorization) ตั้งแต่บันทึกคำขอ อนุมัติ รับสินค้าคืนเข้าคลัง และออก ใบลดหนี้ (Refund) พร้อมเชื่อมกับใบสั่งขาย ใบแจ้งหนี้ และใบเคลมประกัน

เมนูที่เกี่ยวข้อง

  • การขาย › Product Returns (คืนสินค้า)

ขั้นตอนการใช้งาน

  1. สร้างคำขอคืนสินค้า — เลือกลูกค้า สินค้า และเหตุผลการคืน (ชำรุด / สินค้าผิด / เสียหายระหว่างขนส่ง / ไม่ตรงรายละเอียด / เคลมประกัน / อื่น ๆ)
  2. ระบุรายละเอียด — จำนวน, ซีเรียล/ล็อต, วันที่คืน, ใบสั่งขาย/ใบแจ้งหนี้/ใบเคลมประกันที่เกี่ยวข้อง และคำอธิบาย
  3. กด “ยืนยัน” (Confirm) — จากสถานะร่าง
  4. อนุมัติ (Approve) หรือ ปฏิเสธ (Reject) — การปฏิเสธเปิดวิซาร์ดให้ระบุเหตุผล
  5. รับคืนสินค้า (Return) — ระบบสร้างใบรับสินค้า (Incoming Picking) เพื่อรับของคืนเข้าคลัง
  6. คืนเงิน (Refund) — ระบบสร้างใบลดหนี้ลูกค้า (Credit Note / Out Refund)

สถานะเอกสาร

ร่าง (Draft) → ยืนยัน (Confirmed) → อนุมัติ (Approved) → รับคืนแล้ว (Returned) → คืนเงินแล้ว (Refunded)

และสถานะ ปฏิเสธ (Rejected) — พร้อมเหตุผลการปฏิเสธ

ฟิลด์และปุ่มสำคัญ

ฟิลด์ / ปุ่มความหมาย
เลขที่คืน (Return Number)รูปแบบ PR-ปี-เลขรัน
ลูกค้า · สินค้า · ซีเรียล/ล็อต · จำนวน · หน่วยข้อมูลหลักของคำขอคืน
เหตุผลการคืน (Reason)ชำรุด / สินค้าผิด / เสียหายระหว่างขนส่ง / ไม่ตรงรายละเอียด / เคลมประกัน / อื่น ๆ
ใบสั่งขาย · ใบแจ้งหนี้ · ใบเคลมประกันเอกสารอ้างอิงที่เกี่ยวข้อง
วันที่คืน · ยอดคืนเงิน (Refund Amount)วันที่และยอดเงินที่คืน
ใบรับคืน (Return Picking) · ใบลดหนี้ (Refund Invoice)เอกสารที่ระบบสร้างให้ (อ่านอย่างเดียว)

od19_delivery_label ใบปะหน้าสินค้ารอส่ง (Delivery Label)

เพิ่มข้อมูลสำหรับใบปะหน้าสินค้ารอส่ง ได้แก่ รหัสแผนก (DEPT) เหตุผลการส่ง (เคลม/คืนสินค้า/ชำรุด/ในประกัน/ส่งมอบ/เอกสารสำคัญ) และข้อมูลผู้ติดต่อ พร้อมใบพิมพ์ “ใบปะหน้าสินค้ารอส่ง (FM-PU-12)” ขนาด 148×105 มม. แนวนอน

เมนูที่เกี่ยวข้อง

  • คลังสินค้า › ปฏิบัติการ › การส่งสินค้า (Deliveries) — เปิดเอกสารแล้วกด Print › ใบปะหน้าสินค้ารอส่ง (FM-PU-12)
  • ฟิลด์เพิ่มในหน้าเอกสาร picking
  • พนักงาน › หน่วยงาน (Departments) — ตั้งรหัสแผนก (Code)

ขั้นตอนการใช้งาน

  1. เปิดใบส่งสินค้า (Delivery) — ดูฟิลด์รหัสแผนก (DEPT) และตัวเลือกเหตุผลการส่ง
  2. เลือกเหตุผลการส่ง — เลือกได้หลายอย่าง ระบบจะรวมเป็นข้อความแสดงผล
  3. กรอกผู้ติดต่อ — ระบุชื่อผู้ติดต่อและเบอร์โทร
  4. พิมพ์ใบปะหน้า — กด Print แล้วเลือก “ใบปะหน้าสินค้ารอส่ง (FM-PU-12)”

od19_stock_jasper แบบพิมพ์และรายงาน Jasper (J-Report OD15)

รวมแบบพิมพ์และรายงานคลังสินค้าด้วย JasperReports (พอร์ตจากระบบเดิม) ประกอบด้วยแบบฟอร์มเอกสาร (ใบส่งของ ใบรับของ ใบโอน ใบเบิก ใบปะหน้า ใบหยิบ) ป้ายบาร์โค้ด/QR ของสินค้า-ที่ตั้ง-ล็อต และชุดรายงานวิเคราะห์ (บัตรสินค้า การเคลื่อนไหว มูลค่า Aging Dead Stock ตรวจ QC) ภายใต้ป้าย “(J-Report OD15)”

เมนูที่เกี่ยวข้อง

  • คลังสินค้า › Reporting › Stock Reports (J-Report OD15) — รวมรายงานทั้งหมด
  • แบบฟอร์มเอกสาร — เปิดจากตัวเอกสาร (Print) หรือกดปุ่มพิมพ์
  • ทุกใบตั้งภาษา (ไทย/อังกฤษ), ชนิดวันที่ (AD/BE) และรูปแบบวันที่ได้

ขั้นตอนการใช้งาน

  1. เปิดเมนู Stock Reports (J-Report OD15) — เลือกรายงานที่ต้องการ
  2. กำหนดพารามิเตอร์ — ภาษา (ไทย/อังกฤษ), ชนิดปี (AD/BE), รูปแบบวันที่, ช่วงวันที่ หรือ ณ วันที่ (แล้วแต่รายงาน)
  3. เลือกตัวกรอง — ที่ตั้ง, สินค้า, หมวดสินค้า, บริษัท
  4. เปิดแสดง/พิมพ์ — ระบบสร้างรายงานด้วย JasperReports; แบบฟอร์มเอกสารเปิดจากตัวเอกสาร
