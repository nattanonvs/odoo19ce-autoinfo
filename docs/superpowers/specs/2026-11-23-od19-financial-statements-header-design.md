## 1. บริบทและเป้าหมาย

ผู้ใช้ต้องการรายงานงบการเงิน 2 ใบ สร้างจากผังบัญชี (COA) โดยตรง:

| งบ | หมวดบัญชี | ระดับความละเอียด |
|---|---|---|
| งบแสดงฐานะทางการเงิน (Balance Sheet) | 1xxx / 2xxx / 3xxx | **แบบ ค — หัวข้อบัญชี (roll-up)** |
| งบกำไรขาดทุน (Profit and Loss) | 4xxx / 5xxx | **แบบ ค — หัวข้อบัญชี (roll-up)** |

เป้าหมาย: ได้งบที่แสดง **เฉพาะระดับหัวข้อ** และได้ตัวเลขที่ **ถูกต้อง (ผลรวมบัญชีลูกรวมเข้าแม่)** ทั้งบนจอ (interactive) และแบบพิมพ์

## 2. ผลการสอบทานรายงานที่มีอยู่

| งบ | รายงานที่มี | กลไก | ตรงเงื่อนไข แบบ ค? |
|---|---|---|---|
| Balance Sheet | `od19_mis_balance_sheet` | OCA MIS Builder (`mis.report`) | ❌ แบ่งด้วย `account_type`, เปิด `auto_expand_accounts` (ขยายทุกลูกบัญชี) |
| Balance Sheet (พิมพ์) | `balance.sheet.report` | Jasper legacy | ❌ เลือก Level ได้แค่ internal-group / account-type / account |
| Profit & Loss (พิมพ์) | `profit.loss.report` | Jasper legacy | ❌ ไม่มีระดับหัวข้อ, ไม่มี MIS Builder |
| Profit & Loss (จอ) | — | — | ❌ ไม่มี |

**ข้อเท็จจริงเพิ่มเติม**
- Odoo 19 CE **ไม่มี** โมดูล `account_reports` (Enterprise) → ไม่มี engine งบการเงินสำเร็จรูป
- `account.group` ในระบบ = 0 รายการ และ **ไม่มีผลต่อตัวเลขงบ** ใน CE
- ผังบัญชีมีทั้งหมด 384 บัญชี · **หัวข้อบัญชี 103 รายการ** (รหัส `XXXX-00`)

**ข้อเท็จจริงทางเทคนิคสำคัญ (กระทบการออกแบบ)**
> ลำดับชั้นบัญชี (พ่อ-ลูก) ของผังเดิม **ไม่ได้ซ้อนตามรหัส prefix** ตัวอย่าง: หัวข้อ `1120 ลูกหนี้การค้าและลูกหนี้อื่น` มีลูกคือ `1121 เช็ครับ` และ `1130 ลูกหนี้การค้า` — รหัส 1130 ไม่ได้ขึ้นต้นด้วย 1120
> ดังนั้น "roll-up" ต้องอาศัย **รายการบัญชีลูกที่ระบุชัด** (หรือ prefix ที่ตรวจสอบแล้วถูกต้อง) ไม่ใช่เดา prefix ทั่วไป

## 5. สถาปัตยกรรมที่เสนอ (ทำทั้งสองคู่กัน)

### 5.1 ฝั่ง MIS Builder (จอ / interactive) — **แนะนำเป็นแหล่งข้อมูลหลัก**

สร้าง **โมดูลใหม่**: `od19_mis_financial_statements` (data-only, depends `mis_builder`, `account`)

```
od19_mis_financial_statements/
├── __manifest__.py
├── __init__.py
└── data/
    ├── mis_report_style.xml          # สไตล์ FS (line/subtotal/total/good/bad)
    ├── mis_report_balance_sheet.xml  # mis.report + KPI แบบ ค (หมวด 1/2/3)
    ├── mis_report_profit_loss.xml    # mis.report + KPI แบบ ค (หมวด 4/5)
    └── mis_report_instance.xml       # instance + period (เทียบ 3 งวด)
```

- **ไม่ rename** โมดูล `od19_mis_balance_sheet` เดิม (กัน registry error) — คงไว้เป็น "โหมดละเอียด (account_type)"
- KPI ทุกตัว: `auto_expand_accounts = False` (แสดงเฉพาะหัวข้อ)
- Expression ตัวอย่าง: `bale[][('account_id.code','=like','111%')]`
- ใช้สไตล์เดียวกับ BS เดิม (maroon `#7A1C1C`, subtotal `#EAD6D6`) เพื่อความต่อเนื่องของ UI

### 5.2 ฝั่ง Jasper (พิมพ์) — ปรับของเดิม

- ปรับ `od19_reporting_jasper` wizard `pl_bs.py`
  - เพิ่มโหมด **"หัวข้อบัญชี (Header)"** ใน `LEVEL_SELECTION`
  - `ProfitLossReport` / `BalanceSheetReport`: เพิ่ม mapping กลุ่มหัวข้อ → รายการบัญชี
- ปรับ `jrxml/pl_bs.jrxml` (และ `pl_bs.jasper`) ให้รองรับโหมดใหม่ — คง template พิมพ์เดิมไว้เป็นตัวเลือกระดับละเอียด

## 6. กลไกดึงยอด (หัวใจของความถูกต้อง)

เนื่องจากรหัสไม่ซ้อนกันตาม prefix จึงกำหนด mapping ระดับหัวข้อเป็น **ชุด prefix ที่ตรวจสอบแล้ว** ในไฟล์ data:

```python
# ตัวอย่าง (รหัส Odoo 19 ใช้จุด: 1110-00 -> 1110.00)
HEADER_MAP = {
  "1110": ["111%"],            # 1110..1116
  "1120": ["112%", "1130%"],   # ข้อยกเว้น: 1121 + 1130
  "1131": ["1131%"],
  ...
  "5200": ["521%", "53%"],     # ข้อยกเว้น
}
```

- ตรวจ **company-dependency** ของ `account.account.code` ใน Odoo 19 (code ถูกเก็บใน `code_store` ต่อบริษัท) — ต้องทดสอบว่า domain `('account_id.code','=like', ...)` ทำงานกับ MIS Builder
- **ทางถอย (fallback)** หาก prefix ใช้ไม่ได้: สร้างไฟล์ mapping `code -> account_id` จาก `migration/mapping/od15_chart_to_od19.csv` แล้วใช้รายการ id ตรง ๆ
